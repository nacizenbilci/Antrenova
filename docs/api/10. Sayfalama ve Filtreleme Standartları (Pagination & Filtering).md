# 10. Sayfalama ve Filtreleme Standartları (Pagination & Filtering)

> **Doküman Kodu:** API-10  
> **Dosya Adı:** `10_PAGINATION_FILTERING.md`  
> **Versiyon:** 1.0  
> **Durum:** Onaylandı  
> **Bağımlı Dokümanlar:** REST API Standards, Request Response Format, Database Performance, API Documentation, Endpoint Naming

---

# 1. Amaç

Bu dokümanın amacı, Antrenova API'lerinde büyük veri listelerinin yönetimi için kullanılacak sayfalama (Pagination) ve filtreleme (Filtering) standartlarını belirlemek, yüksek performanslı ve tutarlı listeleme servisleri oluşturulmasını sağlamaktır.

Platform büyüdükçe üye, ödeme, rezervasyon, bildirim ve rapor kayıtları milyonlarca satıra ulaşacaktır. Bu nedenle tüm listeleme endpoint'leri performanslı çalışmalı ve istemci uygulamalarına yalnızca ihtiyaç duyduğu veriyi göndermelidir.

---

# 2. Temel İlkeler

Listeleme servisleri aşağıdaki prensiplere uygun olmalıdır.

- Sayfalama zorunlu olmalıdır.
- Filtreleme standart olmalıdır.
- Aynı parametre isimleri kullanılmalıdır.
- Performans öncelikli olmalıdır.
- Gereksiz veri gönderilmemelidir.

Platform genelinde ortak listeleme modeli uygulanmalıdır.

---

# 3. Sayfalama Parametreleri

Tüm liste endpoint'leri aşağıdaki standart parametreleri desteklemelidir.

```text
page
page_size
```

Örnek.

```http
GET /members?page=1&page_size=20
```

Parametre isimleri değiştirilmemelidir.

---

# 4. Varsayılan Değerler

Parametre gönderilmezse varsayılan değerler kullanılmalıdır.

Önerilen yapı.

```text
page = 1
page_size = 20
```

Maksimum sayfa büyüklüğü sınırlandırılmalıdır.

---

# 5. Maksimum Sayfa Boyutu

Tek istekte döndürülebilecek kayıt sayısı sınırlandırılmalıdır.

Örneğin.

```text
max_page_size = 100
```

İstemci daha büyük değer gönderirse sistem maksimum değeri kullanmalıdır.

---

# 6. Sayfalama Yanıtı

Liste endpoint'leri aşağıdaki Pagination yapısını döndürmelidir.

```json
{
  "pagination": {
    "page": 1,
    "page_size": 20,
    "total": 845,
    "total_pages": 43
  }
}
```

Bu yapı tüm servislerde aynı olmalıdır.

---

# 7. Filtreleme

Filtreler Query String ile gönderilmelidir.

Örneğin.

```http
GET /members?status=active
```

Birden fazla filtre birlikte kullanılabilir.

```http
GET /members?status=active&branch_id=...
```

---

# 8. Tarih Filtreleri

Tarih bazlı filtrelerde standart parametreler kullanılmalıdır.

Örneğin.

```text
start_date
end_date
```

ISO-8601 tarih formatı kullanılmalıdır.

---

# 9. Durum Filtreleri

ENUM alanları doğrudan filtrelenebilmelidir.

Örneğin.

```text
status
payment_status
reservation_status
```

Serbest metin yerine standart ENUM değerleri kullanılmalıdır.

---

# 10. Business Filtreleri

Business ID istemciden filtre olarak alınmamalıdır.

Tenant filtreleri Authentication sistemi tarafından otomatik uygulanmalıdır.

İstemci farklı tenant verisini sorgulayamamalıdır.

---

# 11. Branch Filtreleri

Şube desteği bulunan modüllerde.

```text
branch_id
```

filtre olarak kullanılabilir.

Kullanıcının yetkili olmadığı şubeler sorgulanamamalıdır.

---

# 12. Performans

Filtrelenen alanlar uygun şekilde indekslenmelidir.

Örneğin.

- status
- created_at
- member_id
- trainer_id
- business_id

Büyük veri kümelerinde tam tablo taraması yapılmamalıdır.

---

# 13. Hatalı Parametreler

Geçersiz sayfalama değerleri Validation hatası üretmelidir.

Örneğin.

```text
page=-1

page_size=10000
```

istemciye uygun hata mesajı döndürülmelidir.

---

# 14. Dokümantasyon

Her liste endpoint'i aşağıdaki bilgileri içermelidir.

- Desteklenen filtreler
- Pagination parametreleri
- Varsayılan değerler
- Maksimum kayıt sayısı
- Örnek istek ve cevaplar

Dokümantasyon gerçek API davranışıyla birebir uyumlu olmalıdır.

---

# 15. Genel Kurallar

Sayfalama ve filtreleme standartları, Antrenova API'lerinin büyük veri kümelerinde yüksek performansla çalışmasını sağlayan temel kurallardan biridir. Tüm listeleme servisleri ortak Pagination yapısını kullanmalı, filtreleme Query String üzerinden gerçekleştirilmeli ve istemcilere yalnızca ihtiyaç duydukları veriler gönderilmelidir.

Bu nedenle platform genelindeki tüm liste endpoint'leri aynı parametre isimlerini kullanmalı, performans odaklı tasarlanmalı ve büyüyen veri hacmine rağmen hızlı, tutarlı ve ölçeklenebilir bir kullanıcı deneyimi sunmalıdır.
