# 17. API Dokümantasyon Standartları (API Documentation)

> **Doküman Kodu:** API-17  
> **Dosya Adı:** `17_API_DOCUMENTATION.md`  
> **Versiyon:** 1.0  
> **Durum:** Onaylandı  
> **Bağımlı Dokümanlar:** API Design Principles, REST API Standards, Request Response Format, API Versioning, API Testing

---

# 1. Amaç

Bu dokümanın amacı, Antrenova platformunda geliştirilecek tüm API servislerinin eksiksiz, güncel ve standart bir yapıda dokümante edilmesini sağlayacak kuralları belirlemektir.

API dokümantasyonu yalnızca endpoint listesinden ibaret değildir. Her servisin nasıl çalıştığını, hangi verileri kabul ettiğini, hangi yanıtları döndürdüğünü, hangi yetkilere ihtiyaç duyduğunu ve hata durumlarında nasıl davranacağını açık şekilde tanımlayan teknik referans kaynağıdır.

Platform genelindeki tüm API'ler aynı dokümantasyon standardını kullanmalıdır.

---

# 2. Temel İlkeler

API dokümantasyonu aşağıdaki prensiplere uygun hazırlanmalıdır.

- Güncel olmalıdır.
- Tutarlı olmalıdır.
- Eksiksiz olmalıdır.
- Test edilebilir olmalıdır.
- Versiyon kontrollü olmalıdır.

Kod ile dokümantasyon arasında fark oluşmamalıdır.

---

# 3. Endpoint Bilgileri

Her endpoint aşağıdaki temel bilgileri içermelidir.

- Endpoint URL
- HTTP Metodu
- Açıklama
- API Versiyonu
- Yetkilendirme gereksinimi

Bu bilgiler tüm endpoint'lerde zorunludur.

---

# 4. Request Yapısı

Her endpoint için gönderilecek istek ayrıntılı şekilde belgelenmelidir.

İçermesi gereken bilgiler.

- Header'lar
- Query Parametreleri
- Path Parametreleri
- Request Body
- İçerik tipi

Örnek JSON yapıları eklenmelidir.

---

# 5. Response Yapısı

Başarılı yanıtlar için örnek Response verilmelidir.

Örneğin.

```json
{
  "success": true,
  "data": {}
}
```

Gerçek API davranışıyla birebir uyumlu olmalıdır.

---

# 6. Hata Senaryoları

Her endpoint için olası hata durumları belirtilmelidir.

Örneğin.

- 400 Bad Request
- 401 Unauthorized
- 403 Forbidden
- 404 Not Found
- 422 Validation Error
- 500 Internal Server Error

Her hata için açıklama eklenmelidir.

---

# 7. Yetkilendirme

Dokümantasyonda aşağıdaki bilgiler yer almalıdır.

- Gerekli kullanıcı rolü
- Business ID kontrolü
- Branch yetkisi
- Özel izinler

İstemci geliştiricileri gerekli yetkileri önceden görebilmelidir.

---

# 8. Pagination ve Filtreleme

Liste endpoint'lerinde aşağıdaki bilgiler açıklanmalıdır.

- page
- page_size
- search
- sort
- order
- filtre parametreleri

Her parametre için örnek kullanım verilmelidir.

---

# 9. Versiyon Bilgisi

Her endpoint hangi API sürümüne ait olduğunu göstermelidir.

Örneğin.

```text
v1
```

Yeni sürümler için değişiklik geçmişi de belgelenmelidir.

---

# 10. Örnekler

Her endpoint için en az bir başarılı istek örneği bulunmalıdır.

Gerekirse.

- Başarılı senaryo
- Validation hatası
- Yetki hatası

örnekleri ayrı ayrı verilmelidir.

---

# 11. Test Edilebilirlik

Dokümantasyon doğrudan test araçlarında kullanılabilir olmalıdır.

Örneğin.

- Postman
- Insomnia
- Bruno
- OpenAPI

ile uyumlu örnekler hazırlanmalıdır.

---

# 12. Güncelleme Politikası

API değiştiğinde dokümantasyon da aynı anda güncellenmelidir.

Yeni endpoint eklenip dokümantasyon unutulmamalıdır.

Kod ile doküman birlikte sürümlenmelidir.

---

# 13. Yayınlama

Dokümantasyon geliştirici portalında yayınlanmalıdır.

Gerektiğinde.

- İç kullanım
- İş ortakları
- Üçüncü taraf geliştiriciler

için farklı görünüm seviyeleri hazırlanabilir.

---

# 14. Kalite Kontrolü

Dokümantasyon yayınlanmadan önce aşağıdaki kontroller yapılmalıdır.

- Endpoint doğruluğu
- JSON örnekleri
- HTTP kodları
- Parametre isimleri
- Yazım tutarlılığı

Eski bilgiler temizlenmelidir.

---

# 15. Genel Kurallar

API dokümantasyonu, Antrenova platformunun geliştiriciler tarafından doğru kullanılmasını sağlayan en önemli teknik kaynaklardan biridir. Her endpoint eksiksiz belgelenmeli, örnek istek ve cevaplar sunulmalı, hata senaryoları açıklanmalı ve dokümantasyon kod ile eş zamanlı olarak güncellenmelidir.

Bu nedenle API Documentation standartları tüm geliştirme yaşam döngüsünün ayrılmaz bir parçası olmalı, yeni sürümlerle birlikte sürekli güncellenmeli ve platform genelinde ortak referans kaynağı olarak kullanılmalıdır.
