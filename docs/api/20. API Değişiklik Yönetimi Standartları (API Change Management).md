# 20. API Değişiklik Yönetimi Standartları (API Change Management)

> **Doküman Kodu:** API-20  
> **Dosya Adı:** `20_API_CHANGE_MANAGEMENT.md`  
> **Versiyon:** 1.0  
> **Durum:** Onaylandı  
> **Bağımlı Dokümanlar:** API Versioning, API Documentation, API Testing, REST API Standards, Software Architecture

---

# 1. Amaç

Bu dokümanın amacı, Antrenova platformunda yayınlanan API'lerde yapılacak tüm değişikliklerin planlı, kontrollü ve geriye dönük uyumluluğu koruyacak şekilde yönetilmesini sağlayacak standartları belirlemektir.

API'ler mobil uygulamalar, web paneli, yönetim sistemleri ve gelecekte platforma entegre olacak üçüncü taraf servisler tarafından kullanılacaktır. Kontrolsüz değişiklikler istemci uygulamalarının çalışmamasına, veri uyumsuzluklarına ve operasyonel kesintilere neden olabilir. Bu nedenle her değişiklik belirli bir yaşam döngüsü içerisinde yönetilmelidir.

---

# 2. Temel İlkeler

API değişiklik yönetimi aşağıdaki prensiplere uygun olmalıdır.

- Planlı olmalıdır.
- Belgelenmelidir.
- Test edilmelidir.
- Geri alınabilir olmalıdır.
- Geriye dönük uyumluluk korunmalıdır.

Ani ve duyurulmamış değişiklikler yapılmamalıdır.

---

# 3. Değişiklik Türleri

API değişiklikleri aşağıdaki kategorilerde değerlendirilmelidir.

- Yeni endpoint eklenmesi
- Yeni alan eklenmesi
- Hata düzeltmeleri
- Performans iyileştirmeleri
- Güvenlik güncellemeleri
- Kırıcı değişiklikler

Her kategori farklı yayın süreci gerektirebilir.

---

# 4. Kırıcı Değişiklikler

Aşağıdaki işlemler kırıcı değişiklik olarak kabul edilir.

- Endpoint kaldırılması
- URL değişikliği
- Response yapısının değiştirilmesi
- Request alanlarının kaldırılması
- Kimlik doğrulama yönteminin değiştirilmesi

Bu değişiklikler yalnızca yeni API sürümünde yapılmalıdır.

---

# 5. Geriye Dönük Uyumluluk

Mümkün olan her durumda mevcut istemciler çalışmaya devam etmelidir.

Yeni özellikler.

- isteğe bağlı alanlar,
- yeni endpoint'ler,
- ek parametreler

şeklinde sunulmalıdır.

Mevcut davranış gereksiz yere değiştirilmemelidir.

---

# 6. Değişiklik Süreci

Her API değişikliği aşağıdaki adımları takip etmelidir.

1. Analiz
2. Tasarım
3. Geliştirme
4. Test
5. Dokümantasyon
6. Yayın

Hiçbir adım atlanmamalıdır.

---

# 7. Dokümantasyon Güncellemesi

API değişikliği yapıldığında aşağıdaki dokümanlar güncellenmelidir.

- Endpoint açıklamaları
- Örnek Request
- Örnek Response
- Hata kodları
- Versiyon geçmişi

Kod ve doküman aynı sürümde yayınlanmalıdır.

---

# 8. Test Süreci

Her değişiklikten sonra.

- Unit Test
- Integration Test
- Regression Test
- Security Test

çalıştırılmalıdır.

Eski istemcilerle uyumluluk doğrulanmalıdır.

---

# 9. Deprecated Süreci

Kullanımdan kaldırılacak endpoint'ler hemen silinmemelidir.

Önce.

- Deprecated olarak işaretlenmeli,
- geliştiriciler bilgilendirilmeli,
- geçiş süresi tanınmalıdır.

Sonrasında yeni sürümde kaldırılabilir.

---

# 10. İzleme

Yeni yayınlanan değişiklikler yakından izlenmelidir.

Takip edilmesi gereken metrikler.

- Hata oranı
- Yanıt süresi
- Kullanım oranı
- Eski sürüm kullanımı

Beklenmeyen sorunlar hızlıca tespit edilmelidir.

---

# 11. Geri Alma (Rollback)

Kritik sorun oluşursa API değişikliği geri alınabilmelidir.

Rollback planı.

- önceden hazırlanmalı,
- test edilmeli,
- dokümante edilmelidir.

Canlı ortamda doğaçlama geri dönüş yapılmamalıdır.

---

# 12. İletişim

Önemli API değişiklikleri geliştiricilere duyurulmalıdır.

Duyurularda.

- Değişiklik özeti
- Etkilenen endpoint'ler
- Geçiş rehberi
- Yayın tarihi

yer almalıdır.

---

# 13. Audit

Kritik API değişiklikleri kayıt altına alınmalıdır.

Kayıt bilgileri.

- Değişiklik tarihi
- Geliştirici
- Sürüm
- Etkilenen servisler

İzlenebilirlik sağlanmalıdır.

---

# 14. Sürekli İyileştirme

API değişiklik süreçleri düzenli olarak gözden geçirilmelidir.

Geliştirme ekibinden gelen geri bildirimler doğrultusunda.

- yayın süreçleri,
- testler,
- dokümantasyon,
- versiyonlama

iyileştirilmelidir.

---

# 15. Genel Kurallar

API Change Management standartları, Antrenova platformunun uzun yıllar boyunca güvenli ve sürdürülebilir şekilde geliştirilebilmesini sağlayan temel süreçlerden biridir. Her değişiklik planlı olarak uygulanmalı, geriye dönük uyumluluk korunmalı, test ve dokümantasyon süreçleri tamamlanmalı ve gerektiğinde güvenli şekilde geri alınabilmelidir.

Bu nedenle API değişiklikleri merkezi olarak yönetilmeli, tüm ekip aynı yayın kurallarını uygulamalı ve platform büyüdükçe değişiklik yönetimi süreçleri düzenli olarak geliştirilmelidir.
