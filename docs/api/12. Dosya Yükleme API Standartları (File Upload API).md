# 12. Dosya Yükleme API Standartları (File Upload API)

> **Doküman Kodu:** API-12  
> **Dosya Adı:** `12_FILE_UPLOAD_API.md`  
> **Versiyon:** 1.0  
> **Durum:** Onaylandı  
> **Bağımlı Dokümanlar:** API Security, Request Response Format, Database Security, REST API Standards, Storage Architecture

---

# 1. Amaç

Bu dokümanın amacı, Antrenova platformunda gerçekleştirilecek tüm dosya yükleme (File Upload) işlemlerinin standartlarını belirlemek ve güvenli, performanslı ve ölçeklenebilir bir dosya yönetim altyapısı oluşturmaktır.

Dosya yükleme işlemleri kullanıcı profil fotoğrafları, sözleşmeler, sağlık raporları, ödeme dekontları, belgeler ve gelecekte sisteme eklenecek diğer medya dosyaları için ortak kurallarla yönetilmelidir.

---

# 2. Temel İlkeler

Dosya yükleme sistemi aşağıdaki prensiplere uygun olmalıdır.

- Güvenli olmalıdır.
- Ölçeklenebilir olmalıdır.
- Dosya sistemi yerine Object Storage kullanılmalıdır.
- Kimlik doğrulaması zorunlu olmalıdır.
- Tenant izolasyonu korunmalıdır.

Tüm yükleme işlemleri ortak API yapısını kullanmalıdır.

---

# 3. Desteklenen Dosya Türleri

Sistem yalnızca izin verilen dosya türlerini kabul etmelidir.

Örnek.

```text
jpg
jpeg
png
webp
pdf
docx
xlsx
csv
```

İzin verilmeyen uzantılar reddedilmelidir.

---

# 4. Dosya Boyutu

Her dosya türü için maksimum yükleme boyutu belirlenmelidir.

Örnek.

- Profil fotoğrafı → 5 MB
- PDF belge → 20 MB
- Excel dosyası → 10 MB

Sınır aşılırsa uygun hata döndürülmelidir.

---

# 5. Depolama

Dosyalar doğrudan veritabanında saklanmamalıdır.

Standart yaklaşım.

- Object Storage
- CDN desteği
- Güvenli URL yapısı

Veritabanında yalnızca dosya metaverileri tutulmalıdır.

---

# 6. Dosya Adları

Kullanıcının yüklediği dosya adı doğrudan kullanılmamalıdır.

Dosya adı sistem tarafından benzersiz şekilde oluşturulmalıdır.

Örneğin.

```text
uuid.ext
```

Dosya çakışmaları engellenmelidir.

---

# 7. Tenant İzolasyonu

Dosyalar işletme bazında ayrılmalıdır.

Örnek dizin mantığı.

```text
business_id/member_id/
business_id/payments/
business_id/contracts/
```

Farklı işletmeler birbirlerinin dosyalarına erişememelidir.

---

# 8. Güvenlik Kontrolleri

Yükleme öncesinde aşağıdaki kontroller yapılmalıdır.

- Kimlik doğrulama
- Yetkilendirme
- Dosya türü
- Dosya boyutu
- Zararlı içerik kontrolü

İzin verilmeyen dosyalar depolanmamalıdır.

---

# 9. MIME Type Kontrolü

Yalnızca dosya uzantısı kontrol edilmemelidir.

MIME Type doğrulaması da yapılmalıdır.

Yanlış uzantıyla yüklenen zararlı dosyalar reddedilmelidir.

---

# 10. Yanıt Formatı

Başarılı yükleme sonrasında standart Response döndürülmelidir.

Örneğin.

```json
{
  "success": true,
  "data": {
    "file_id": "...",
    "url": "...",
    "file_name": "..."
  }
}
```

Dosya sistemi detayları istemciye gösterilmemelidir.

---

# 11. Silme İşlemleri

Dosya silme işlemleri Soft Delete mantığıyla yönetilebilir.

Gerektiğinde.

- Dosya arşivlenebilir.
- Geri yüklenebilir.
- Kalıcı silme ayrı süreçte yapılabilir.

Silinen dosyaların erişimi kapatılmalıdır.

---

# 12. Performans

Büyük dosyalar için.

- Parçalı yükleme (Chunk Upload)
- Arka plan işleme
- CDN dağıtımı

desteklenebilir.

Mobil bağlantılar dikkate alınmalıdır.

---

# 13. Audit

Aşağıdaki işlemler Audit sistemine kaydedilmelidir.

- Dosya yükleme
- Dosya silme
- Dosya indirme
- Dosya güncelleme
- Yetkisiz erişim denemeleri

Kritik dosya işlemleri izlenebilir olmalıdır.

---

# 14. Dokümantasyon

Dosya yükleme API'leri aşağıdaki bilgileri içermelidir.

- Desteklenen formatlar
- Boyut limitleri
- Yetki gereksinimleri
- Örnek istek
- Örnek cevap
- Hata kodları

Tüm istemci uygulamaları aynı dokümantasyonu kullanmalıdır.

---

# 15. Genel Kurallar

Dosya yükleme API'leri, Antrenova platformunda güvenli ve ölçeklenebilir medya yönetiminin temelini oluşturur. Tüm dosyalar güvenlik kontrollerinden geçirilmeli, Object Storage üzerinde saklanmalı, tenant izolasyonu korunmalı ve yalnızca yetkili kullanıcılar tarafından erişilebilir olmalıdır.

Bu nedenle File Upload API standartları platform genelinde ortak uygulanmalı, dosya yönetimi veritabanından bağımsız planlanmalı ve büyüyen veri hacmine uygun sürdürülebilir bir mimari kullanılmalıdır.
