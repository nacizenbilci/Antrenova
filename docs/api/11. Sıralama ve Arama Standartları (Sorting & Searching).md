# 11. Sıralama ve Arama Standartları (Sorting & Searching)

> **Doküman Kodu:** API-11  
> **Dosya Adı:** `11_SORTING_SEARCHING.md`  
> **Versiyon:** 1.0  
> **Durum:** Onaylandı  
> **Bağımlı Dokümanlar:** Pagination & Filtering, Database Performance, REST API Standards, Request Response Format, API Documentation

---

# 1. Amaç

Bu dokümanın amacı, Antrenova API'lerinde kullanılacak sıralama (Sorting) ve arama (Searching) mekanizmalarının standartlarını belirlemek, tüm listeleme servislerinde tutarlı ve yüksek performanslı bir sorgulama deneyimi sağlamaktır.

Kullanıcılar üye, eğitmen, ödeme, rezervasyon, paket ve rapor kayıtları arasında hızlı şekilde arama yapabilmeli ve sonuçları farklı kriterlere göre sıralayabilmelidir. Tüm endpoint'ler ortak parametre yapısını kullanmalıdır.

---

# 2. Temel İlkeler

Arama ve sıralama sistemi aşağıdaki prensiplere uygun olmalıdır.

- Tutarlı parametre isimleri kullanılmalıdır.
- Performans öncelikli olmalıdır.
- Güvenli olmalıdır.
- Filtreleme ile birlikte çalışabilmelidir.
- Büyük veri kümelerini desteklemelidir.

Platform genelinde aynı sorgulama modeli uygulanmalıdır.

---

# 3. Arama Parametresi

Serbest metin aramaları aşağıdaki standart parametreyi kullanmalıdır.

```text
search
```

Örnek.

```http
GET /members?search=Ali
```

Farklı endpoint'lerde farklı parametre isimleri kullanılmamalıdır.

---

# 4. Aranabilir Alanlar

Her endpoint yalnızca belirlenen alanlarda arama yapmalıdır.

Örneğin üyeler için.

- Ad
- Soyad
- Telefon
- E-posta
- Üyelik numarası

Tüm sütunlarda kontrolsüz arama yapılmamalıdır.

---

# 5. Kısmi Arama

Arama işlemleri mümkün olduğunca kısmi eşleşmeyi desteklemelidir.

Örneğin.

```text
Ali
```

araması.

- Ali
- Alim
- Alihan

sonuçlarını döndürebilir.

Arama davranışı tüm endpoint'lerde tutarlı olmalıdır.

---

# 6. Büyük/Küçük Harf

Aramalar büyük-küçük harf duyarsız çalışmalıdır.

Örneğin.

```text
ali

ALI

Ali
```

aynı sonucu döndürmelidir.

---

# 7. Sıralama Parametresi

Sıralama aşağıdaki standart parametre ile yapılmalıdır.

```text
sort
```

Örnek.

```http
GET /members?sort=created_at
```

Alan isimleri doğrudan veri sözlüğüyle uyumlu olmalıdır.

---

# 8. Sıralama Yönü

Sıralama yönü aşağıdaki parametre ile belirtilmelidir.

```text
order
```

Desteklenen değerler.

```text
asc
desc
```

Varsayılan yön dokümantasyonda belirtilmelidir.

---

# 9. Varsayılan Sıralama

Parametre belirtilmezse sistem varsayılan sıralama kullanmalıdır.

Örneğin.

```text
created_at DESC
```

Her endpoint kendi varsayılan sıralama kuralına sahip olabilir.

---

# 10. Çoklu Sıralama

Gerekli durumlarda birden fazla alanla sıralama desteklenebilir.

Örneğin.

```text
sort=branch_id,name
```

Ancak karmaşık sorgular performans açısından değerlendirilmelidir.

---

# 11. Performans

Sıralanabilir alanlar uygun şekilde indekslenmelidir.

Özellikle.

- created_at
- name
- status
- payment_date
- reservation_date

performans açısından optimize edilmelidir.

---

# 12. Güvenlik

İstemci yalnızca izin verilen alanlarda sıralama yapabilmelidir.

Dinamik SQL oluşturacak parametreler doğrudan kullanılmamalıdır.

Whitelist yaklaşımı uygulanmalıdır.

---

# 13. Validation

Geçersiz sıralama alanları Validation hatası üretmelidir.

Örneğin.

```text
sort=password
```

gibi desteklenmeyen alanlar reddedilmelidir.

---

# 14. Dokümantasyon

Her endpoint aşağıdaki bilgileri içermelidir.

- Desteklenen arama alanları
- Desteklenen sıralama alanları
- Varsayılan sıralama
- Parametre örnekleri

API dokümantasyonu gerçek davranışla uyumlu olmalıdır.

---

# 15. Genel Kurallar

Sıralama ve arama standartları, Antrenova API'lerinde büyük veri kümeleri üzerinde hızlı ve tutarlı sorgulama yapılmasını sağlayan temel mekanizmalardan biridir. Tüm endpoint'ler ortak `search`, `sort` ve `order` parametrelerini kullanmalı, performanslı indeksleme ile desteklenmeli ve güvenlik açısından yalnızca izin verilen alanlarda çalışmalıdır.

Bu nedenle arama ve sıralama kuralları platform genelinde standartlaştırılmalı, istemci uygulamalarına öngörülebilir bir API deneyimi sunulmalı ve veri hacmi büyüdükçe performans düzenli olarak izlenip optimize edilmelidir.
