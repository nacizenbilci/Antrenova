# 09. API Hata Yönetimi Standartları (Error Handling)

> **Doküman Kodu:** API-09  
> **Dosya Adı:** `09_ERROR_HANDLING.md`  
> **Versiyon:** 1.0  
> **Durum:** Onaylandı  
> **Bağımlı Dokümanlar:** HTTP Status Codes, Request Response Format, API Security, API Logging, API Documentation

---

# 1. Amaç

Bu dokümanın amacı, Antrenova API'lerinde oluşabilecek tüm hata durumlarının standart şekilde yönetilmesini sağlamak, istemci uygulamalarına tutarlı hata cevapları sunmak ve sistem güvenliğini koruyacak ortak hata yönetimi kurallarını belirlemektir.

Hata yönetimi yalnızca başarısız işlemleri bildirmek için kullanılmaz. Aynı zamanda geliştiricilerin sorunları hızlı tespit etmesini, istemci uygulamalarının doğru tepki vermesini ve güvenlik açısından hassas bilgilerin korunmasını sağlar.

Platform genelindeki tüm servisler aynı hata yönetimi yapısını kullanmalıdır.

---

# 2. Temel İlkeler

Hata yönetimi aşağıdaki prensiplere uygun olmalıdır.

- Tutarlı olmalıdır.
- Anlaşılır olmalıdır.
- Güvenli olmalıdır.
- İzlenebilir olmalıdır.
- Dokümante edilmelidir.

Her hata belirli bir standart yapıyla döndürülmelidir.

---

# 3. Standart Hata Formatı

Başarısız tüm işlemler aşağıdaki temel yapıyı kullanmalıdır.

```json
{
  "success": false,
  "message": "Validation failed.",
  "errors": []
}
```

Alan isimleri tüm API'lerde aynı olmalıdır.

---

# 4. Validation Hataları

Alan doğrulama hataları ayrı ayrı döndürülmelidir.

Örnek.

```json
{
  "errors": [
    {
      "field": "email",
      "message": "Email is required."
    }
  ]
}
```

Birden fazla hata aynı Response içerisinde yer alabilir.

---

# 5. Sistem Hataları

Beklenmeyen sunucu hatalarında.

- SQL hataları
- Stack Trace
- Dosya yolları
- Kod satırları

istemciye gönderilmemelidir.

Kullanıcı yalnızca genel hata mesajı görmelidir.

---

# 6. Hata Mesajları

Mesajlar açık ve anlaşılır olmalıdır.

Yanlış.

```text
Unhandled exception
```

Doğru.

```text
Member not found.
```

Teknik terimlerden mümkün olduğunca kaçınılmalıdır.

---

# 7. HTTP Durum Kodları

Hatalar uygun HTTP durum kodlarıyla birlikte gönderilmelidir.

Örneğin.

```text
400
401
403
404
409
422
429
500
```

Her hata türü doğru kodu kullanmalıdır.

---

# 8. İş Kuralı Hataları

Business Rule ihlalleri açık şekilde belirtilmelidir.

Örneğin.

- Paket süresi dolmuş.
- Borç nedeniyle işlem yapılamıyor.
- Rezervasyon kapasitesi dolu.

Bu hatalar teknik hata değildir.

---

# 9. Yetki Hataları

Yetki sorunlarında.

```http
403 Forbidden
```

döndürülmelidir.

Kullanıcının erişemediği kaynak hakkında gereksiz bilgi verilmemelidir.

---

# 10. Loglama

Her kritik hata API Log sistemine kaydedilmelidir.

Kayıt bilgileri.

- Tarih
- Endpoint
- Kullanıcı
- Business ID
- HTTP Kodu
- Hata Türü

Şifre ve Token gibi hassas bilgiler loglanmamalıdır.

---

# 11. Hata Kimliği

Kritik sistem hatalarına benzersiz bir Error ID atanmalıdır.

Örneğin.

```text
ERR-20260804-000145
```

Bu kimlik destek süreçlerinde kullanılabilir.

---

# 12. Retry Politikası

Geçici sistem hatalarında istemci tekrar deneyebilir.

Örneğin.

- Ağ hataları
- Timeout
- Geçici servis kesintileri

Kalıcı hatalarda otomatik tekrar önerilmez.

---

# 13. Audit

Aşağıdaki olaylar Audit sistemine kaydedilmelidir.

- Yetki ihlalleri
- Kimlik doğrulama hataları
- Kritik sistem hataları
- Güvenlik olayları

Normal Validation hataları Audit kaydı gerektirmez.

---

# 14. Dokümantasyon

Her endpoint için olası hata senaryoları belgelenmelidir.

Dokümantasyonda.

- HTTP kodu
- Hata mesajı
- Açıklama
- Çözüm önerisi

yer almalıdır.

İstemci geliştiricileri tüm hata senaryolarını önceden görebilmelidir.

---

# 15. Genel Kurallar

API hata yönetimi, Antrenova platformunda güvenilir ve öngörülebilir servis davranışını sağlayan temel standartlardan biridir. Her hata uygun HTTP durum koduyla döndürülmeli, istemciye anlaşılır mesajlar sunulmalı ve güvenliği riske atacak teknik bilgiler paylaşılmamalıdır.

Bu nedenle tüm servisler ortak hata formatını kullanmalı, kritik olaylar log ve Audit sistemine kaydedilmeli ve hata yönetimi platform genelinde tek tip standartlarla uygulanmalıdır.
