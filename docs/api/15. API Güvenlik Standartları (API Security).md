# 15. API Güvenlik Standartları (API Security)

> **Doküman Kodu:** API-15  
> **Dosya Adı:** `15_API_SECURITY.md`  
> **Versiyon:** 1.0  
> **Durum:** Onaylandı  
> **Bağımlı Dokümanlar:** Authentication API, Authorization API, Database Security, Rate Limiting, Webhook Standards

---

# 1. Amaç

Bu dokümanın amacı, Antrenova platformunda geliştirilecek tüm API servislerinin güvenlik standartlarını belirlemek ve istemci ile sunucu arasındaki iletişimin gizlilik, bütünlük ve erişilebilirlik ilkelerine uygun şekilde gerçekleştirilmesini sağlamaktır.

API katmanı, mobil uygulamalar, web paneli, yönetim araçları ve üçüncü taraf entegrasyonlarının ortak erişim noktasıdır. Bu nedenle güvenlik yalnızca kimlik doğrulamayla sınırlı değildir; veri doğrulama, iletişim güvenliği, saldırı önleme ve olay izleme süreçlerini de kapsar.

Platform genelindeki tüm API servisleri bu kurallara uygun geliştirilmelidir.

---

# 2. Temel İlkeler

API güvenliği aşağıdaki temel prensiplere dayanmalıdır.

- Gizlilik (Confidentiality)
- Bütünlük (Integrity)
- Erişilebilirlik (Availability)
- En az yetki (Least Privilege)
- Savunma katmanları (Defense in Depth)

Her yeni servis güvenlik açısından değerlendirilmeden yayınlanmamalıdır.

---

# 3. HTTPS Zorunluluğu

Tüm API çağrıları yalnızca HTTPS üzerinden gerçekleştirilmelidir.

Aşağıdaki bağlantılar reddedilmelidir.

```text
http://
```

Tüm istemciler güvenli TLS bağlantısı kullanmalıdır.

---

# 4. Kimlik Doğrulama

Korunan tüm endpoint'lerde Authentication zorunludur.

Kimlik doğrulama.

- Access Token
- Bearer Token
- Güvenli Header

üzerinden yapılmalıdır.

Kimliği doğrulanmamış istekler işlenmemelidir.

---

# 5. Yetkilendirme

Kimliği doğrulanmış her kullanıcı her veriye erişemez.

Her istek için.

- Rol
- Business ID
- Branch ID
- İşlem Yetkisi

ayrı ayrı doğrulanmalıdır.

Authentication ve Authorization birbirinin yerine kullanılmamalıdır.

---

# 6. Girdi Doğrulama

API'ye gelen tüm veriler doğrulanmalıdır.

Kontrol edilmesi gerekenler.

- Veri tipi
- Uzunluk
- Format
- Zorunlu alanlar
- ENUM değerleri

Doğrulanmamış veri işlenmemelidir.

---

# 7. SQL Injection Koruması

Dinamik SQL sorguları oluşturulmamalıdır.

Tüm veri erişimleri.

- Parametreli sorgular
- ORM mekanizmaları
- Güvenli sorgu oluşturucular

ile gerçekleştirilmelidir.

Kullanıcı girdileri doğrudan SQL içerisine eklenmemelidir.

---

# 8. XSS ve İçerik Güvenliği

API tarafından döndürülen metinler gerektiğinde güvenli şekilde işlenmelidir.

Özellikle kullanıcı tarafından oluşturulan içerikler.

- filtrelenmeli,
- doğrulanmalı,
- güvenli biçimde sunulmalıdır.

İstemci uygulamaları da gerekli önlemleri almalıdır.

---

# 9. Hassas Veriler

API yanıtlarında aşağıdaki bilgiler gönderilmemelidir.

- Şifre
- Hash değeri
- Refresh Token
- API Secret
- İç sistem kimlikleri

Yalnızca gerekli bilgiler paylaşılmalıdır.

---

# 10. Güvenlik Başlıkları

Gerekli HTTP güvenlik başlıkları kullanılmalıdır.

Örneğin.

- Strict-Transport-Security
- X-Content-Type-Options
- Content-Security-Policy
- X-Frame-Options

Sunucu güvenlik yapılandırmaları düzenli olarak gözden geçirilmelidir.

---

# 11. Loglama

API güvenliği açısından önemli olaylar kayıt altına alınmalıdır.

Örneğin.

- Başarısız girişler
- Yetki ihlalleri
- Rate Limit aşımı
- Şüpheli istekler

Loglarda hassas bilgiler yer almamalıdır.

---

# 12. Güvenlik Testleri

API'ler düzenli olarak güvenlik testlerinden geçirilmelidir.

Örneğin.

- Penetrasyon testleri
- Zafiyet taramaları
- OWASP kontrolleri
- Yetki testleri

Yeni sürümler yayınlanmadan önce temel güvenlik kontrolleri tamamlanmalıdır.

---

# 13. Audit

Aşağıdaki güvenlik olayları Audit sistemine kaydedilmelidir.

- Yetki değişiklikleri
- Token iptalleri
- Kritik API çağrıları
- Başarısız doğrulamalar

Güvenlik kayıtları değiştirilememelidir.

---

# 14. Dokümantasyon

Her endpoint için aşağıdaki güvenlik bilgileri belgelenmelidir.

- Authentication gereksinimi
- Gerekli roller
- Rate Limit
- Güvenlik Header'ları
- Hata kodları

API dokümantasyonu güvenlik kurallarıyla uyumlu olmalıdır.

---

# 15. Genel Kurallar

API güvenliği, Antrenova platformunun en kritik mimari katmanlarından biridir. Tüm servisler HTTPS üzerinden çalışmalı, kimlik doğrulama ve yetkilendirme eksiksiz uygulanmalı, gelen tüm veriler doğrulanmalı ve güvenlik olayları sürekli izlenmelidir.

Bu nedenle API Security standartları tüm geliştirme sürecinin ayrılmaz bir parçası olarak değerlendirilmeli, güvenlik sonradan eklenen bir özellik değil, API tasarımının temel gereksinimi olarak ele alınmalıdır.
