# 01. API Tasarım İlkeleri (API Design Principles)

> **Doküman Kodu:** API-01  
> **Dosya Adı:** `01_API_DESIGN_PRINCIPLES.md`  
> **Versiyon:** 1.0  
> **Durum:** Onaylandı  
> **Bağımlı Dokümanlar:** Software Architecture, Business Rules, Database Standards, REST API Standards, API Security

---

# 1. Amaç

Bu dokümanın amacı, Antrenova platformunda geliştirilecek tüm API servislerinin ortak tasarım prensiplerini belirlemek ve tüm modüllerin aynı mimari yaklaşımı kullanmasını sağlamaktır.

API katmanı yalnızca istemci ile veritabanı arasında veri taşıyan bir yapı değildir. Mobil uygulamalar, web paneli, üçüncü taraf servisler ve gelecekte geliştirilecek entegrasyonlar için platformun resmi iletişim katmanıdır. Bu nedenle API tasarımı okunabilir, güvenli, sürdürülebilir ve ölçeklenebilir olmalıdır.

Platform genelindeki tüm servisler bu standartlara uygun geliştirilmelidir.

---

# 2. Temel İlkeler

API tasarımı aşağıdaki prensiplere uygun olmalıdır.

- Tutarlı olmalıdır.
- REST mimarisine uygun olmalıdır.
- Tahmin edilebilir olmalıdır.
- Sürüm yönetimini desteklemelidir.
- Güvenli olmalıdır.
- Performanslı olmalıdır.

Her endpoint aynı tasarım dilini kullanmalıdır.

---

# 3. Kaynak Odaklı Tasarım

API'ler işlemlere değil kaynaklara (Resources) göre tasarlanmalıdır.

Örnekler.

```text
/members
/trainers
/packages
/payments
/reservations
```

Yanlış örnekler.

```text
/getMembers
/createTrainer
/doPayment
```

Endpoint isimleri nesneleri temsil etmelidir.

---

# 4. HTTP Metotları

HTTP metotları standart amaçları doğrultusunda kullanılmalıdır.

```text
GET
POST
PUT
PATCH
DELETE
```

Metotların amacı değiştirilmemelidir.

Örneğin veri silme işlemi GET ile yapılamaz.

---

# 5. Stateless Yapı

API tamamen Stateless çalışmalıdır.

Her istek.

- gerekli kimlik bilgilerini,
- yetkilendirme bilgisini,
- tenant bilgisini

kendi içerisinde taşımalıdır.

Sunucu istemci oturumuna bağımlı olmamalıdır.

---

# 6. JSON Standardı

API varsayılan olarak JSON veri formatını kullanmalıdır.

Örneğin.

```json
{
  "success": true,
  "data": {}
}
```

XML veya farklı veri formatları yalnızca özel ihtiyaçlarda desteklenmelidir.

---

# 7. Multi-Tenant Uyumluluğu

Tüm API çağrıları Multi-Tenant mimariye uygun çalışmalıdır.

Her istek.

- doğrulanmış kullanıcı,
- Business ID,
- yetkilendirme

kontrollerinden geçmelidir.

Tenant izolasyonu API seviyesinde de korunmalıdır.

---

# 8. Tek Sorumluluk

Her endpoint yalnızca tek bir iş amacına hizmet etmelidir.

Örneğin.

```text
GET /members
```

üyeleri listeler.

Aynı endpoint ödeme oluşturma gibi farklı işlemler yapmamalıdır.

---

# 9. Standart Yanıt Yapısı

Başarılı ve başarısız tüm cevaplar ortak yapıyı kullanmalıdır.

Örneğin.

```json
{
  "success": true,
  "message": "",
  "data": {}
}
```

İstemciler tüm servislerde aynı yapıyı bekleyebilmelidir.

---

# 10. Hata Yönetimi

Hatalar standart HTTP kodlarıyla birlikte döndürülmelidir.

Örneğin.

```text
400
401
403
404
409
422
500
```

Teknik hata mesajları doğrudan son kullanıcıya gösterilmemelidir.

---

# 11. Güvenlik

Tüm endpoint'ler aşağıdaki güvenlik kontrollerini desteklemelidir.

- Kimlik doğrulama
- Yetkilendirme
- Rate Limiting
- Girdi doğrulama
- SQL Injection koruması

Varsayılan yaklaşım güvenli erişim olmalıdır.

---

# 12. Performans

API'ler minimum veri döndürmelidir.

Gereksiz.

- JOIN
- Büyük JSON yapıları
- Kullanılmayan alanlar

gönderilmemelidir.

Mobil uygulama performansı öncelikli düşünülmelidir.

---

# 13. Genişletilebilirlik

Yeni modüller mevcut API yapısını bozmadan eklenebilmelidir.

Örneğin.

- CRM
- POS
- RFID
- Yapay Zeka

yeni endpoint'lerle sisteme dahil edilebilmelidir.

Eski istemciler etkilenmemelidir.

---

# 14. Dokümantasyon

Her endpoint aşağıdaki bilgilerle belgelenmelidir.

- Amaç
- URL
- HTTP Metodu
- Parametreler
- Örnek istek
- Örnek cevap
- Hata kodları

Dokümantasyon kodla aynı anda güncellenmelidir.

---

# 15. Genel Kurallar

API tasarım ilkeleri, Antrenova'nın tüm istemci uygulamaları ile sunucu arasındaki iletişim standardını oluşturur. Her endpoint REST prensiplerine uygun geliştirilmeli, ortak veri yapısını kullanmalı, güvenliği ön planda tutmalı ve Multi-Tenant mimariyle tam uyumlu çalışmalıdır.

Bu nedenle API tasarımı kısa vadeli ihtiyaçlara göre değil, yıllarca büyüyebilecek kurumsal bir SaaS platformunun gereksinimleri dikkate alınarak planlanmalı ve platform genelinde tek bir standart korunmalıdır.
