# 05. HTTP Durum Kodu Standartları (HTTP Status Codes)

> **Doküman Kodu:** API-05  
> **Dosya Adı:** `05_HTTP_STATUS_CODES.md`  
> **Versiyon:** 1.0  
> **Durum:** Onaylandı  
> **Bağımlı Dokümanlar:** REST API Standards, Request Response Format, Error Handling, API Documentation

---

# 1. Amaç

Bu dokümanın amacı, Antrenova API'lerinde kullanılacak HTTP durum kodlarının (HTTP Status Codes) standartlarını belirlemek ve tüm servislerde aynı hata yönetimi yaklaşımını uygulamaktır.

HTTP durum kodları yalnızca istemciye işlemin başarılı veya başarısız olduğunu bildirmez. Aynı zamanda uygulamaların otomatik karar verebilmesini, hata yönetimini standartlaştırmasını ve entegrasyonların daha güvenilir çalışmasını sağlar.

Platform genelindeki tüm endpoint'ler bu dokümanda belirtilen kodları kullanmalıdır.

---

# 2. Temel İlkeler

HTTP durum kodları aşağıdaki prensiplere uygun kullanılmalıdır.

- Gerçek durumu yansıtmalıdır.
- Tutarlı olmalıdır.
- REST standartlarına uygun olmalıdır.
- Aynı hata için aynı kod kullanılmalıdır.
- Özel HTTP kodları üretilmemelidir.

Her durum için en uygun standart kod tercih edilmelidir.

---

# 3. 200 OK

İşlem başarıyla tamamlandığında kullanılmalıdır.

Örneğin.

- Listeleme
- Tek kayıt görüntüleme
- Başarılı güncelleme
- Başarılı sorgulama

Yanıt gövdesi (Response Body) veri içerebilir.

---

# 4. 201 Created

Yeni kayıt başarıyla oluşturulduğunda kullanılmalıdır.

Örneğin.

```http
POST /members

POST /payments

POST /reservations
```

Yeni oluşturulan kaydın bilgisi Response içerisinde döndürülebilir.

---

# 5. 204 No Content

İşlem başarılı ancak döndürülecek veri yoksa kullanılmalıdır.

Örneğin.

- Başarılı silme
- Boş güncelleme
- İçerik gerektirmeyen işlemler

Response Body gönderilmemelidir.

---

# 6. 400 Bad Request

İstek yapısı hatalıysa kullanılmalıdır.

Örneğin.

- Eksik JSON
- Yanlış format
- Geçersiz parametre
- Hatalı Query String

Sunucu hatası ile karıştırılmamalıdır.

---

# 7. 401 Unauthorized

Kimlik doğrulaması başarısız olduğunda kullanılmalıdır.

Örneğin.

- Token bulunamadı
- Token geçersiz
- Token süresi dolmuş

Kimlik doğrulama yapılmadan veri döndürülmemelidir.

---

# 8. 403 Forbidden

Kimlik doğrulaması başarılı ancak yetki yetersiz olduğunda kullanılmalıdır.

Örneğin.

- Rol yetkisi yok
- Tenant erişimi yok
- Modül erişimi yasak

401 ile karıştırılmamalıdır.

---

# 9. 404 Not Found

İstenen kaynak bulunamadığında kullanılmalıdır.

Örneğin.

- Üye bulunamadı
- Paket bulunamadı
- Rezervasyon bulunamadı

Var olmayan endpoint'ler de aynı kodu döndürmelidir.

---

# 10. 409 Conflict

Veri çakışması oluştuğunda kullanılmalıdır.

Örneğin.

- Aynı e-posta
- Aynı üyelik numarası
- Aynı rezervasyon

Business Rule ihlalleri bu kodla döndürülebilir.

---

# 11. 422 Unprocessable Entity

Doğrulama (Validation) hatalarında kullanılmalıdır.

Örneğin.

- Eksik zorunlu alan
- Geçersiz tarih
- Negatif ücret
- Yanlış format

Alan bazlı hata listesi Response içerisinde gönderilmelidir.

---

# 12. 429 Too Many Requests

Rate Limiting devreye girdiğinde kullanılmalıdır.

İstemci.

- belirli süre beklemeli,
- tekrar denemelidir.

Rate Limit bilgisi Header içerisinde gönderilebilir.

---

# 13. 500 Internal Server Error

Beklenmeyen sunucu hatalarında kullanılmalıdır.

İstemciye.

- SQL hatası
- Stack Trace
- Teknik detay

gönderilmemelidir.

Hata Audit sistemine kaydedilmelidir.

---

# 14. Kullanılmaması Gereken Yaklaşımlar

Başarısız işlemlerde her zaman.

```http
200 OK
```

döndürülmemelidir.

Hata bilgisi yalnızca JSON içerisinde verilerek HTTP kodu değiştirilmemelidir.

Gerçek durum her zaman HTTP koduyla ifade edilmelidir.

---

# 15. Genel Kurallar

HTTP durum kodları, Antrenova API'lerinin istemci uygulamalarıyla doğru iletişim kurmasını sağlayan temel standartlardan biridir. Her endpoint gerçek işlem sonucunu uygun HTTP koduyla döndürmeli, hata yönetimi platform genelinde tutarlı olmalı ve istemcilerin otomatik karar verebileceği öngörülebilir bir yapı sunmalıdır.

Bu nedenle tüm servislerde standart HTTP kodları kullanılmalı, özel durum kodlarından kaçınılmalı ve hata yönetimi REST prensiplerine tam uyumlu şekilde uygulanmalıdır.
