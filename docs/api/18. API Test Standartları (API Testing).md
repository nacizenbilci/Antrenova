# 18. API Test Standartları (API Testing)

> **Doküman Kodu:** API-18  
> **Dosya Adı:** `18_API_TESTING.md`  
> **Versiyon:** 1.0  
> **Durum:** Onaylandı  
> **Bağımlı Dokümanlar:** API Documentation, REST API Standards, Error Handling, API Performance, CI/CD Standards

---

# 1. Amaç

Bu dokümanın amacı, Antrenova platformunda geliştirilecek tüm API servislerinin test süreçlerini standartlaştırmak ve yayınlanan her endpoint'in güvenilir, kararlı ve beklenen davranışı sergilediğini doğrulamak için uygulanacak test kurallarını belirlemektir.

API testleri yalnızca çalışan bir endpoint'i doğrulamak için yapılmaz. Aynı zamanda iş kurallarının korunması, güvenlik kontrollerinin doğrulanması, geriye dönük uyumluluğun sürdürülmesi ve performansın izlenmesi açısından da kritik öneme sahiptir.

---

# 2. Temel İlkeler

API testleri aşağıdaki prensiplere uygun yürütülmelidir.

- Otomatik olmalıdır.
- Tekrarlanabilir olmalıdır.
- İzole çalışmalıdır.
- Gerçekçi senaryolar içermelidir.
- Sürekli entegrasyon sürecine dahil edilmelidir.

Hiçbir kritik endpoint testsiz yayınlanmamalıdır.

---

# 3. Test Türleri

Her API aşağıdaki test türlerinden uygun olanları desteklemelidir.

- Unit Test
- Integration Test
- Functional Test
- Security Test
- Performance Test
- Regression Test

Tek bir test yöntemi yeterli kabul edilmemelidir.

---

# 4. Başarılı Senaryolar

Her endpoint için en az bir başarılı kullanım senaryosu test edilmelidir.

Örneğin.

- Üye oluşturma
- Üye güncelleme
- Ödeme kaydı
- Rezervasyon oluşturma

Beklenen HTTP kodu ve Response doğrulanmalıdır.

---

# 5. Validation Testleri

Geçersiz verilerle yapılan istekler test edilmelidir.

Örneğin.

- Boş zorunlu alan
- Geçersiz tarih
- Yanlış veri tipi
- Desteklenmeyen ENUM değeri

Doğru hata mesajları döndürülmelidir.

---

# 6. Yetkilendirme Testleri

Tüm korunan endpoint'lerde aşağıdaki senaryolar test edilmelidir.

- Token yok
- Token geçersiz
- Yetki yetersiz
- Farklı tenant erişimi

Güvenlik kontrolleri eksiksiz doğrulanmalıdır.

---

# 7. Multi-Tenant Testleri

Her API aşağıdaki tenant senaryolarını test etmelidir.

- Doğru Business ID
- Yanlış Business ID
- Yetkisiz Branch erişimi
- Tenant izolasyonu

Hiçbir tenant diğer tenant verisini görememelidir.

---

# 8. Performans Testleri

API yanıt süreleri düzenli olarak ölçülmelidir.

Test edilmesi gereken durumlar.

- Tek kullanıcı
- Çoklu kullanıcı
- Büyük veri
- Yoğun istek

Belirlenen performans hedefleri aşılmamalıdır.

---

# 9. Hata Senaryoları

Beklenmeyen durumlar test edilmelidir.

Örneğin.

- Veritabanı bağlantı hatası
- Timeout
- Eksik servis
- Geçersiz JSON

API güvenli hata cevapları üretmelidir.

---

# 10. Dosya Testleri

Dosya yükleme servislerinde.

- Desteklenmeyen uzantı
- Büyük dosya
- Zararlı dosya
- Eksik dosya

senaryoları test edilmelidir.

---

# 11. Otomasyon

API testleri CI/CD sürecine dahil edilmelidir.

Kod değişikliklerinde.

- Testler otomatik çalışmalı,
- Başarısız testler dağıtımı durdurmalıdır.

Manuel testlere bağımlı kalınmamalıdır.

---

# 12. Test Verileri

Test ortamında kullanılan veriler üretim verilerinden bağımsız olmalıdır.

Gerçek kullanıcı bilgileri testlerde kullanılmamalıdır.

Test verileri tekrar oluşturulabilir yapıda hazırlanmalıdır.

---

# 13. Dokümantasyon

Her endpoint için aşağıdaki test bilgileri belgelenmelidir.

- Test senaryoları
- Beklenen sonuçlar
- Kullanılan örnek veriler
- Test kapsamı

Dokümantasyon testlerle birlikte güncellenmelidir.

---

# 14. Sürekli İyileştirme

Yeni hata bulunduğunda ilgili senaryo test paketine eklenmelidir.

Böylece aynı hata tekrar oluştuğunda otomatik olarak tespit edilebilir.

Test kapsamı sürekli genişletilmelidir.

---

# 15. Genel Kurallar

API test standartları, Antrenova platformunun güvenilir ve kararlı çalışmasını sağlayan temel kalite güvence mekanizmalarından biridir. Her endpoint başarılı ve başarısız senaryolarla test edilmeli, güvenlik kontrolleri doğrulanmalı ve otomatik test süreçleri CI/CD altyapısının ayrılmaz bir parçası olmalıdır.

Bu nedenle API Testing standartları tüm geliştirme yaşam döngüsünde uygulanmalı, yeni özelliklerle birlikte sürekli güncellenmeli ve platformun uzun vadeli sürdürülebilirliğini desteklemelidir.
