# 08. API Yetkilendirme Standartları (Authorization API)

> **Doküman Kodu:** API-08  
> **Dosya Adı:** `08_AUTHORIZATION_API.md`  
> **Versiyon:** 1.0  
> **Durum:** Onaylandı  
> **Bağımlı Dokümanlar:** Authentication API, API Security, Multi-Tenant Database, Business Rules, Authorization Rules

---

# 1. Amaç

Bu dokümanın amacı, Antrenova API'lerinde uygulanacak yetkilendirme (Authorization) standartlarını belirlemek ve doğrulanmış kullanıcıların yalnızca izin verilen kaynaklara erişebilmesini sağlamaktır.

Kimlik doğrulama kullanıcının kim olduğunu belirlerken, yetkilendirme hangi işlemleri yapabileceğini belirler. Bu iki süreç birbirinden bağımsızdır ve her API isteğinde ayrı ayrı değerlendirilmelidir.

Platform genelindeki tüm endpoint'ler ortak yetkilendirme kurallarını kullanmalıdır.

---

# 2. Temel İlkeler

Yetkilendirme sistemi aşağıdaki prensiplere uygun olmalıdır.

- En az yetki (Least Privilege)
- Rol bazlı erişim
- Tenant izolasyonu
- Modül bazlı izinler
- İşlem bazlı kontrol

Varsayılan yaklaşım erişimi reddetmek olmalıdır.

---

# 3. Rol Bazlı Yetkilendirme

Her kullanıcı en az bir role sahip olmalıdır.

Varsayılan roller.

```text
super_admin
owner
manager
reception
trainer
accounting
member
parent
```

Tüm API kontrolleri bu roller üzerinden yapılmalıdır.

---

# 4. Modül Yetkileri

Her rol yalnızca izin verilen modüllere erişebilmelidir.

Örneğin.

- Üye Yönetimi
- Finans
- Rezervasyon
- Raporlama
- Ayarlar

Yetkisiz modül istekleri reddedilmelidir.

---

# 5. İşlem Yetkileri

Her modül içerisinde işlem bazlı izinler uygulanmalıdır.

Örneğin.

- Görüntüleme
- Oluşturma
- Güncelleme
- Silme
- Dışa Aktarma

Aynı modülde farklı işlem izinleri bulunabilir.

---

# 6. Business ID Kontrolü

Her API isteğinde kullanıcının Business ID bilgisi doğrulanmalıdır.

Kullanıcı.

- yalnızca kendi işletmesine,
- kendi tenant verilerine

erişebilmelidir.

Business ID doğrulaması zorunludur.

---

# 7. Branch Yetkilendirmesi

Şube yapısı kullanan işletmelerde.

Branch ID kontrolü de yapılmalıdır.

Kullanıcı yalnızca yetkili olduğu şubedeki verilere erişebilmelidir.

Şubeler arası veri erişimi iş kurallarına göre sınırlandırılmalıdır.

---

# 8. Kaynak Bazlı Yetki

Bazı işlemler yalnızca belirli kayıtlara uygulanabilir.

Örneğin.

Bir eğitmen.

- yalnızca kendi derslerini,
- kendi öğrencilerini

görebilir.

Kaynak bazlı kontroller endpoint seviyesinde uygulanmalıdır.

---

# 9. Sistem Yönetimi

`super_admin` rolü platform genelindeki yönetim işlemlerini gerçekleştirebilir.

Ancak.

- tenant verileri,
- işletme işlemleri

gereksiz yere görüntülenmemelidir.

En yüksek yetki dahi Audit sistemine tabi olmalıdır.

---

# 10. Yetki Hataları

Yetki yetersizliği durumunda.

```http
403 Forbidden
```

döndürülmelidir.

Kimlik doğrulama başarılı olsa bile yetki yoksa işlem yapılmamalıdır.

---

# 11. Dinamik Yetkiler

Rol dışında ek izinler gerektiğinde.

- kullanıcı bazlı,
- modül bazlı,
- işletme bazlı

ek yetki tanımları yapılabilir.

Bu yapı temel rol sistemini bozmamalıdır.

---

# 12. Audit

Aşağıdaki işlemler kayıt altına alınmalıdır.

- Yetki reddi
- Rol değişikliği
- Yetki güncellemesi
- Yönetici işlemleri
- Kritik erişimler

Audit kayıtları değiştirilememelidir.

---

# 13. Performans

Yetkilendirme kontrolleri API performansını olumsuz etkilememelidir.

Sık kullanılan izinler.

- önbelleğe alınabilir,
- optimize edilebilir,

ancak güvenlikten ödün verilmemelidir.

---

# 14. Dokümantasyon

Her endpoint için aşağıdaki bilgiler belirtilmelidir.

- Gerekli rol
- Gerekli izin
- Business kontrolü
- Branch kontrolü
- Yetki hataları

API dokümantasyonu gerçek davranışla uyumlu olmalıdır.

---

# 15. Genel Kurallar

Authorization API, Antrenova platformunda güvenli veri erişimini sağlayan temel mekanizmadır. Her API isteğinde kullanıcı rolü, modül izinleri, Business ID ve gerektiğinde Branch ID doğrulanmalı; yalnızca yetkili işlemlere izin verilmelidir.

Bu nedenle yetkilendirme süreçleri merkezi olarak yönetilmeli, tüm endpoint'lerde aynı kurallar uygulanmalı ve güvenlik ihlallerinin önüne geçmek için Audit sistemiyle tam entegre çalışmalıdır.
