# 20. Geliştirici Kontrol Listesi (Developer Checklist)

> **Doküman Kodu:** DEV-20  
> **Dosya Adı:** `20_DEVELOPER_CHECKLIST.md`  
> **Versiyon:** 1.0  
> **Durum:** Onaylandı  
> **Bağımlı Dokümanlar:** Tüm Developer Guide Dokümanları, Software Architecture, Business Rules, API Standards, Deployment & DevOps Standards

---

# 1. Amaç

Bu dokümanın amacı, Antrenova projesinde geliştirilen her özelliğin yayınlanmadan önce aynı kalite standartlarından geçtiğini doğrulamak için kullanılacak geliştirici kontrol listesini tanımlamaktır.

Kontrol listesi yeni özellik geliştirme, hata düzeltme, performans iyileştirme ve bakım çalışmaları dahil olmak üzere tüm geliştirme faaliyetlerinde kullanılmalıdır.

Her geliştirme tamamlandığında bu liste gözden geçirilmelidir.

---

# 2. Mimari Kontrolü

Aşağıdaki sorular doğrulanmalıdır.

- Mimari standartlara uyuldu mu?
- Doğru klasör yapısı kullanıldı mı?
- Tek sorumluluk ilkesi korundu mu?
- Gereksiz bağımlılık oluşturuldu mu?

Mimari bütünlük korunmalıdır.

---

# 3. Kod Kalitesi

Kontrol edilmesi gerekenler.

- Kod okunabilir mi?
- İsimlendirme standartlarına uygun mu?
- Kod tekrarları giderildi mi?
- Magic Number kullanılmadı mı?

Kod kalite standartlarını karşılamalıdır.

---

# 4. Multi-Tenant Kontrolü

Her geliştirme aşağıdaki açıdan incelenmelidir.

- `business_id` kontrolü yapıldı mı?
- Şube izolasyonu doğru mu?
- İşletmeler arası veri erişimi engellendi mi?

Bu kontrol zorunludur.

---

# 5. Güvenlik Kontrolü

Kontrol edilmesi gerekenler.

- Authentication
- Authorization
- Validation
- SQL Injection koruması
- XSS koruması

Güvenlik açıkları kapatılmalıdır.

---

# 6. Veritabanı

Yeni veritabanı değişiklikleri için.

- Migration hazır mı?
- İndeksler uygun mu?
- Foreign Key kontrol edildi mi?
- Soft Delete ihtiyacı değerlendirildi mi?

Şema tutarlılığı korunmalıdır.

---

# 7. API Kontrolü

Yeni endpoint geliştirildiyse.

- DTO kullanıldı mı?
- Validation yapıldı mı?
- Yetki kontrolü var mı?
- Hata yönetimi uygun mu?

API standartları uygulanmalıdır.

---

# 8. Kullanıcı Arayüzü

Yeni ekranlar aşağıdaki kriterleri sağlamalıdır.

- UI/UX Bible ile uyumlu mu?
- Responsive çalışıyor mu?
- Erişilebilirlik sağlandı mı?
- Form doğrulamaları tamamlandı mı?

Tutarlı kullanıcı deneyimi korunmalıdır.

---

# 9. Performans

Performans açısından aşağıdaki kontroller yapılmalıdır.

- Gereksiz sorgu var mı?
- Gereksiz render oluşuyor mu?
- Büyük işlemler Queue üzerinden mi?
- Cache ihtiyacı değerlendirildi mi?

Performans darboğazı oluşturulmamalıdır.

---

# 10. Test

Kod yayınlanmadan önce.

- Unit Test
- Integration Test
- Manuel Test

tamamlanmalıdır.

Başarısız testlerle yayın yapılmamalıdır.

---

# 11. Log ve Monitoring

Kontrol edilmesi gerekenler.

- Kritik işlemler loglanıyor mu?
- Monitoring destekleniyor mu?
- Alarm gerektiren durumlar tanımlandı mı?

İzlenebilirlik korunmalıdır.

---

# 12. Dokümantasyon

Kod değişikliği dokümanı etkiliyorsa.

- API belgeleri
- Veritabanı belgeleri
- İş kuralları
- Mimari dokümanlar

güncellenmelidir.

Kod ve doküman birlikte ilerlemelidir.

---

# 13. Code Review

Merge öncesinde.

- Review tamamlandı mı?
- Tüm yorumlar çözüldü mü?
- Onay alındı mı?

Review tamamlanmadan Merge yapılmamalıdır.

---

# 14. Deployment Hazırlığı

Yayın öncesinde.

- Environment değişkenleri kontrol edildi mi?
- Migration doğrulandı mı?
- Rollback planı hazır mı?
- CI/CD başarılı mı?

Deployment güvenli şekilde yapılmalıdır.

---

# 15. Genel Kurallar

Developer Checklist, Antrenova platformunda geliştirilen her özelliğin aynı kalite standartlarından geçtiğini doğrulayan son kontrol mekanizmasıdır. Mimari, güvenlik, performans, test, dokümantasyon ve yayın hazırlıkları eksiksiz tamamlanmadan geliştirme tamamlanmış kabul edilmemelidir.

Bu kontrol listesi tüm geliştiriciler tarafından standart olarak kullanılmalı ve her yayın öncesinde eksiksiz uygulanmalıdır. Böylece Antrenova'nın kod kalitesi, güvenliği ve sürdürülebilirliği uzun yıllar boyunca korunabilir.
