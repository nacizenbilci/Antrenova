# 12. API Geliştirme Rehberi (API Development Guide)

> **Doküman Kodu:** DEV-12  
> **Dosya Adı:** `12_API_DEVELOPMENT_GUIDE.md`  
> **Versiyon:** 1.0  
> **Durum:** Onaylandı  
> **Bağımlı Dokümanlar:** API Standards, Security Standards, Error Handling Guide, Database Development Guide, TypeScript Guidelines

---

# 1. Amaç

Bu dokümanın amacı, Antrenova platformunda geliştirilecek tüm API servislerinin ortak geliştirme yaklaşımına uygun hazırlanmasını, güvenli çalışmasını ve uzun vadede sürdürülebilir olmasını sağlamaktır.

API geliştirme yalnızca veri alıp döndüren endpoint'lerden oluşmaz. Kimlik doğrulama, yetkilendirme, doğrulama, hata yönetimi, performans, sürümlendirme ve dokümantasyon süreçleri birlikte değerlendirilmelidir.

Platformdaki tüm API geliştirmeleri bu rehbere uygun yapılmalıdır.

---

# 2. Temel İlkeler

API geliştirme aşağıdaki prensiplere uygun olmalıdır.

- REST standartlarına uygun olmalıdır.
- Güvenli olmalıdır.
- Tutarlı olmalıdır.
- Performanslı olmalıdır.
- Dokümante edilmelidir.

Her endpoint aynı geliştirme kurallarını uygulamalıdır.

---

# 3. Endpoint Tasarımı

Endpoint isimleri kaynak odaklı olmalıdır.

Örneğin.

```text
/api/members

/api/payments

/api/reservations

/api/packages
```

Fiil isimleri URL içerisinde kullanılmamalıdır.

---

# 4. HTTP Method Kullanımı

HTTP metodları doğru amaçla kullanılmalıdır.

- GET → Veri okuma
- POST → Yeni kayıt
- PUT → Tam güncelleme
- PATCH → Kısmi güncelleme
- DELETE → Silme

Method seçimi iş mantığını yansıtmalıdır.

---

# 5. Kimlik Doğrulama

Korunan tüm endpoint'ler kullanıcı kimliğini doğrulamalıdır.

Kontroller.

- Token doğrulaması
- Oturum kontrolü
- Süre kontrolü

Doğrulanmamış kullanıcı işlem yapamamalıdır.

---

# 6. Yetkilendirme

Kimlik doğrulaması yeterli değildir.

Her istek için.

- Rol kontrolü
- Yetki kontrolü
- Business ID doğrulaması

uygulanmalıdır.

Yetkisiz veri erişimi engellenmelidir.

---

# 7. DTO Kullanımı

Request ve Response modelleri DTO üzerinden tanımlanmalıdır.

Kurallar.

- Validation desteklenmelidir.
- Gereksiz alan döndürülmemelidir.
- Veritabanı modeli doğrudan paylaşılmamalıdır.

DTO yapısı merkezi yönetilmelidir.

---

# 8. Doğrulama

Tüm giriş verileri doğrulanmalıdır.

Örneğin.

- Tip kontrolü
- Uzunluk
- Format
- İş kuralları

İstemci doğrulamasına güvenilmemelidir.

---

# 9. Hata Yönetimi

API yanıtları standart hata formatını kullanmalıdır.

İçerik.

- Error Code
- Message
- Request ID

Teknik ayrıntılar kullanıcıya gönderilmemelidir.

---

# 10. Sayfalama

Liste döndüren endpoint'lerde Pagination kullanılmalıdır.

Desteklenmesi gereken bilgiler.

- Sayfa
- Sayfa boyutu
- Toplam kayıt
- Toplam sayfa

Tüm kayıtlar tek istekte gönderilmemelidir.

---

# 11. Performans

API geliştirilirken performans dikkate alınmalıdır.

Örneğin.

- Gereksiz JOIN
- Gereksiz sorgu
- Büyük Response
- N+1 problemi

Performans ölçülerek optimize edilmelidir.

---

# 12. Loglama

Kritik API işlemleri loglanmalıdır.

Kaydedilecek bilgiler.

- Endpoint
- Süre
- Kullanıcı
- Business ID
- Sonuç

Kişisel veriler loglanmamalıdır.

---

# 13. Kod İnceleme

API geliştirmeleri aşağıdaki kriterlerle değerlendirilmelidir.

- Güvenlik
- Yetkilendirme
- Validation
- DTO
- Performans

Review süreci tamamlanmadan yayın yapılmamalıdır.

---

# 14. Sürekli İyileştirme

API yapısı düzenli olarak analiz edilmelidir.

İyileştirilebilecek alanlar.

- Performans
- Güvenlik
- Endpoint tasarımı
- Hata yönetimi
- Dokümantasyon

Yeni standartlar kontrollü şekilde uygulanmalıdır.

---

# 15. Genel Kurallar

API Development Guide, Antrenova platformundaki tüm servislerin güvenli, performanslı ve sürdürülebilir şekilde geliştirilmesini sağlayan temel geliştirme rehberidir. Tüm endpoint'ler ortak standartları kullanmalı, kimlik doğrulama ve yetkilendirme uygulanmalı, DTO yapısı korunmalı ve performans ile güvenlik her geliştirme sürecinde ön planda tutulmalıdır.

Bu yaklaşım sayesinde API mimarisi büyüdükçe tutarlılığını korur, bakım kolaylaşır, entegrasyon süreçleri sadeleşir ve platform uzun vadede güvenilir bir servis altyapısına sahip olur.
