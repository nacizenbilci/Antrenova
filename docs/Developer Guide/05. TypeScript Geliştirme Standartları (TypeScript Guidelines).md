# 05. TypeScript Geliştirme Standartları (TypeScript Guidelines)

> **Doküman Kodu:** DEV-05  
> **Dosya Adı:** `05_TYPESCRIPT_GUIDELINES.md`  
> **Versiyon:** 1.0  
> **Durum:** Onaylandı  
> **Bağımlı Dokümanlar:** Coding Standards, Naming Conventions, API Standards, Database Standards

---

# 1. Amaç

Bu dokümanın amacı, Antrenova projesinde TypeScript kullanımına ilişkin standartları belirlemek, tip güvenliğini artırmak ve büyük ölçekli kod tabanında oluşabilecek hataları geliştirme aşamasında önlemektir.

TypeScript yalnızca JavaScript üzerine eklenmiş tip tanımları değildir. Kodun daha güvenli yazılmasını, otomatik tamamlama desteğini güçlendirmesini, yeniden düzenlemeleri kolaylaştırmasını ve ekip içindeki iletişimi standartlaştırmasını sağlayan temel geliştirme aracıdır.

Projedeki tüm yeni kodlar TypeScript standartlarına uygun geliştirilmelidir.

---

# 2. Temel İlkeler

TypeScript kullanımı aşağıdaki prensiplere uygun olmalıdır.

- Güçlü tip kullanılmalıdır.
- Tip güvenliği korunmalıdır.
- Tahmin edilebilir kod yazılmalıdır.
- Gereksiz `any` kullanımından kaçınılmalıdır.
- Okunabilirlik ön planda tutulmalıdır.

Derleyicinin uyarıları dikkate alınmalıdır.

---

# 3. Strict Mode

Proje **TypeScript Strict Mode** ile çalışmalıdır.

Kurallar.

- `strict` kapatılmamalıdır.
- Tip hataları göz ardı edilmemelidir.
- Uyarılar çözülmeden kod tamamlanmış sayılmamalıdır.

Strict Mode proje genelinde zorunludur.

---

# 4. `any` Kullanımı

`any` yalnızca istisnai durumlarda kullanılmalıdır.

Tercih sırası.

```text
Specific Type
↓

Interface

↓

Type

↓

Generic

↓

unknown

↓

any
```

`any` son çare olarak değerlendirilmelidir.

---

# 5. Interface ve Type

Genel veri yapıları için `interface`, birleşik veya türetilmiş tipler için `type` kullanılmalıdır.

Örneğin.

- API modelleri
- Veritabanı kayıtları
- DTO yapıları
- Bileşen özellikleri

Tutarlı kullanım sağlanmalıdır.

---

# 6. Null ve Undefined

Null değerler açık şekilde yönetilmelidir.

Kurallar.

- Gereksiz nullable alan oluşturulmamalıdır.
- Optional alanlar bilinçli kullanılmalıdır.
- Null kontrolü yapılmadan erişim sağlanmamalıdır.

Sessiz hatalar engellenmelidir.

---

# 7. Enum Kullanımı

Sabit seçenekler için Enum kullanılabilir.

Örneğin.

- Üye Durumu
- Ödeme Durumu
- Rezervasyon Durumu

Dinamik veriler için Enum kullanılmamalıdır.

---

# 8. Generic Kullanımı

Generic yapılar tekrar kullanılabilir kod üretmek için kullanılmalıdır.

Örneğin.

- Sayfalama sonuçları
- API Response
- Repository yapıları

Gereksiz Generic karmaşıklığından kaçınılmalıdır.

---

# 9. Tip Dönüştürme

Zorunlu tip dönüşümleri minimum seviyede tutulmalıdır.

Kurallar.

- Güvenli dönüşüm yapılmalıdır.
- Tür doğrulanmalıdır.
- Gereksiz Cast kullanılmamalıdır.

Tip sistemi atlatılmamalıdır.

---

# 10. Fonksiyon Tipleri

Fonksiyonların parametre ve dönüş tipleri açıkça belirtilmelidir.

Örneğin.

- Parametre tipleri
- Return Type
- Async dönüş tipleri

Belirsiz dönüşlerden kaçınılmalıdır.

---

# 11. DTO Kullanımı

API ile taşınan veriler DTO üzerinden tanımlanmalıdır.

Kurallar.

- Request DTO
- Response DTO
- Validation kuralları

Veritabanı modeli doğrudan dış dünyaya açılmamalıdır.

---

# 12. Tip Paylaşımı

Ortak tipler merkezi klasörde tutulmalıdır.

Örneğin.

```text
types/

api/

database/

auth/

shared/
```

Aynı tip farklı dosyalarda tekrar oluşturulmamalıdır.

---

# 13. Kod İnceleme

Kod incelemelerinde aşağıdaki konular kontrol edilmelidir.

- Gereksiz any kullanımı
- Tip güvenliği
- Nullable alanlar
- Generic kullanımı
- Interface tutarlılığı

TypeScript standartları Review sürecinin parçasıdır.

---

# 14. Sürekli İyileştirme

TypeScript kullanımı düzenli olarak geliştirilmelidir.

İyileştirilebilecek alanlar.

- Tip güvenliği
- Generic kullanımı
- DTO yapıları
- Shared Types
- Strict kuralları

Yeni TypeScript özellikleri uygun olduğunda projeye dahil edilmelidir.

---

# 15. Genel Kurallar

TypeScript Guidelines, Antrenova projesinde güçlü tip güvenliği sağlayan temel geliştirme standartlarını tanımlar. Tüm kodlar Strict Mode altında geliştirilmeli, `any` kullanımından kaçınılmalı, tipler merkezi olarak yönetilmeli ve veri modelleri açık şekilde tanımlanmalıdır.

Bu yaklaşım sayesinde geliştirme aşamasında birçok hata önceden yakalanır, yeniden düzenlemeler güvenli şekilde yapılabilir, ekip içi tutarlılık korunur ve proje büyüdükçe kod kalitesi sürdürülebilir hale gelir.
