# 04. İsimlendirme Standartları (Naming Conventions)

> **Doküman Kodu:** DEV-04  
> **Dosya Adı:** `04_NAMING_CONVENTIONS.md`  
> **Versiyon:** 1.0  
> **Durum:** Onaylandı  
> **Bağımlı Dokümanlar:** Coding Standards, TypeScript Guidelines, Database Standards, API Standards

---

# 1. Amaç

Bu dokümanın amacı, Antrenova projesinde kullanılacak tüm isimlendirme kurallarını standartlaştırmak ve kod tabanında ortak bir dil oluşturmaktır.

İsimlendirme yalnızca değişken adlarından ibaret değildir. Dosyalar, klasörler, fonksiyonlar, bileşenler, API endpoint'leri, veritabanı tabloları, kolonlar, tipler ve sabitler aynı kurallara göre adlandırılmalıdır.

Tutarlı isimlendirme, okunabilirliği artırır, hata riskini azaltır ve geliştiricilerin kodu daha hızlı anlamasını sağlar.

---

# 2. Temel İlkeler

İsimlendirme aşağıdaki prensiplere uygun olmalıdır.

- Açık olmalıdır.
- Anlam taşımalıdır.
- Kısa fakat açıklayıcı olmalıdır.
- Tutarlı olmalıdır.
- İngilizce kullanılmalıdır.

Kısaltmalar yalnızca yaygın kabul gören durumlarda kullanılmalıdır.

---

# 3. Dosya İsimleri

Dosya isimleri küçük harf ve kebab-case formatında yazılmalıdır.

Örnek.

```text
member-card.tsx
payment-service.ts
reservation-table.tsx
```

Boşluk ve Türkçe karakter kullanılmamalıdır.

---

# 4. Klasör İsimleri

Klasör isimleri de kebab-case formatında olmalıdır.

Örnek.

```text
member-management
payment-history
reservation-calendar
```

Klasör isimleri içerdiği modülü açıkça ifade etmelidir.

---

# 5. React Component

React bileşenleri PascalCase kullanılmalıdır.

Örnek.

```text
MemberCard
PaymentModal
ReservationCalendar
DashboardHeader
```

Her bileşen adı bir kullanıcı arayüzü öğesini ifade etmelidir.

---

# 6. Değişkenler

Değişken isimleri camelCase kullanılmalıdır.

Örnek.

```text
memberName
paymentAmount
reservationDate
branchId
```

Tek harfli değişkenlerden kaçınılmalıdır.

---

# 7. Fonksiyonlar

Fonksiyon isimleri yaptığı işi ifade etmelidir.

Örnek.

```text
createMember()
updatePayment()
cancelReservation()
sendNotification()
```

Fonksiyon isimleri fiil ile başlamalıdır.

---

# 8. Boolean Değişkenler

Boolean isimleri soru niteliğinde olmalıdır.

Örneğin.

```text
isActive
isExpired
hasPermission
canEdit
shouldNotify
```

Boolean isimleri durumu açıkça ifade etmelidir.

---

# 9. Sabitler

Global sabitler büyük harf ve snake_case kullanılmalıdır.

Örnek.

```text
MAX_UPLOAD_SIZE

DEFAULT_PAGE_SIZE

TOKEN_EXPIRATION_MINUTES
```

Sabitlerin anlamı açık olmalıdır.

---

# 10. TypeScript Türleri

Interface, Type ve Class isimleri PascalCase kullanılmalıdır.

Örneğin.

```text
Member

Payment

ReservationDto

DashboardStatistics
```

Kısaltmalar minimum seviyede tutulmalıdır.

---

# 11. API Endpoint

Endpoint isimleri küçük harf kullanılmalıdır.

Örnek.

```text
/api/members

/api/payments

/api/reservations
```

Fiil yerine kaynak adı tercih edilmelidir.

---

# 12. Veritabanı

Tablo ve kolon isimleri snake_case kullanılmalıdır.

Örnek.

```text
members

payment_transactions

created_at

business_id
```

Kısaltılmış kolon isimlerinden kaçınılmalıdır.

---

# 13. Enum

Enum isimleri PascalCase olmalıdır.

Enum değerleri ise büyük harfle yazılmalıdır.

Örneğin.

```text
MemberStatus

ACTIVE

PASSIVE

SUSPENDED
```

Enum isimleri tekil kullanılmalıdır.

---

# 14. Yasaklanan İsimler

Aşağıdaki isimler kullanılmamalıdır.

```text
temp

test

data

value

obj

item

newData
```

Bu tür isimler kodun anlaşılmasını zorlaştırır.

---

# 15. Genel Kurallar

Naming Conventions, Antrenova projesindeki tüm isimlendirme kurallarının ortak standardını oluşturur. Dosyalar, klasörler, değişkenler, fonksiyonlar, bileşenler, API endpoint'leri ve veritabanı nesneleri belirlenen biçimlerde adlandırılmalı; isimler açık, anlamlı ve proje genelinde tutarlı olmalıdır.

Bu yaklaşım sayesinde kod tabanı daha okunabilir hale gelir, ekip üyeleri ortak bir dil kullanır, bakım süreçleri kolaylaşır ve proje büyüdükçe isim karmaşası oluşmasının önüne geçilir.
