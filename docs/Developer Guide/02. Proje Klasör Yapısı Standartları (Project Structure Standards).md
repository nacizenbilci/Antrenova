# 02. Proje Klasör Yapısı Standartları (Project Structure Standards)

> **Doküman Kodu:** DEV-02  
> **Dosya Adı:** `02_PROJECT_STRUCTURE.md`  
> **Versiyon:** 1.0  
> **Durum:** Onaylandı  
> **Bağımlı Dokümanlar:** Software Architecture, Next.js Standards, Database Standards, API Standards

---

# 1. Amaç

Bu dokümanın amacı, Antrenova projesinde kullanılacak klasör ve dosya organizasyonunu standartlaştırmak, tüm geliştiricilerin aynı proje yapısını kullanmasını sağlamak ve kod tabanının büyüdükçe düzenini korumaktır.

Klasör yapısı yalnızca dosyaları gruplamak için değildir. Modüllerin birbirinden ayrılması, bağımlılıkların azaltılması, kodun kolay bulunabilmesi ve bakım maliyetinin düşürülmesi açısından kritik öneme sahiptir.

Platform genelindeki tüm geliştirmeler bu klasör yapısına uygun yapılmalıdır.

---

# 2. Temel İlkeler

Proje yapısı aşağıdaki prensiplere uygun olmalıdır.

- Modüler olmalıdır.
- Anlaşılır olmalıdır.
- Ölçeklenebilir olmalıdır.
- Tek sorumluluk ilkesine uygun olmalıdır.
- Gereksiz klasörlerden kaçınılmalıdır.

Klasör yapısı geliştiricinin kodu kolay bulmasını sağlamalıdır.

---

# 3. Ana Dizin Yapısı

Proje kök dizininde aşağıdaki temel klasörler bulunmalıdır.

```text
app/
components/
features/
lib/
hooks/
services/
types/
utils/
docs/
public/
styles/
supabase/
scripts/
tests/
```

Her klasörün belirli bir sorumluluğu olmalıdır.

---

# 4. app Dizini

`app/` yalnızca Next.js App Router yapısını içermelidir.

İçerik örnekleri.

- Sayfalar
- Layout dosyaları
- Route Handler
- Loading
- Error
- Not Found

İş mantığı bu klasörde yer almamalıdır.

---

# 5. components Dizini

Tekrar kullanılabilir kullanıcı arayüzü bileşenleri burada tutulmalıdır.

Örneğin.

```text
Button
Input
Modal
Table
Card
Avatar
```

Bileşenler mümkün olduğunca bağımsız olmalıdır.

---

# 6. features Dizini

Her iş modülü kendi klasörü altında geliştirilmelidir.

Örneğin.

```text
members/
payments/
reservations/
packages/
dashboard/
notifications/
```

Modüller birbirinden bağımsız geliştirilebilmelidir.

---

# 7. lib Dizini

Ortak altyapı kodları burada bulunmalıdır.

Örneğin.

- Authentication
- Authorization
- Database
- Queue
- Logger
- Cache

İş kuralları burada yazılmamalıdır.

---

# 8. services Dizini

Harici servis entegrasyonları burada yer almalıdır.

Örneğin.

- WhatsApp
- SMTP
- Storage
- Payment
- SMS

Her servis ayrı klasörde yönetilmelidir.

---

# 9. hooks Dizini

Özel React Hook'ları burada tutulmalıdır.

Örneğin.

```text
useAuth
useMember
usePermission
usePagination
```

Hook'lar yalnızca ortak davranışları kapsamalıdır.

---

# 10. types Dizini

Paylaşılan TypeScript tipleri burada bulunmalıdır.

Örneğin.

- API Types
- Database Types
- DTO
- Enum
- Interface

Tip tekrarından kaçınılmalıdır.

---

# 11. utils Dizini

Yardımcı fonksiyonlar burada yer almalıdır.

Örneğin.

- Date Helpers
- Formatters
- Validators
- Calculators

İş kuralları Utility fonksiyonlarına yazılmamalıdır.

---

# 12. tests Dizini

Test dosyaları standart şekilde organize edilmelidir.

Örneğin.

```text
unit/
integration/
e2e/
fixtures/
```

Test verileri üretim kodundan ayrılmalıdır.

---

# 13. docs Dizini

Projeye ait tüm teknik dokümanlar burada tutulmalıdır.

İçerik.

- UI/UX Bible
- Architecture
- Business Rules
- API
- Database
- Workflow
- DevOps
- Developer Guide

Kod ile doküman birlikte sürümlenmelidir.

---

# 14. Yeni Klasör Oluşturma

Yeni klasör oluşturulmadan önce aşağıdaki sorular değerlendirilmelidir.

- Mevcut yapıya uygun mu?
- Tek sorumluluğu var mı?
- Başka klasörde bulunabilir mi?
- Uzun vadede kullanılacak mı?

Gereksiz klasör oluşturulmamalıdır.

---

# 15. Genel Kurallar

Project Structure standartları, Antrenova kod tabanının uzun yıllar düzenli kalmasını sağlayan temel geliştirme kurallarından biridir. Tüm dosyalar belirlenen klasör yapısına uygun yerleştirilmeli, modüller birbirinden ayrılmalı, ortak kodlar merkezi klasörlerde tutulmalı ve proje yapısı büyüdükçe okunabilirliğini korumalıdır.

Bu yaklaşım sayesinde yeni geliştiriciler projeye daha hızlı adapte olur, bakım maliyetleri azalır, modüller bağımsız geliştirilebilir ve Antrenova'nın kod tabanı sürdürülebilir bir yapıya kavuşur.
