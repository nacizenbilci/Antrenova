# 16. Kod İnceleme Rehberi (Code Review Guide)

> **Doküman Kodu:** DEV-16  
> **Dosya Adı:** `16_CODE_REVIEW_GUIDE.md`  
> **Versiyon:** 1.0  
> **Durum:** Onaylandı  
> **Bağımlı Dokümanlar:** Coding Standards, Git Workflow Guide, Security Standards, Testing Guide, API Standards

---

# 1. Amaç

Bu dokümanın amacı, Antrenova projesinde gerçekleştirilecek tüm kod inceleme (Code Review) süreçlerini standartlaştırmak, yazılım kalitesini yükseltmek ve bilgi paylaşımını artırmaktır.

Kod inceleme yalnızca hata bulma süreci değildir. Mimari tutarlılığı korumak, güvenlik açıklarını erken tespit etmek, performansı değerlendirmek, kod okunabilirliğini artırmak ve ekip içerisinde ortak geliştirme kültürü oluşturmak için uygulanan temel kalite güvence mekanizmasıdır.

Production ortamına gönderilecek her kod değişikliği bu rehbere uygun şekilde incelenmelidir.

---

# 2. Temel İlkeler

Kod inceleme aşağıdaki prensiplere uygun olmalıdır.

- Yapıcı olmalıdır.
- Nesnel olmalıdır.
- Standartlara dayanmalıdır.
- Öğretici olmalıdır.
- Dokümante edilmelidir.

Kod değil, çözüm yaklaşımı değerlendirilmelidir.

---

# 3. Review Zorunluluğu

Aşağıdaki geliştirmeler Code Review sürecinden geçmelidir.

- Yeni özellikler
- Hata düzeltmeleri
- Veritabanı değişiklikleri
- API geliştirmeleri
- Yetkilendirme değişiklikleri
- Güvenlik güncellemeleri

Review tamamlanmadan Merge işlemi yapılmamalıdır.

---

# 4. İnceleme Kapsamı

Kod incelemesi yalnızca çalışan kodu doğrulamaz.

Aşağıdaki alanlar değerlendirilmelidir.

- Mimari uyum
- Kod okunabilirliği
- Performans
- Güvenlik
- Test kapsamı
- Dokümantasyon

Her değişiklik bütünsel olarak incelenmelidir.

---

# 5. Mimari Uyum

Kod mevcut mimariye uygun olmalıdır.

Kontrol edilmesi gerekenler.

- Klasör yapısı
- Katman ayrımı
- Modüler yapı
- Bağımlılıklar

Mimariyi bozan çözümler kabul edilmemelidir.

---

# 6. Kod Kalitesi

Kod aşağıdaki kriterlere göre değerlendirilmelidir.

- Açıklayıcı isimler
- Kısa fonksiyonlar
- Tek sorumluluk
- Kod tekrarının önlenmesi
- Anlaşılır akış

Gereksiz karmaşıklık azaltılmalıdır.

---

# 7. Güvenlik Kontrolleri

Her geliştirme güvenlik açısından incelenmelidir.

Kontrol alanları.

- Yetkilendirme
- Girdi doğrulama
- SQL Injection koruması
- XSS koruması
- Gizli bilgilerin korunması

Güvenlik eksikleri öncelikli olarak düzeltilmelidir.

---

# 8. Performans Değerlendirmesi

Kod performans açısından değerlendirilmelidir.

Örneğin.

- Gereksiz sorgular
- Büyük veri döngüleri
- Fazla render
- Gereksiz API çağrıları

Performans sorunları Merge öncesinde giderilmelidir.

---

# 9. Test Kontrolü

Her geliştirme uygun testlerle desteklenmelidir.

Kontrol edilmesi gerekenler.

- Unit Test
- Integration Test
- Manuel doğrulama
- Başarılı CI sonuçları

Test edilmeyen kritik kodlar yayınlanmamalıdır.

---

# 10. Dokümantasyon

Kod değişiklikleri dokümantasyonu etkiliyorsa ilgili belgeler güncellenmelidir.

Örneğin.

- API değişikliği
- Yeni iş kuralı
- Veritabanı şeması
- Yeni modül

Kod ve doküman birlikte ilerlemelidir.

---

# 11. Review Geri Bildirimi

Geri bildirimler açık ve çözüm odaklı olmalıdır.

Kurallar.

- Somut örnek verilmelidir.
- Standart referans gösterilmelidir.
- Kişisel ifadelerden kaçınılmalıdır.

Amaç kodun kalitesini artırmaktır.

---

# 12. Onay Süreci

Kod aşağıdaki şartlar sağlandıktan sonra onaylanmalıdır.

- Tüm yorumlar çözüldü.
- Testler başarılı.
- Güvenlik kontrolleri tamamlandı.
- Dokümantasyon güncellendi.

Onay sonrası Merge işlemi gerçekleştirilebilir.

---

# 13. Audit

Review süreçleri kayıt altına alınmalıdır.

Kaydedilecek bilgiler.

- İnceleyen kişi
- İnceleme tarihi
- Tespit edilen sorunlar
- Yapılan düzeltmeler
- Onay durumu

Review geçmişi kalite analizlerinde kullanılmalıdır.

---

# 14. Sürekli İyileştirme

Kod inceleme süreçleri düzenli olarak değerlendirilmelidir.

İyileştirilebilecek alanlar.

- Review süresi
- Tekrarlayan hatalar
- Kod kalitesi
- Güvenlik kontrolleri
- Test kapsamı

Review standartları proje geliştikçe güncellenmelidir.

---

# 15. Genel Kurallar

Code Review Guide, Antrenova projesinde geliştirilen tüm kodların kalite standartlarına uygunluğunu doğrulayan temel geliştirme rehberidir. Her kod değişikliği mimari, güvenlik, performans, test ve dokümantasyon açısından değerlendirilmeli; yapıcı geri bildirimlerle iyileştirilmeli ve yalnızca gerekli kalite kriterlerini sağlayan kodlar ana dala aktarılmalıdır.

Bu yaklaşım sayesinde kod kalitesi sürekli yükselir, teknik borç azalır, ekip içinde ortak geliştirme kültürü oluşur ve platform uzun vadede sürdürülebilir bir yazılım mimarisine sahip olur.
