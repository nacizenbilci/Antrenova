# 01. Developer Guide Genel Bakış (Developer Guide Overview)

> **Doküman Kodu:** DEV-01  
> **Dosya Adı:** `01_DEVELOPER_GUIDE_OVERVIEW.md`  
> **Versiyon:** 1.0  
> **Durum:** Onaylandı  
> **Bağımlı Dokümanlar:** Tüm Antrenova Dokümantasyonu

---

# 1. Amaç

Bu dokümanın amacı, Antrenova projesine katkı sağlayacak tüm geliştiriciler için ortak geliştirme kültürünü oluşturmak, teknik standartların nasıl uygulanacağını açıklamak ve proje genelinde tutarlı bir yazılım geliştirme yaklaşımı sağlamaktır.

Developer Guide; mimari kararları yeniden tanımlamaz. Bunun yerine daha önce hazırlanan UI/UX Bible, Software Architecture, Business Rules, Database Standards, API Standards, Workflow Standards ve Deployment & DevOps Standards dokümanlarının günlük geliştirme sürecinde nasıl uygulanacağını açıklar.

Bu doküman serisi, projeye yeni katılan bir geliştiricinin mümkün olan en kısa sürede proje standartlarını anlayarak üretken hale gelmesini hedefler.

---

# 2. Kapsam

Developer Guide aşağıdaki konuları kapsar.

- Proje klasör yapısı
- Kodlama standartları
- İsimlendirme kuralları
- TypeScript kullanımı
- Next.js geliştirme standartları
- React bileşen yapısı
- State yönetimi
- Form geliştirme
- Hata yönetimi
- API geliştirme
- Veritabanı geliştirme
- Yetkilendirme
- Test süreçleri
- Git iş akışı
- Kod inceleme
- Dokümantasyon
- Performans optimizasyonu
- Güvenlik kuralları
- Geliştirici kontrol listeleri

Bu rehber uygulama geliştirme sırasında günlük referans dokümanı olarak kullanılmalıdır.

---

# 3. Temel Yaklaşım

Antrenova geliştirilirken aşağıdaki prensipler esas alınmalıdır.

- Okunabilir kod yazılmalıdır.
- Basit çözümler tercih edilmelidir.
- Gereksiz karmaşıklıktan kaçınılmalıdır.
- Kod tekrarından kaçınılmalıdır.
- Ölçeklenebilir yapı korunmalıdır.
- Güvenlik hiçbir zaman ikinci planda bırakılmamalıdır.

Kod yalnızca çalışıyor olması için değil, yıllar sonra da kolay anlaşılabilir olması için yazılmalıdır.

---

# 4. Dokümantasyon Önceliği

Kod yazılmadan önce ilgili doküman incelenmelidir.

Örneğin.

- Yeni API geliştirilecekse API Standards okunmalıdır.
- Yeni tablo oluşturulacaksa Database Standards referans alınmalıdır.
- Yeni ekran geliştirilecekse UI/UX Bible incelenmelidir.

Dokümanlar geliştirme sürecinin temel referansıdır.

---

# 5. Tek Doğruluk Kaynağı

Her konu için yalnızca tek referans doküman kullanılmalıdır.

Örneğin.

- Yetkilendirme → Business Rules
- API → API Standards
- Deployment → DevOps Standards
- UI → UI/UX Bible

Aynı bilginin farklı yerlerde tekrar edilmesinden kaçınılmalıdır.

---

# 6. Kod Kalitesi

Kod aşağıdaki özelliklere sahip olmalıdır.

- Anlaşılır
- Test edilebilir
- Modüler
- Genişletilebilir
- Güvenli

Kısa olması kaliteli olduğu anlamına gelmez.

---

# 7. Ölçeklenebilirlik

Her geliştirme gelecekteki büyüme düşünülerek yapılmalıdır.

Platform başlangıçta küçük işletmeler tarafından kullanılacak olsa bile mimari;

- yüzlerce işletmeyi,
- binlerce kullanıcıyı,
- milyonlarca kayıtı

destekleyebilecek şekilde korunmalıdır.

---

# 8. Multi-Tenant Yaklaşımı

Platformun temel mimarisi Multi-Tenant'tır.

Bu nedenle geliştirilen her modül.

- Business ID
- Yetkilendirme
- Veri izolasyonu

kurallarına uymak zorundadır.

Hiçbir geliştirme bu mimariyi ihlal edemez.

---

# 9. Güvenlik Yaklaşımı

Her geliştirici güvenliği kendi sorumluluğu olarak görmelidir.

Aşağıdaki prensipler uygulanmalıdır.

- Yetki kontrolü
- Girdi doğrulama
- Gizli bilgi koruması
- SQL Injection önlemleri
- XSS önlemleri

Güvenlik sonradan eklenen bir özellik değildir.

---

# 10. Performans Yaklaşımı

Performans sorunları oluşmasını beklemeden önlenmelidir.

Örneğin.

- Gereksiz sorgular yazılmamalıdır.
- Büyük işlemler Queue üzerinden yürütülmelidir.
- Sayfalama kullanılmalıdır.
- Cache stratejileri uygulanmalıdır.

Her modül performans açısından değerlendirilmelidir.

---

# 11. Test Kültürü

Kod geliştirildikten sonra test edilmesi beklenmez.

Kod geliştirilirken test edilebilir şekilde tasarlanmalıdır.

Her geliştirici.

- Unit Test
- Integration Test
- Manuel doğrulama

süreçlerini destekleyen kod yazmalıdır.

---

# 12. Takım Çalışması

Kod bireysel değil ekip çalışmasına uygun yazılmalıdır.

Kurallar.

- Açıklayıcı isimler kullanılmalıdır.
- Gerektiğinde yorum eklenmelidir.
- Standartlara uyulmalıdır.

Kod başkasının okuyacağı düşünülerek yazılmalıdır.

---

# 13. Sürekli Öğrenme

Teknolojiler zamanla değişecektir.

Bu nedenle geliştiriciler.

- Next.js
- React
- TypeScript
- PostgreSQL
- Supabase

başta olmak üzere kullanılan teknolojileri düzenli takip etmelidir.

---

# 14. Doküman Güncelliği

Kod değiştiğinde ilgili doküman da güncellenmelidir.

Kod ile doküman birbirinden bağımsız yaşamamalıdır.

Eski dokümanlar yanlış geliştirmelere neden olabilir.

---

# 15. Genel Kurallar

Developer Guide, Antrenova projesinin günlük geliştirme rehberidir. Tüm geliştiriciler ortak standartlara uymalı, mevcut dokümantasyonu referans almalı, kod kalitesini korumalı ve her geliştirmeyi uzun vadeli sürdürülebilirlik hedefiyle gerçekleştirmelidir.

Bu rehber tamamlandığında projeye katılan herhangi bir geliştirici, yalnızca bu dokümanları takip ederek Antrenova'nın mimarisine, geliştirme standartlarına ve çalışma prensiplerine uyum sağlayabilecek seviyede bilgiye sahip olacaktır.
