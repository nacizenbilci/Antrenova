# 19. Güvenli Yazılım Geliştirme Rehberi (Secure Development Guide)

> **Doküman Kodu:** DEV-19  
> **Dosya Adı:** `19_SECURITY_GUIDE.md`  
> **Versiyon:** 1.0  
> **Durum:** Onaylandı  
> **Bağımlı Dokümanlar:** Security Standards, API Standards, Authentication & Authorization Guide, Infrastructure Security Standards, Error Handling Guide

---

# 1. Amaç

Bu dokümanın amacı, Antrenova platformunda geliştirilecek tüm yazılımların güvenlik odaklı geliştirilmesini sağlamak, güvenlik açıklarını daha kod yazım aşamasında önlemek ve güvenli yazılım geliştirme kültürünü standartlaştırmaktır.

Güvenlik yalnızca altyapının veya sistem yöneticisinin sorumluluğu değildir. Her geliştirici yazdığı kodun güvenliğinden sorumludur. Güvenlik yaklaşımı tasarım aşamasından başlayarak geliştirme, test, yayın ve bakım süreçlerinin tamamına entegre edilmelidir.

Platformdaki tüm modüller bu rehbere uygun geliştirilmelidir.

---

# 2. Temel İlkeler

Güvenli yazılım geliştirme aşağıdaki prensiplere uygun olmalıdır.

- Güvenlik varsayılan olmalıdır.
- En az yetki ilkesi uygulanmalıdır.
- Veri korunmalıdır.
- Sürekli denetlenmelidir.
- Güvenlik testleri yapılmalıdır.

Sonradan eklenen güvenlik yeterli değildir.

---

# 3. Kimlik Doğrulama

Korunan tüm işlemler kimlik doğrulaması gerektirmelidir.

Kontroller.

- Geçerli oturum
- Token doğrulama
- Süre kontrolü
- Güvenli çıkış

Kimliği doğrulanmamış kullanıcı işlem yapamamalıdır.

---

# 4. Yetkilendirme

Her işlem için yetki doğrulanmalıdır.

Kontrol edilmesi gerekenler.

- Rol
- İşletme
- Şube
- Kaynak erişimi
- İşlem yetkisi

Authentication tek başına yeterli değildir.

---

# 5. Girdi Doğrulama

Sisteme gelen tüm veriler doğrulanmalıdır.

Örneğin.

- Tip kontrolü
- Uzunluk
- Format
- İş kuralları

Hiçbir istemci verisine doğrudan güvenilmemelidir.

---

# 6. Veri Koruma

Hassas bilgiler korunmalıdır.

Örneğin.

- Şifreler
- Token'lar
- API anahtarları
- Kişisel bilgiler

Gizli bilgiler kaynak kodunda bulunmamalıdır.

---

# 7. SQL Injection Koruması

Veritabanı sorguları güvenli oluşturulmalıdır.

Kurallar.

- Parametreli sorgular kullanılmalıdır.
- String birleştirme yapılmamalıdır.
- ORM güvenli kullanılmalıdır.

Dinamik SQL dikkatli yönetilmelidir.

---

# 8. XSS ve CSRF

Web güvenliği temel kontrolleri uygulanmalıdır.

Örneğin.

- Çıktı kodlama
- Input temizleme
- Güvenli Cookie kullanımı
- CSRF koruması

Tarayıcı güvenliği ihmal edilmemelidir.

---

# 9. Log Güvenliği

Log kayıtlarında hassas bilgiler yer almamalıdır.

Loglanmaması gereken örnekler.

- Parola
- Token
- Kart bilgileri
- Secret değerleri

Loglar yalnızca gerekli teknik bilgileri içermelidir.

---

# 10. API Güvenliği

API geliştirilirken aşağıdaki kontroller uygulanmalıdır.

- HTTPS
- Authentication
- Authorization
- Validation
- Rate Limit

Her endpoint güvenlik açısından bağımsız değerlendirilmelidir.

---

# 11. Üçüncü Taraf Servisler

Harici servislerle güvenli iletişim kurulmalıdır.

Kurallar.

- Secret yönetimi
- Timeout
- Retry
- Sertifika doğrulaması

Harici servisler güvenilir kabul edilmemelidir.

---

# 12. Güvenlik Testleri

Her kritik modül güvenlik açısından test edilmelidir.

Kontrol alanları.

- Yetkilendirme
- Girdi doğrulama
- SQL Injection
- XSS
- Kimlik doğrulama

Güvenlik testleri düzenli tekrarlanmalıdır.

---

# 13. Kod İnceleme

Review sırasında güvenlik kontrolleri yapılmalıdır.

Kontrol alanları.

- Secret sızıntısı
- Yetki eksikleri
- Validation
- Güvenli sorgular
- Log içerikleri

Güvenlik Code Review sürecinin zorunlu parçasıdır.

---

# 14. Sürekli İyileştirme

Güvenlik süreçleri düzenli olarak değerlendirilmelidir.

İyileştirilebilecek alanlar.

- Yeni tehditler
- Güvenlik testleri
- Kod analizi
- Eğitim
- Politika güncellemeleri

Güvenlik yaşayan bir süreç olarak ele alınmalıdır.

---

# 15. Genel Kurallar

Secure Development Guide, Antrenova platformunda güvenlik odaklı yazılım geliştirme kültürünü oluşturan temel rehberdir. Kimlik doğrulama, yetkilendirme, veri doğrulama, güvenli API geliştirme ve hassas veri koruma kuralları eksiksiz uygulanmalı; tüm geliştirmeler güvenlik açısından düzenli olarak test edilmeli ve denetlenmelidir.

Bu yaklaşım sayesinde platform siber tehditlere karşı daha dayanıklı hale gelir, kullanıcı verileri korunur, güvenlik açıkları erken tespit edilir ve Antrenova uzun vadede kurumsal güvenlik standartlarına uygun bir yazılım platformu olarak gelişimini sürdürür.
