# 08. State Yönetimi Standartları (State Management)

> **Doküman Kodu:** DEV-08  
> **Dosya Adı:** `08_STATE_MANAGEMENT.md`  
> **Versiyon:** 1.0  
> **Durum:** Onaylandı  
> **Bağımlı Dokümanlar:** React Component Guide, Next.js Standards, Software Architecture, API Standards

---

# 1. Amaç

Bu dokümanın amacı, Antrenova projesinde istemci tarafı durum (State) yönetiminin standartlarını belirlemek, gereksiz karmaşıklığı önlemek ve uygulamanın büyümesiyle birlikte yönetilebilir bir veri akışı sağlamaktır.

State yönetimi yalnızca veriyi saklamak değildir. Verinin yaşam döngüsü, güncellenme şekli, paylaşımı, önbelleğe alınması ve kullanıcı arayüzü ile senkronizasyonu da bu sürecin bir parçasıdır.

Platformdaki tüm istemci tarafı veri yönetimi bu standartlara uygun yapılmalıdır.

---

# 2. Temel İlkeler

State yönetimi aşağıdaki prensiplere uygun olmalıdır.

- Gerektiği kadar kullanılmalıdır.
- Basit tutulmalıdır.
- Tek doğruluk kaynağı olmalıdır.
- Tahmin edilebilir olmalıdır.
- Test edilebilir olmalıdır.

State yalnızca gerçekten ihtiyaç varsa oluşturulmalıdır.

---

# 3. State Türleri

Platformda aşağıdaki State türleri kullanılmalıdır.

- Local State
- Shared State
- Server State
- UI State
- Session State

Her veri doğru kategoride yönetilmelidir.

---

# 4. Local State

Yalnızca ilgili bileşeni ilgilendiren veriler Local State olmalıdır.

Örneğin.

- Modal açık mı?
- Input değeri
- Seçili sekme
- Filtre paneli

Bu veriler global taşınmamalıdır.

---

# 5. Shared State

Birden fazla bileşenin kullandığı veriler Shared State olabilir.

Örneğin.

- Kullanıcı bilgisi
- Yetkiler
- Tema
- Dil seçimi

Gereksiz Global State oluşturulmamalıdır.

---

# 6. Server State

Sunucudan gelen veriler istemci tarafında kopyalanmamalıdır.

Kurallar.

- Güncel veri korunmalıdır.
- Gerektiğinde yeniden alınmalıdır.
- Cache stratejileri kullanılmalıdır.

Server State ile UI State karıştırılmamalıdır.

---

# 7. State Güncelleme

State değişiklikleri kontrollü yapılmalıdır.

Kurallar.

- Immutable yaklaşım kullanılmalıdır.
- Yan etkiler ayrıştırılmalıdır.
- Gereksiz yeniden render engellenmelidir.

Doğrudan veri mutasyonu yapılmamalıdır.

---

# 8. Derived State

Başka verilerden hesaplanabilen bilgiler State olarak tutulmamalıdır.

Örneğin.

- Toplam tutar
- Filtrelenmiş liste
- Sayfa sayısı

Bu değerler gerektiğinde hesaplanmalıdır.

---

# 9. Form State

Form verileri yalnızca form süresince tutulmalıdır.

Kurallar.

- Validation desteklenmelidir.
- Submit sonrası temizlenmelidir.
- Gereksiz Global State kullanılmamalıdır.

Her form bağımsız yönetilmelidir.

---

# 10. Senkronizasyon

State ile kullanıcı arayüzü her zaman uyumlu olmalıdır.

Kontrol edilmesi gerekenler.

- Güncel veri
- Yüklenme durumu
- Hata durumu
- Boş veri

Tutarsız ekran gösterilmemelidir.

---

# 11. Performans

State değişiklikleri performansı olumsuz etkilememelidir.

Örneğin.

- Gereksiz render
- Büyük State objeleri
- Derin güncellemeler

Minimum değişiklik prensibi uygulanmalıdır.

---

# 12. Kod Organizasyonu

State yönetimi bileşenlerden ayrılmalıdır.

Tercih edilen yapılar.

- Custom Hooks
- Context
- State Store
- Services

Kod tekrarından kaçınılmalıdır.

---

# 13. Kod İnceleme

State yönetimi aşağıdaki kriterlerle değerlendirilmelidir.

- Gereksiz State var mı?
- Derived State doğru kullanılmış mı?
- Performans uygun mu?
- Immutable yapı korunmuş mu?

Kod incelemesinde veri akışı mutlaka kontrol edilmelidir.

---

# 14. Sürekli İyileştirme

State yönetimi düzenli analiz edilmelidir.

İyileştirilebilecek alanlar.

- Render sayısı
- State boyutu
- Veri akışı
- Kod tekrarları
- Performans

Yeni ihtiyaçlara göre yapı sadeleştirilmelidir.

---

# 15. Genel Kurallar

State Management standartları, Antrenova istemci tarafı veri yönetiminin düzenli, öngörülebilir ve sürdürülebilir olmasını sağlayan temel geliştirme kurallarını tanımlar. Veriler doğru State kategorisinde yönetilmeli, gereksiz Global State oluşturulmamalı, Immutable yaklaşımı korunmalı ve kullanıcı arayüzü ile veri her zaman senkronize tutulmalıdır.

Bu yaklaşım sayesinde uygulama büyüdükçe veri yönetimi karmaşık hale gelmez, performans korunur, bakım kolaylaşır ve geliştiriciler ortak bir State yönetim modeliyle çalışabilir.
