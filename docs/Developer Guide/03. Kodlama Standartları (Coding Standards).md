# 03. Kodlama Standartları (Coding Standards)

> **Doküman Kodu:** DEV-03  
> **Dosya Adı:** `03_CODING_STANDARDS.md`  
> **Versiyon:** 1.0  
> **Durum:** Onaylandı  
> **Bağımlı Dokümanlar:** Software Architecture, Project Structure, TypeScript Guidelines, Code Review Guide

---

# 1. Amaç

Bu dokümanın amacı, Antrenova projesinde yazılacak tüm kaynak kodların ortak kalite standartlarına uygun olmasını sağlamak, okunabilirliği artırmak ve uzun vadede bakım maliyetini düşürmektir.

Kodlama standartları yalnızca biçimlendirme kurallarını değil; okunabilirlik, sürdürülebilirlik, modülerlik, performans ve güvenlik prensiplerini de kapsar. Aynı problemi çözen kodlar, farklı geliştiriciler tarafından yazılmış olsa bile benzer kalite seviyesinde olmalıdır.

Projedeki tüm kaynak kodlar bu standartlara uygun geliştirilmelidir.

---

# 2. Temel İlkeler

Kod aşağıdaki prensiplere uygun olmalıdır.

- Okunabilir olmalıdır.
- Basit olmalıdır.
- Modüler olmalıdır.
- Test edilebilir olmalıdır.
- Tek sorumluluk ilkesine uygun olmalıdır.

Karmaşık kod yerine anlaşılır kod tercih edilmelidir.

---

# 3. Okunabilirlik

Kod ilk bakışta anlaşılabilir olmalıdır.

Kurallar.

- Anlamlı isimler kullanılmalıdır.
- Gereksiz kısaltmalardan kaçınılmalıdır.
- Mantıksal bloklar ayrılmalıdır.
- Girinti düzeni korunmalıdır.

Kod açıklamaya ihtiyaç duyuyorsa yeniden tasarlanması değerlendirilmelidir.

---

# 4. Fonksiyon Yapısı

Fonksiyonlar tek bir işi yapmalıdır.

Kurallar.

- Kısa olmalıdır.
- Tek sorumluluğa sahip olmalıdır.
- Yan etkileri minimum olmalıdır.
- Gerektiğinde yeniden kullanılabilir olmalıdır.

Büyük fonksiyonlar daha küçük parçalara bölünmelidir.

---

# 5. Kod Tekrarı

Aynı mantık birden fazla yerde yazılmamalıdır.

Tekrar eden kodlar.

- Utility fonksiyonlarına,
- Ortak servislere,
- Paylaşılan bileşenlere

taşınmalıdır.

DRY (Don't Repeat Yourself) prensibi uygulanmalıdır.

---

# 6. Magic Number ve Magic String

Kod içerisinde açıklamasız sabit değerler kullanılmamalıdır.

Örneğin.

- Enum
- Constant
- Configuration

kullanımı tercih edilmelidir.

Sabit değerlerin anlamı açık olmalıdır.

---

# 7. Yorum Satırları

Yorum satırları yalnızca gerekli durumlarda kullanılmalıdır.

Yorumlar.

- Karmaşık iş kurallarını,
- Geçici çözümleri,
- Önemli teknik kararları

açıklamak için kullanılmalıdır.

Kodun ne yaptığı değil, neden yapıldığı açıklanmalıdır.

---

# 8. Hata Yönetimi

Beklenen tüm hata durumları ele alınmalıdır.

Kurallar.

- Sessiz hata oluşmamalıdır.
- Kullanıcı dostu mesajlar kullanılmalıdır.
- Teknik detaylar loglanmalıdır.

Hatalar göz ardı edilmemelidir.

---

# 9. Performans

Kod yazılırken performans dikkate alınmalıdır.

Örneğin.

- Gereksiz döngülerden kaçınılmalıdır.
- Gereksiz sorgular yazılmamalıdır.
- Büyük işlemler parçalanmalıdır.

Erken optimizasyon yerine ölçülebilir optimizasyon tercih edilmelidir.

---

# 10. Güvenlik

Kod güvenlik prensiplerine uygun yazılmalıdır.

Kontrol alanları.

- Yetki doğrulama
- Girdi doğrulama
- SQL Injection
- XSS
- CSRF

Her geliştirici güvenlikten sorumludur.

---

# 11. Kod Tutarlılığı

Projedeki benzer problemler benzer şekilde çözülmelidir.

Kurallar.

- Aynı isimlendirme
- Aynı klasör yapısı
- Aynı hata yönetimi
- Aynı tasarım yaklaşımı

Tutarlılık bakım maliyetini azaltır.

---

# 12. Refactoring

Kod düzenli olarak iyileştirilmelidir.

Refactoring sırasında.

- Davranış değişmemelidir.
- Testler korunmalıdır.
- Kod okunabilirliği artırılmalıdır.

Refactoring yeni özellik geliştirmek değildir.

---

# 13. Dokümantasyon

Kritik kodlar gerektiğinde belgelenmelidir.

Örneğin.

- Mimari kararlar
- Algoritmalar
- Karmaşık iş kuralları

Kod ile doküman uyumlu olmalıdır.

---

# 14. Sürekli İyileştirme

Kodlama standartları düzenli olarak gözden geçirilmelidir.

İyileştirilebilecek alanlar.

- Okunabilirlik
- Performans
- Güvenlik
- Test edilebilirlik
- Kod tekrarının azaltılması

Yeni standartlar ekip kararıyla uygulanmalıdır.

---

# 15. Genel Kurallar

Coding Standards, Antrenova projesinde geliştirilen tüm kaynak kodların ortak kalite seviyesinde olmasını sağlayan temel geliştirme kurallarını tanımlar. Kod okunabilir, modüler, güvenli, test edilebilir ve sürdürülebilir şekilde yazılmalı; gereksiz karmaşıklıktan kaçınılmalı ve proje genelinde tutarlı bir geliştirme yaklaşımı korunmalıdır.

Bu sayede kod tabanı büyüse bile anlaşılabilirliğini kaybetmez, yeni geliştiriciler projeye kolay adapte olur ve uzun vadeli bakım süreçleri önemli ölçüde kolaylaşır.
