# 14. Test Geliştirme Rehberi (Testing Guide)

> **Doküman Kodu:** DEV-14  
> **Dosya Adı:** `14_TESTING_GUIDE.md`  
> **Versiyon:** 1.0  
> **Durum:** Onaylandı  
> **Bağımlı Dokümanlar:** Coding Standards, API Standards, Workflow Standards, Deployment & DevOps Standards

---

# 1. Amaç

Bu dokümanın amacı, Antrenova platformunda geliştirilen tüm kodların planlı, tekrarlanabilir ve güvenilir test süreçlerinden geçirilmesini sağlayacak standartları belirlemektir.

Test süreçleri yalnızca hataları bulmak için değil; mevcut davranışın korunmasını sağlamak, yeni geliştirmelerin yan etkilerini önlemek ve yayın kalitesini artırmak için uygulanmalıdır.

Platformdaki tüm kritik geliştirmeler bu rehbere uygun test edilmelidir.

---

# 2. Temel İlkeler

Test süreçleri aşağıdaki prensiplere uygun olmalıdır.

- Tekrarlanabilir olmalıdır.
- Otomatikleştirilebilir olmalıdır.
- Bağımsız çalışmalıdır.
- Anlaşılır olmalıdır.
- Güvenilir sonuç üretmelidir.

Testler gerçek kullanım senaryolarını yansıtmalıdır.

---

# 3. Test Piramidi

Platform aşağıdaki test yaklaşımını benimsemelidir.

```text
E2E Testleri
↑

Integration Testleri
↑

Unit Testleri
```

Unit testler en geniş kapsama sahip olmalıdır.

---

# 4. Unit Test

Tek bir fonksiyon veya bileşenin doğru çalışması doğrulanmalıdır.

Örneğin.

- Utility fonksiyonları
- Validator'lar
- Hesaplama işlemleri
- Hook'lar

Her test yalnızca tek davranışı doğrulamalıdır.

---

# 5. Integration Test

Birden fazla bileşenin birlikte çalışması test edilmelidir.

Örneğin.

- API ve veritabanı
- Servis ve Repository
- Authentication akışı

Modüller arası uyumluluk kontrol edilmelidir.

---

# 6. End-to-End Test

Kullanıcının gerçekleştirdiği tam senaryolar test edilmelidir.

Örneğin.

- Giriş yapma
- Üye oluşturma
- Paket satışı
- Rezervasyon oluşturma
- Ödeme alma

Gerçek kullanıcı akışları doğrulanmalıdır.

---

# 7. Test Verileri

Testlerde kullanılan veriler kontrollü olmalıdır.

Kurallar.

- Üretim verisi kullanılmamalıdır.
- Tekrar üretilebilir olmalıdır.
- Birbirinden bağımsız olmalıdır.

Test ortamı her çalıştırmada aynı sonucu vermelidir.

---

# 8. Mock Kullanımı

Harici bağımlılıklar gerektiğinde Mock edilmelidir.

Örneğin.

- WhatsApp API
- SMTP
- SMS
- Ödeme servisleri

Gerçek servisler sürekli kullanılmamalıdır.

---

# 9. Performans Testleri

Yoğun kullanım senaryoları düzenli test edilmelidir.

Kontrol alanları.

- API yükü
- Veritabanı sorguları
- Çoklu kullanıcı
- Büyük veri setleri

Performans darboğazları erken tespit edilmelidir.

---

# 10. Güvenlik Testleri

Temel güvenlik kontrolleri test edilmelidir.

Örneğin.

- Yetkilendirme
- Kimlik doğrulama
- Girdi doğrulama
- SQL Injection
- XSS

Güvenlik testleri ihmal edilmemelidir.

---

# 11. CI Süreci

Otomatik testler Continuous Integration sürecinin parçası olmalıdır.

Kod birleştirilmeden önce.

- Testler çalışmalıdır.
- Başarısız testler engel oluşturmalıdır.
- Sonuçlar raporlanmalıdır.

Başarısız testlerle yayın yapılmamalıdır.

---

# 12. Kod Kapsamı

Test kapsamı düzenli takip edilmelidir.

Öncelik verilmesi gereken alanlar.

- İş kuralları
- Finans işlemleri
- Yetkilendirme
- Rezervasyon sistemi

Kapsam tek başına kalite göstergesi değildir.

---

# 13. Kod İnceleme

Test kodları da Review sürecinden geçmelidir.

Kontrol alanları.

- Anlaşılabilirlik
- Tek davranış testi
- Mock kullanımı
- Gereksiz tekrar

Test kodları da üretim kodu kadar önemlidir.

---

# 14. Sürekli İyileştirme

Test süreçleri düzenli analiz edilmelidir.

İyileştirilebilecek alanlar.

- Test süresi
- Başarı oranı
- Otomasyon
- Kapsam
- Performans

Yeni modüller test stratejisine dahil edilmelidir.

---

# 15. Genel Kurallar

Testing Guide, Antrenova platformunda geliştirilen tüm kodların güvenilir ve sürdürülebilir şekilde doğrulanmasını sağlayan temel geliştirme rehberidir. Unit, Integration ve End-to-End testleri birlikte uygulanmalı, kritik iş akışları otomatik olarak doğrulanmalı ve test süreçleri CI altyapısının ayrılmaz bir parçası olmalıdır.

Bu yaklaşım sayesinde hatalar erken tespit edilir, yayın kalitesi artar, regresyon riski azalır ve platform büyüdükçe güvenilir yazılım geliştirme kültürü korunur.
