# 07. API ARCHITECTURE

## Amaç

Bu doküman, Antrenova platformunda kullanılacak API (Application Programming Interface) mimarisini, standartlarını ve geliştirme kurallarını tanımlar.

API katmanı; web uygulaması, mobil uygulama, gelecekte geliştirilecek masaüstü istemcileri ve üçüncü taraf sistemler arasında güvenli, tutarlı ve ölçeklenebilir veri iletişimini sağlayan merkezi bileşendir.

Bu belge, geliştirilecek tüm API'ler için zorunlu standartları belirler.

---

# Mimari Felsefesi

API yapısı;

- REST tabanlı,
- tutarlı,
- güvenli,
- versiyonlanabilir,
- ölçeklenebilir,
- dokümante edilmiş

olmalıdır.

Her endpoint aynı geliştirme standartlarını takip etmelidir.

---

# API Katmanı

API, kullanıcı arayüzü ile iş kuralları arasında köprü görevi görür.

Standart veri akışı:

```text
Client

↓

API

↓

Application Service

↓

Domain

↓

Repository

↓

Database
```

API katmanında iş kuralları bulunmamalıdır.

---

# Endpoint Yapısı

Endpoint isimleri açık ve tahmin edilebilir olmalıdır.

Örnekler:

```text
/api/members
/api/trainers
/api/packages
/api/finance
/api/attendance
/api/appointments
/api/reports
```

İsimlendirme çoğul (plural) yapıda kullanılmalıdır.

---

# HTTP Metotları

Standart kullanım:

- GET → Veri Oku
- POST → Yeni Kayıt
- PUT → Tam Güncelleme
- PATCH → Kısmi Güncelleme
- DELETE → Soft Delete

HTTP standartları değiştirilmemelidir.

---

# Yanıt Formatı

Tüm API'ler ortak yanıt yapısını kullanmalıdır.

Başarılı örnek:

```json
{
  "success": true,
  "data": {},
  "message": "İşlem başarılı."
}
```

Hatalı örnek:

```json
{
  "success": false,
  "message": "Geçersiz istek.",
  "errors": []
}
```

Yanıt formatı tüm sistemde aynı olmalıdır.

---

# Kimlik Doğrulama

Korunan tüm endpoint'ler Authentication kontrolünden geçmelidir.

Anonim erişime yalnızca açık olarak izin verilen endpoint'ler cevap verebilir.

Kimlik doğrulama sunucu tarafında yapılmalıdır.

---

# Yetkilendirme

Her API isteğinde aşağıdaki kontroller uygulanmalıdır.

- Authentication
- Authorization
- business_id
- branch_id
- Permission

Bu kontroller istemci tarafına bırakılamaz.

---

# Veri Doğrulama

API'ye gelen tüm veriler doğrulanmalıdır.

Doğrulama kuralları merkezi şema yapısı üzerinden yönetilmelidir.

Geçersiz veri hiçbir zaman Domain katmanına ulaşmamalıdır.

---

# Pagination

Liste döndüren endpoint'ler sayfalamayı desteklemelidir.

Örneğin:

```text
?page=1
&pageSize=25
```

Çok büyük veri kümeleri tek istekte döndürülmemelidir.

---

# Filtreleme

API standart filtreleme yapısını desteklemelidir.

Örnek parametreler:

```text
status
branch
trainer
member
startDate
endDate
search
```

Filtreleme performanslı çalışmalıdır.

---

# Sıralama

Tüm liste endpoint'leri sıralama desteği sunmalıdır.

Örneğin:

```text
sort=name
order=asc
```

Varsayılan sıralama modüle göre belirlenmelidir.

---

# Versiyonlama

API gelecekte sürümlendirilebilir olmalıdır.

Örneğin:

```text
/api/v1/
/api/v2/
```

Yeni sürümler eski istemcileri bozmamalıdır.

---

# Hata Yönetimi

API teknik hata mesajlarını istemciye göndermemelidir.

Kullanıcı dostu açıklamalar kullanılmalıdır.

Sunucu loglarında ise ayrıntılı hata bilgileri saklanmalıdır.

---

# Audit Uyumluluğu

Aşağıdaki işlemler Audit Log sistemine yazılmalıdır.

- Oluşturma
- Güncelleme
- Silme
- Toplu İşlem
- Kritik Veri Görüntüleme

API katmanı denetlenebilir olmalıdır.

---

# Performans

API aşağıdaki prensiplere uygun geliştirilmelidir.

- Gereksiz veri döndürülmemeli
- Lazy Loading kullanılmalı
- Sayfalama zorunlu olmalı
- Büyük sorgular optimize edilmeli
- Cache kullanılabilecek endpoint'ler belirlenmeli

Performans mimarinin temel parçasıdır.

---

# Güvenlik

API güvenlik standartları:

- HTTPS zorunlu
- Parametrik sorgular
- Rate Limiting
- Input Validation
- SQL Injection koruması
- XSS koruması
- CSRF politikaları (gerektiğinde)

Hiçbir endpoint güvenlik kontrollerini atlayamaz.

---

# Entegrasyon Uyumluluğu

API katmanı aşağıdaki sistemlerle uyumlu çalışmalıdır.

- Web Uygulaması
- Mobil Uygulama
- Dashboard
- Notification Engine
- CRM
- WhatsApp
- Harici Servisler

Tüm istemciler aynı API standartlarını kullanmalıdır.

---

# Ölçeklenebilirlik

İlerleyen sürümlerde API aşağıdaki ihtiyaçları destekleyebilmelidir.

- Public API
- Partner API
- Webhook Sistemi
- GraphQL Katmanı (gerektiğinde)
- Enterprise Entegrasyonları

Mevcut mimari bozulmadan genişleyebilmelidir.

---

# Değiştirilemez Kurallar

Aşağıdaki kurallar tüm API geliştirmeleri için zorunludur.

- Ortak yanıt formatı kullanılacaktır.
- Authentication zorunludur.
- Authorization zorunludur.
- business_id doğrulaması yapılacaktır.
- Input Validation uygulanacaktır.
- Soft Delete mantığı korunacaktır.
- Audit Log desteği sağlanacaktır.

---

# Sonuç

API Architecture, Antrenova'nın tüm istemcileri ile sunucu arasındaki iletişimin temelini oluşturur. Tutarlı endpoint yapısı, ortak yanıt formatı, güçlü güvenlik kontrolleri ve ölçeklenebilir tasarımı sayesinde platform; web, mobil ve gelecekteki tüm entegrasyonlar için güvenilir ve sürdürülebilir bir API altyapısı sunar.
