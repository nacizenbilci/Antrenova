# 09. FRONTEND ARCHITECTURE

## Amaç

Bu doküman, Antrenova platformunun Frontend (Ön Yüz) mimarisini, geliştirme standartlarını ve kullanıcı arayüzü katmanının sorumluluklarını tanımlar.

Frontend yalnızca ekranların oluşturulduğu katman değildir. Kullanıcı deneyimini yöneten, API ile iletişim kuran, istemci tarafı durum yönetimini sağlayan ve performanslı bir kullanım sunan temel uygulama katmanıdır.

Bu belge, geliştirilecek tüm frontend kodları için ortak standartları belirler.

---

# Mimari Felsefesi

Frontend;

- modüler,
- yeniden kullanılabilir,
- okunabilir,
- test edilebilir,
- performanslı,
- erişilebilir

olmalıdır.

Her ekran aynı geliştirme standartlarını takip etmelidir.

---

# Teknoloji Altyapısı

Antrenova'nın frontend katmanı aşağıdaki teknolojiler üzerine kurulacaktır.

- Next.js (App Router)
- React
- TypeScript
- Tailwind CSS
- shadcn/ui
- TanStack Query (React Query)
- React Hook Form
- Zod

Yeni kütüphaneler eklenmeden önce mimari uyumluluğu değerlendirilmelidir.

---

# Katman Yapısı

Frontend aşağıdaki sorumluluklara ayrılmalıdır.

- UI Components
- Feature Components
- Pages
- Hooks
- Services
- State Management
- Validation

Katmanlar birbirinin görevini üstlenmemelidir.

---

# Component Mimarisi

Bileşenler iki ana gruba ayrılmalıdır.

### Ortak Bileşenler

Tekrar kullanılabilir.

Örneğin;

- Button
- Card
- Table
- Dialog
- Badge
- Avatar
- Input

### Feature Bileşenleri

Belirli modüle özeldir.

Örneğin;

- MemberCard
- TrainerProfile
- FinanceSummary
- AttendanceTable

Feature bileşenleri başka modüllere bağımlı olmamalıdır.

---

# Sayfa Yapısı

Her sayfa aşağıdaki standart bölümleri içermelidir.

- Page Header
- Toolbar
- İçerik
- Sağ Panel (gerekiyorsa)
- Modal Yapıları

Tüm ekranlarda aynı düzen korunmalıdır.

---

# State Management

Durum yönetimi mümkün olduğunca sade tutulmalıdır.

Temel prensip:

- Sunucu verileri → TanStack Query
- Form verileri → React Hook Form
- Yerel durum → React State

Global state yalnızca gerçekten gerekli olduğunda kullanılmalıdır.

---

# Veri Yönetimi

Frontend doğrudan veritabanı mantığını bilmemelidir.

Veriler yalnızca API veya güvenli servis katmanı üzerinden alınmalıdır.

İş kuralları frontend tarafına taşınmamalıdır.

---

# Form Yönetimi

Tüm formlar aşağıdaki standartları kullanmalıdır.

- React Hook Form
- Zod Validation

Doğrulama mesajları kullanıcı dostu olmalıdır.

Her form aynı davranışı göstermelidir.

---

# Yüklenme Durumları

Her veri yüklenirken kullanıcı bilgilendirilmelidir.

Tercih edilen yöntemler:

- Skeleton Screen
- Loading Spinner
- Progress Indicator

Boş beyaz ekran gösterilmemelidir.

---

# Hata Yönetimi

Frontend aşağıdaki hata türlerini ayırt etmelidir.

- Doğrulama Hataları
- Yetki Hataları
- Ağ Hataları
- Sunucu Hataları

Her hata kullanıcıya anlaşılır şekilde açıklanmalıdır.

---

# Bildirimler

İşlem sonuçları standart bildirim sistemiyle gösterilmelidir.

Örneğin;

- Başarılı
- Bilgilendirme
- Uyarı
- Hata

Bildirim dili platform genelinde aynı olmalıdır.

---

# Performans

Frontend aşağıdaki performans kurallarına uymalıdır.

- Lazy Loading
- Dynamic Import
- Image Optimization
- Route Splitting
- Memoization (gerektiğinde)
- Gereksiz Render'dan Kaçınma

Kullanıcı deneyimi her zaman ön planda tutulmalıdır.

---

# Responsive Tasarım

Her ekran aşağıdaki cihazlarda sorunsuz çalışmalıdır.

- Masaüstü
- Dizüstü
- Tablet
- Mobil

Responsive tasarım sonradan eklenen özellik değildir.

---

# Erişilebilirlik

Frontend aşağıdaki erişilebilirlik kurallarını desteklemelidir.

- Klavye Navigasyonu
- Screen Reader Uyumluluğu
- Yeterli Kontrast
- Doğru HTML Semantik Yapısı
- ARIA Etiketleri (gerektiğinde)

WCAG standartları dikkate alınmalıdır.

---

# Güvenlik

Frontend aşağıdaki güvenlik kurallarına uymalıdır.

- Hassas veriler LocalStorage'da tutulmamalıdır.
- JWT veya oturum bilgileri güvenli şekilde yönetilmelidir.
- XSS korumaları uygulanmalıdır.
- Yetki kontrolleri yalnızca istemci tarafına bırakılmamalıdır.

Frontend güvenliği, backend güvenliğinin yerine geçmez.

---

# Kod Standartları

Frontend geliştiricileri aşağıdaki standartlara uymalıdır.

- TypeScript zorunlu
- ESLint kullanılmalı
- Prettier kullanılmalı
- Component isimleri tutarlı olmalı
- Gereksiz yorum satırlarından kaçınılmalı
- Kod okunabilir olmalı

---

# Ölçeklenebilirlik

Yeni modüller;

- mevcut component yapısını bozmadan,
- ortak tasarım sistemini kullanarak,
- tekrar eden kod üretmeden

geliştirilebilmelidir.

Frontend mimarisi büyüdükçe karmaşıklaşmamalıdır.

---

# Değiştirilemez Kurallar

Aşağıdaki kurallar tüm frontend geliştirmeleri için zorunludur.

- TypeScript kullanılacaktır.
- Ortak UI bileşenleri tekrar yazılmayacaktır.
- API dışındaki kaynaklardan veri alınmayacaktır.
- İş kuralları frontend katmanında tutulmayacaktır.
- Responsive tasarım zorunludur.
- Erişilebilirlik standartları gözetilecektir.

---

# Sonuç

Frontend Architecture, Antrenova'nın kullanıcı deneyiminin teknik temelini oluşturur. Next.js, React ve TypeScript üzerine kurulan bu mimari; modüler component yapısı, güçlü durum yönetimi, yüksek performans ve erişilebilirlik standartları sayesinde uzun yıllar boyunca sürdürülebilir ve geliştirilebilir bir ön yüz altyapısı sağlar.
