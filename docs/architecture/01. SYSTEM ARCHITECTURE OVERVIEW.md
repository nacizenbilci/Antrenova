# 01. SYSTEM ARCHITECTURE OVERVIEW

## Amaç

Bu doküman, Antrenova platformunun genel yazılım mimarisini, katmanlarını, temel prensiplerini ve tüm sistem bileşenleri arasındaki ilişkiyi tanımlar.

Bu belge Software Architecture serisinin temel referans dokümanıdır. Sonraki tüm mimari kararları bu belgeyle uyumlu olmak zorundadır.

---

# Mimari Felsefesi

Antrenova;

- ölçeklenebilir,
- modüler,
- güvenli,
- yüksek performanslı,
- bakım yapılabilir,
- test edilebilir

bir mimari üzerine inşa edilir.

Sistem yalnızca bugünkü ihtiyaçları değil, önümüzdeki 10 yıllık büyüme hedefini de desteklemelidir.

---

# Temel Mimari Yaklaşım

Antrenova;

**Modüler Monolith (Modüler Monolit)** mimarisi ile geliştirilecektir.

İlk sürümlerde;

- tek kod tabanı,
- tek veritabanı,
- tek dağıtım

kullanılır.

Ancak tüm modüller birbirinden bağımsız geliştirilecek şekilde tasarlanacaktır.

İlerleyen yıllarda ihtiyaç duyulursa belirli modüller Microservice mimarisine ayrılabilecek şekilde tasarlanmalıdır.

---

# Temel Katmanlar

Sistem aşağıdaki katmanlardan oluşur.

## Presentation Layer

Kullanıcı arayüzü.

- Web
- Mobil
- Yönetim Paneli

Görevi yalnızca kullanıcı etkileşimidir.

İş kuralları burada bulunmaz.

---

## Application Layer

Uygulama servisleri.

Bu katmanda;

- iş akışları,
- servis koordinasyonu,
- transaction yönetimi

bulunur.

---

## Domain Layer

Sistemin kalbidir.

Burada;

- Business Rules
- Domain Models
- Validation Rules
- Domain Services

yer alır.

İş kuralları yalnızca bu katmanda bulunmalıdır.

---

## Infrastructure Layer

Teknik servisler.

Örneğin;

- Supabase
- Storage
- Cache
- Queue
- Mail
- WhatsApp
- SMS
- Logging

Bu katman gerektiğinde değiştirilebilir olmalıdır.

---

# Modül Yapısı

Her modül bağımsız geliştirilmelidir.

Örneğin;

- Members
- Trainers
- Packages
- Attendance
- Finance
- CRM
- Reports
- Notifications

Hiçbir modül başka bir modülün iç yapısını doğrudan kullanmamalıdır.

İletişim servisler üzerinden yapılmalıdır.

---

# Multi-Tenant

Antrenova'nın değiştirilemez temel mimari kararı:

**Sistem tamamen Multi-Tenant çalışacaktır.**

Her kayıt;

- business_id

ile ilişkilidir.

Gerekli durumlarda;

- branch_id

da kullanılacaktır.

Tenant izolasyonu hiçbir koşulda bozulamaz.

---

Standart veri akışı şu şekilde olmalıdır.

```
UI

↓

Application Service

↓

Domain

↓

Repository

↓

Database

↓

Repository

↓

Domain

↓

Application

↓

UI
```

Katman atlanamaz.

---

# Bağımlılık Kuralları

Katmanlar yalnızca aşağı doğru bağımlılık oluşturabilir.

Örneğin;

Presentation

↓

Application

↓

Domain

↓

Infrastructure

ters bağımlılık oluşturulmamalıdır.

---

# Güvenlik

Her işlem;

- Authentication
- Authorization
- Validation
- Audit Log

katmanlarından geçmelidir.

Güvenlik yalnızca kullanıcı arayüzünde sağlanamaz.

---

# Performans

Sistem aşağıdaki hedefleri sağlamalıdır.

- Hızlı açılış
- Minimum sorgu
- Lazy Loading
- Pagination
- Cache
- Queue

Performans sonradan eklenen özellik değil, mimarinin parçasıdır.

---

# Genişleyebilirlik

Yeni modül eklemek;

- mevcut kodu değiştirmeden,

mümkün olmalıdır.

Yeni spor branşları, yeni cihazlar veya yeni servisler mevcut yapıyı bozmadan sisteme eklenebilmelidir.

---

# Kod Standartları

Tüm geliştiriciler aynı mimariyi kullanmalıdır.

Hiçbir modül kendi klasör yapısını, veri akışını veya servis mimarisini oluşturamaz.

Bu belge tüm geliştirme ekibi için zorunlu referanstır.

---

# Sonuç

System Architecture Overview, Antrenova'nın teknik omurgasını tanımlar. Modüler yapı, Multi-Tenant mimari, katmanlı geliştirme modeli ve ölçeklenebilir tasarım sayesinde platform; küçük spor salonlarından yüzlerce şubesi bulunan kurumsal zincirlere kadar aynı yazılım mimarisi üzerinde güvenle çalışabilecek şekilde geliştirilecektir.
