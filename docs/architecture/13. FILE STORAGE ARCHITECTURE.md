# 13. FILE STORAGE ARCHITECTURE

## Amaç

Bu doküman, Antrenova platformunda dosya yönetimi, belge saklama ve medya depolama mimarisini tanımlar.

File Storage Architecture, yalnızca dosya yükleme sistemi değildir. Platform üzerinde oluşturulan tüm belgelerin, fotoğrafların, sözleşmelerin, raporların ve dijital evrakların güvenli, düzenli ve ölçeklenebilir şekilde saklanmasını sağlayan merkezi altyapıdır.

Bu belge, dosya yönetiminin teknik standartlarını belirler.

---

# Mimari Felsefesi

Dosya sistemi;

- güvenli,
- organize,
- ölçeklenebilir,
- hızlı,
- yedeklenebilir

olmalıdır.

Dosyalar hiçbir zaman rastgele klasörlerde saklanmamalıdır.

---

# Temel Altyapı

İlk sürümde dosya depolama altyapısı olarak **Supabase Storage** kullanılacaktır.

Veritabanında yalnızca dosya ile ilgili meta veriler tutulmalıdır.

Dosyanın kendisi Storage katmanında saklanmalıdır.

---

# Dosya Türleri

Antrenova aşağıdaki dosya türlerini desteklemelidir.

- Profil Fotoğrafları
- Üyelik Sözleşmeleri
- KVKK Belgeleri
- Sağlık Raporları
- Kimlik Belgeleri
- Makbuzlar
- Faturalar
- Eğitmen Sertifikaları
- Ölçüm Dosyaları
- Raporlar

Yeni belge türleri mevcut yapıyı bozmadan eklenebilmelidir.

---

# Klasör Organizasyonu

Dosyalar tenant bazlı organize edilmelidir.

Örnek yapı:

```text
business_id/

members/

member_id/

contracts/

photos/

documents/

finance/

receipts/

reports/

trainers/
```

Hiçbir işletmenin dosyası başka bir işletmeyle aynı dizinde bulunmamalıdır.

---

# Dosya Adlandırma

Dosya isimleri benzersiz olmalıdır.

Önerilen yapı:

```text
UUID + Uzantı

7f5d9c0e.pdf

1b83e8aa.jpg
```

Kullanıcının yüklediği dosya adı yalnızca bilgi amaçlı saklanabilir.

---

# Desteklenen Formatlar

İlk sürümde desteklenecek formatlar:

Belgeler:

- PDF
- DOCX
- XLSX

Görseller:

- JPG
- PNG
- WEBP

Diğer formatlar ihtiyaç doğrultusunda eklenebilir.

---

# Dosya Boyutu

Her dosya türü için maksimum boyut tanımlanmalıdır.

Örneğin;

Profil Fotoğrafı

- 10 MB

Belgeler

- 25 MB

Toplu içe aktarma

- 100 MB

Bu limitler sistem ayarlarından yönetilebilir olmalıdır.

---

# Dosya Meta Verileri

Veritabanında aşağıdaki bilgiler saklanmalıdır.

- Dosya ID
- Dosya Adı
- Orijinal Ad
- MIME Type
- Boyut
- business_id
- İlgili Kayıt ID
- Yükleyen Kullanıcı
- Oluşturulma Tarihi

Bu bilgiler arama ve denetim için kullanılacaktır.

---

# Dosya Güvenliği

Hiçbir dosya herkese açık URL ile erişilebilir olmamalıdır.

Erişim yalnızca yetkili kullanıcılar tarafından sağlanmalıdır.

İmzalı (Signed URL) erişim tercih edilmelidir.

---

# Yetkilendirme

Dosya erişimleri rol bazlı olmalıdır.

Örneğin;

Resepsiyon;

- Profil fotoğrafını görebilir.

Ancak;

- Sağlık raporunu göremeyebilir.

Hassas belgeler ek izin gerektirmelidir.

---

# Önizleme

Desteklenen dosyalar uygulama içerisinde önizlenebilmelidir.

Örneğin;

- PDF
- JPG
- PNG

Kullanıcının dosyayı indirmesi zorunlu olmamalıdır.

---

# Dosya Sürümleme

İlerleyen sürümlerde belge sürümleme desteklenebilir.

Örneğin;

Sözleşme v1

↓

Sözleşme v2

↓

Sözleşme v3

Eski sürümler gerektiğinde görüntülenebilmelidir.

---

# Soft Delete

Silinen dosyalar hemen fiziksel olarak kaldırılmamalıdır.

Önce Soft Delete uygulanmalıdır.

Belirli süre sonunda kalıcı silme gerçekleştirilebilir.

---

# Audit Log

Dosyalar üzerinde yapılan kritik işlemler kayıt altına alınmalıdır.

Örneğin;

- Dosya yüklendi
- Dosya görüntülendi
- Dosya indirildi
- Dosya silindi

Bu kayıtlar güvenlik açısından önemlidir.

---

# Performans

Storage sistemi aşağıdaki prensiplere uygun çalışmalıdır.

- CDN desteği
- Thumbnail üretimi
- Lazy Loading
- Büyük dosya optimizasyonu

Kullanıcı gereksiz veri indirmemelidir.

---

# Yedekleme

Dosyalar düzenli olarak yedeklenebilmelidir.

Yedekleme stratejisi veritabanından bağımsız planlanmalıdır.

Dosya kaybı kabul edilemez.

---

# Ölçeklenebilirlik

İlerleyen sürümlerde aşağıdaki özellikler eklenebilmelidir.

- Video Saklama
- Ses Dosyaları
- Dijital İmza
- OCR İşleme
- Virüs Taraması
- Yapay Zekâ Destekli Belge Analizi

Yeni özellikler mevcut dosya mimarisini bozmamalıdır.

---

# Değiştirilemez Kurallar

Aşağıdaki kurallar File Storage sistemi için zorunludur.

- Dosyalar Storage üzerinde saklanacaktır.
- Veritabanında yalnızca meta veriler tutulacaktır.
- business_id izolasyonu uygulanacaktır.
- Signed URL kullanılacaktır.
- Soft Delete desteklenecektir.
- Audit Log tutulacaktır.
- Yetki kontrolü zorunlu olacaktır.

---

# Sonuç

File Storage Architecture, Antrenova'nın tüm dijital belgelerini ve medya içeriklerini güvenli, düzenli ve ölçeklenebilir şekilde yöneten merkezi altyapıdır. Tenant bazlı klasör yapısı, güçlü yetkilendirme, güvenli erişim ve denetlenebilir kayıt sistemi sayesinde platform, uzun yıllar boyunca güvenilir bir belge yönetim çözümü sunacaktır.
