# 17. INTEGRATION ARCHITECTURE

## Amaç

Bu doküman, Antrenova platformunun üçüncü taraf servisler, cihazlar ve harici yazılımlarla güvenli, sürdürülebilir ve ölçeklenebilir şekilde haberleşmesini sağlayan **Entegrasyon Mimarisi**ni tanımlar.

Antrenova kapalı bir sistem değildir. Ödeme sistemleri, WhatsApp, e-posta servisleri, muhasebe yazılımları, turnike cihazları, QR sistemleri ve gelecekte eklenecek yüzlerce farklı servis ile iletişim kurabilecek şekilde tasarlanmalıdır.

Bu belge, tüm entegrasyon geliştirmeleri için ortak standartları belirler.

---

# Mimari Felsefesi

Entegrasyon sistemi;

- modüler,
- servis bağımsız,
- kolay değiştirilebilir,
- güvenli,
- test edilebilir,
- ölçeklenebilir

olmalıdır.

Hiçbir modül harici bir servise doğrudan bağımlı olmamalıdır.

---

# Entegrasyon Katmanı

Harici sistemlerle iletişim yalnızca **Integration Layer** üzerinden yapılmalıdır.

Standart veri akışı:

```text
Frontend

↓

API

↓

Application Service

↓

Integration Layer

↓

External Service
```

Domain katmanı hiçbir zaman doğrudan harici API çağrısı yapmamalıdır.

# Adapter Pattern

Her harici servis için ayrı bir Adapter kullanılmalıdır.

Örnek:

```text
Notification Interface

↓

WhatsApp Adapter

↓

Meta API
```

Yarın farklı bir sağlayıcıya geçildiğinde yalnızca ilgili Adapter değiştirilmelidir.

---

# Sağlayıcı Bağımsızlığı

Kod hiçbir zaman belirli bir firmaya bağımlı olmamalıdır.

Örneğin;

Bugün:

Meta WhatsApp

Yarın:

Başka bir resmi WhatsApp sağlayıcısı

Sistem yeniden yazılmadan geçiş yapılabilmelidir.

---

# Kimlik Bilgileri

API anahtarları ve gizli bilgiler yalnızca güvenli ortam değişkenlerinde saklanmalıdır.

Hiçbir anahtar;

- kod içerisine,
- Git deposuna,
- istemci tarafına

eklenmemelidir.

---

# Timeout Yönetimi

Harici servislerin cevap vermemesi durumunda sistem beklememelidir.

Her entegrasyon için uygun timeout süresi tanımlanmalıdır.

Uzun süren işlemler Queue sistemine aktarılmalıdır.

---

# Retry Mekanizması

Geçici bağlantı hatalarında otomatik tekrar deneme uygulanmalıdır.

Kalıcı hatalarda kullanıcı bilgilendirilmeli ve olay Audit Log sistemine kaydedilmelidir.

---

# Webhook Desteği

Antrenova hem API çağrısı yapabilmeli hem de dış sistemlerden Webhook alabilmelidir.

Webhook istekleri;

- doğrulanmalı,
- imzalanmalı,
- kayıt altına alınmalıdır.

---

# Hata Yönetimi

Harici sistemlerde oluşan teknik hatalar kullanıcıya doğrudan gösterilmemelidir.

Kullanıcı anlaşılır bir mesaj görmelidir.

Teknik detaylar log sisteminde saklanmalıdır.

---

# Monitoring

Her entegrasyon izlenebilmelidir.

Gösterilecek bilgiler:

- Son başarılı bağlantı
- Son hata
- Ortalama yanıt süresi
- Günlük istek sayısı
- Başarı oranı

Yönetici gerektiğinde entegrasyon sağlığını görebilmelidir.

---

# Güvenlik

Tüm entegrasyonlar aşağıdaki güvenlik standartlarını uygulamalıdır.

- HTTPS/TLS
- API Key Koruması
- OAuth 2.0 (gerektiğinde)
- IP Kısıtlaması (destekleniyorsa)
- İstek Doğrulama
- Rate Limit Kontrolü

Harici sistemlere gereğinden fazla veri gönderilmemelidir.

---

# Tenant İzolasyonu

Her işletmenin entegrasyon ayarları ayrı tutulmalıdır.

Örneğin;

- WhatsApp hesabı
- SMTP bilgileri
- Sanal POS bilgileri

business_id bazında saklanmalıdır.

Bir işletmenin entegrasyon bilgileri başka bir işletme tarafından kullanılamaz.

---

# Audit Log

Aşağıdaki işlemler kayıt altına alınmalıdır.

- Entegrasyon oluşturuldu
- API anahtarı güncellendi
- Webhook alındı
- Bağlantı başarısız oldu
- Sağlayıcı değiştirildi

Tüm kritik değişiklikler izlenebilir olmalıdır.

---

# Ölçeklenebilirlik

Yeni entegrasyonlar;

- mevcut kodu değiştirmeden,
- yeni Adapter eklenerek,
- ortak Interface yapısını kullanarak

sisteme eklenebilmelidir.

Platform zamanla onlarca farklı servisle çalışabilecek şekilde tasarlanmalıdır.

---

# Değiştirilemez Kurallar

Aşağıdaki kurallar tüm entegrasyonlar için zorunludur.

- Harici servisler doğrudan çağrılmayacaktır.
- Integration Layer kullanılacaktır.
- Adapter Pattern uygulanacaktır.
- API anahtarları güvenli ortam değişkenlerinde saklanacaktır.
- Retry ve Timeout mekanizmaları desteklenecektir.
- business_id izolasyonu korunacaktır.
- Audit Log entegrasyonu zorunlu olacaktır.

---

# Sonuç

Integration Architecture, Antrenova'nın dış dünya ile güvenli ve sürdürülebilir şekilde iletişim kurmasını sağlayan temel mimaridir. Modüler entegrasyon katmanı, sağlayıcı bağımsız tasarım ve güçlü güvenlik standartları sayesinde platform; yeni servisler ve cihazlarla kolayca genişleyebilir, mevcut entegrasyonlarını ise minimum maliyetle değiştirebilir.
