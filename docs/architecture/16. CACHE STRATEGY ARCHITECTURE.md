# 16. CACHE STRATEGY ARCHITECTURE

## Amaç

Bu doküman, Antrenova platformunda kullanılacak **Cache (Önbellekleme)** mimarisini, stratejilerini ve performans standartlarını tanımlar.

Cache sistemi; sık kullanılan verilerin geçici olarak saklanmasını sağlayarak veritabanı yükünü azaltır, API yanıt sürelerini kısaltır ve kullanıcı deneyimini iyileştirir.

Bu belge, platform genelinde uygulanacak önbellekleme standartlarını belirler.

---

# Mimari Felsefesi

Cache;

- performansı artırmalı,
- veri bütünlüğünü bozmamalı,
- yönetilebilir olmalı,
- gerektiğinde kolayca temizlenebilmeli,
- kullanıcıdan gizli çalışmalıdır.

Cache hiçbir zaman sistemin tek veri kaynağı değildir.

Asıl veri her zaman veritabanıdır.

---

# Temel Prensip

Önbelleğe yalnızca tekrar tekrar okunan veriler alınmalıdır.

Sık değişen kritik veriler gereksiz yere cache'e alınmamalıdır.

Her veri için uygun yaşam süresi (TTL) belirlenmelidir.

---

# Cache Seviyeleri

Antrenova üç seviyeli cache yapısını desteklemelidir.

### 1. Client Cache

Tarayıcı veya mobil uygulama tarafında saklanan veriler.

Örnekler:

- Tema
- Dil
- Kullanıcı tercihleri

---

### 2. Application Cache

API katmanında tutulan veriler.

Örneğin:

- Dashboard özetleri
- Sabit listeler
- Ayarlar

---

### 3. CDN / Static Cache

Statik içerikler.

Örneğin:

- Logo
- Görseller
- İkonlar
- Fontlar

---

# Cache Kullanılabilecek Veriler

Aşağıdaki veriler cache için uygundur.

- Dashboard KPI'ları
- Branş Listeleri
- Şehir Listeleri
- Ülke Listeleri
- Ayarlar
- Yetki Tanımları
- Sabit Parametreler

---

# Cache Kullanılmaması Gereken Veriler

Aşağıdaki veriler doğrudan güncel kaynaktan okunmalıdır.

- Finans İşlemleri
- Aktif Tahsilatlar
- Gerçek Zamanlı Yoklama
- Anlık Bildirimler
- Kritik Güvenlik Bilgileri

Bu verilerde gecikme kabul edilmez.

---

# TTL (Time To Live)

Her cache kaydı yaşam süresine sahip olmalıdır.

Örnek:

- Dashboard → 5 dakika
- Ayarlar → 30 dakika
- Şehir Listesi → 24 saat
- Yetkiler → 15 dakika

TTL, veri türüne göre belirlenmelidir.

---

# Cache Temizleme

Aşağıdaki durumlarda cache otomatik temizlenmelidir.

- Kayıt güncellendiğinde
- Kayıt silindiğinde
- Ayarlar değiştiğinde
- Rol değiştiğinde
- Şube değiştiğinde

Eski verilerin gösterilmesi engellenmelidir.

---

# Tenant İzolasyonu

Cache kayıtları business_id bazında ayrılmalıdır.

Örneğin;

```
Business A

↓

Dashboard Cache

Business B

↓

Dashboard Cache
```

Hiçbir işletme başka işletmenin cache verisini göremez.

---

# Kullanıcı Bazlı Cache

Bazı veriler kullanıcıya özel tutulmalıdır.

Örneğin;

- Menü Yetkileri
- Favoriler
- Son Aramalar
- Dashboard Düzeni

Bu bilgiler diğer kullanıcılarla paylaşılmamalıdır.

---

# API Cache

Sık kullanılan GET istekleri cache desteği kullanabilir.

Ancak;

POST

PUT

PATCH

DELETE

işlemleri sonrasında ilgili cache temizlenmelidir.

---

# React Query Entegrasyonu

Frontend tarafında veri önbellekleme için TanStack Query kullanılmalıdır.

Önbellek yönetimi;

- invalidate,
- refetch,
- staleTime

mekanizmaları ile kontrol edilmelidir.

---

# Performans

Cache sistemi aşağıdaki hedefleri desteklemelidir.

- Veritabanı yükünü azaltmak
- API yanıt süresini düşürmek
- Dashboard açılışını hızlandırmak
- Mobil veri kullanımını azaltmak

---

# Monitoring

Cache kullanımı izlenebilmelidir.

Örneğin;

- Cache Hit
- Cache Miss
- Ortalama Yanıt Süresi
- Temizlenen Cache Sayısı

Bu veriler performans analizlerinde kullanılmalıdır.

---

# Güvenlik

Aşağıdaki veriler cache'e alınmamalıdır.

- Şifreler
- Token'lar
- Kimlik doğrulama bilgileri
- Hassas finansal bilgiler

Cache güvenlik katmanı değildir.

---

# Ölçeklenebilirlik

İlerleyen sürümlerde aşağıdaki teknolojiler desteklenebilir.

- Redis
- Distributed Cache
- Edge Cache
- CDN Cache
- Memory Cache

Mevcut mimari kolayca genişletilebilmelidir.

---

# Değiştirilemez Kurallar

Aşağıdaki kurallar Cache sistemi için zorunludur.

- business_id izolasyonu korunacaktır.
- Kritik finans verileri cache'de tutulmayacaktır.
- TTL zorunlu olacaktır.
- Güncellenen kayıtların cache'i temizlenecektir.
- React Query standartları uygulanacaktır.
- Cache asıl veri kaynağı olmayacaktır.

---

# Sonuç

Cache Strategy Architecture, Antrenova'nın yüksek performanslı çalışmasını sağlayan temel optimizasyon katmanıdır. Doğru önbellekleme stratejileri sayesinde API yükü azalır, kullanıcı deneyimi hızlanır ve sistem büyüdükçe performansını koruyabilir. Tüm cache işlemleri veri bütünlüğünü ve tenant izolasyonunu bozmayacak şekilde yönetilmelidir.
