# 18. SECURITY ARCHITECTURE

## Amaç

Bu doküman, Antrenova platformunun güvenlik mimarisini, veri koruma politikalarını ve platform genelinde uygulanacak güvenlik standartlarını tanımlar.

Security Architecture yalnızca kullanıcı girişini koruyan bir sistem değildir. Kullanıcı hesaplarından veritabanına, API katmanından dosya depolamaya kadar tüm platformun güvenliğini kapsayan merkezi güvenlik yaklaşımıdır.

Bu belge, geliştirilecek tüm modüller için zorunlu güvenlik kurallarını belirler.

---

# Güvenlik Felsefesi

Antrenova'da güvenlik sonradan eklenen bir özellik değildir.

Tüm geliştirmeler aşağıdaki prensiplerle yapılmalıdır.

- Security by Design
- Least Privilege
- Zero Trust
- Defense in Depth
- Privacy by Default

Her yeni özellik güvenlik açısından değerlendirilmeden canlı ortama alınmamalıdır.

---

# Güvenlik Katmanları

Platform aşağıdaki güvenlik katmanlarından oluşmalıdır.

- Authentication
- Authorization
- API Security
- Database Security
- Storage Security
- Network Security
- Audit Log
- Monitoring

Her katman birbirini desteklemelidir.

---

# Authentication

Kimlik doğrulama aşağıdaki standartları desteklemelidir.

- Güçlü parola politikası
- Güvenli oturum yönetimi
- Şifre sıfırlama
- E-posta doğrulama
- Çok faktörlü doğrulama (gelecek sürüm)

Kimlik doğrulama güvenliğin ilk katmanıdır.

---

# Authorization

Kullanıcılar yalnızca yetkili oldukları işlemleri gerçekleştirebilmelidir.

Yetki kontrolü;

- Rol
- İzin
- business_id
- branch_id

üzerinden yapılmalıdır.

Varsayılan yaklaşım "Erişim Yok" olmalıdır.

---

# API Güvenliği

Tüm API istekleri aşağıdaki kontrollerden geçmelidir.

- Kimlik doğrulama
- Yetki doğrulama
- Veri doğrulama
- Rate Limiting
- business_id kontrolü

API güvenliği yalnızca istemci tarafına bırakılamaz.

---

# Veritabanı Güvenliği

Veriler aşağıdaki kurallara göre korunmalıdır.

- Row Level Security (RLS)
- Foreign Key Kısıtları
- Parametrik Sorgular
- SQL Injection Koruması
- Soft Delete

Veritabanı en son savunma hattıdır.

---

# Dosya Güvenliği

Hiçbir dosya doğrudan herkese açık olmamalıdır.

Dosya erişimleri;

- rol,
- business_id,
- izin

kontrolleri sonrasında sağlanmalıdır.

İmzalı bağlantılar (Signed URL) kullanılmalıdır.

---

# Ağ Güvenliği

Tüm istemci ve sunucu iletişimi HTTPS üzerinden gerçekleştirilmelidir.

Güvenli olmayan bağlantılar kabul edilmemelidir.

TLS standartları güncel tutulmalıdır.

---

# KVKK ve Gizlilik

Platform aşağıdaki gizlilik ilkelerini desteklemelidir.

- Veri Minimizasyonu
- Açık Rıza Yönetimi
- Veri Saklama Politikaları
- Veri Silme Talepleri
- Kişisel Veri Koruması

Gizlilik, sistem tasarımının ayrılmaz parçasıdır.

---

# Hassas Veriler

Aşağıdaki bilgiler özel koruma gerektirir.

- TC Kimlik Numarası
- Sağlık Bilgileri
- Finansal Bilgiler
- Kimlik Belgeleri
- API Anahtarları
- Erişim Token'ları

Bu alanlara erişim rol bazlı sınırlandırılmalıdır.

---

# Oturum Güvenliği

Oturum yönetimi aşağıdaki kurallara uymalıdır.

- Otomatik zaman aşımı
- Güvenli token yönetimi
- Çıkışta oturum sonlandırma
- Aynı anda aktif cihaz takibi (gelecek sürüm)

Eski veya geçersiz oturumlar kullanılmamalıdır.

---

# Güvenlik Olayları

Aşağıdaki olaylar Audit Log sistemine kaydedilmelidir.

- Başarısız giriş
- Yetkisiz erişim denemesi
- Rol değişikliği
- API anahtarı güncellemesi
- Kritik veri görüntüleme

Şüpheli işlemler gerektiğinde yöneticilere bildirilebilmelidir.

---

# Rate Limiting

Sistemi kötüye kullanımı önlemek amacıyla;

- Giriş denemeleri
- API çağrıları
- Şifre sıfırlama istekleri
- OTP talepleri

belirlenen sınırlar içerisinde çalışmalıdır.

---

# Güvenlik Güncellemeleri

Kullanılan bağımlılıklar düzenli olarak güncellenmelidir.

Kritik güvenlik açıkları öncelikli olarak kapatılmalıdır.

Üçüncü taraf paketler kullanılmadan önce güvenlik açısından değerlendirilmelidir.

---

# Monitoring

Güvenlik olayları merkezi olarak izlenebilmelidir.

Örneğin;

- Başarısız giriş oranı
- Yetkisiz API çağrıları
- Şüpheli IP adresleri
- Anormal kullanım davranışları

Bu bilgiler güvenlik panellerinde raporlanmalıdır.

---

# Felaket Senaryoları

Platform aşağıdaki durumlara hazırlıklı olmalıdır.

- Veri kaybı
- Sunucu arızası
- Storage problemi
- Yetkisiz erişim
- API sağlayıcısı kesintisi

Her senaryo için kurtarma planı bulunmalıdır.

---

# Ölçeklenebilirlik

İlerleyen sürümlerde aşağıdaki güvenlik özellikleri eklenebilmelidir.

- MFA
- SSO
- IP Beyaz Liste
- SIEM Entegrasyonu
- Yapay Zekâ Destekli Güvenlik Analizi
- Güvenlik Skorlama Sistemi

Mevcut mimari yeniden tasarlanmadan genişleyebilmelidir.

---

# Değiştirilemez Kurallar

Aşağıdaki kurallar platform genelinde zorunludur.

- HTTPS kullanılacaktır.
- RLS uygulanacaktır.
- business_id izolasyonu korunacaktır.
- Hassas veriler rol bazlı korunacaktır.
- Audit Log zorunlu olacaktır.
- API anahtarları istemci tarafında tutulmayacaktır.
- Güvenlik kontrolleri sunucu tarafında gerçekleştirilecektir.

---

# Sonuç

Security Architecture, Antrenova'nın tüm güvenlik katmanlarını tek çatı altında toplayan temel mimari dokümandır. Kimlik doğrulama, yetkilendirme, veri koruma, ağ güvenliği ve denetlenebilirlik standartları sayesinde platform; bireysel spor salonlarından kurumsal zincirlere kadar güvenli, sürdürülebilir ve yasal gerekliliklere uygun bir altyapı sunacaktır.
