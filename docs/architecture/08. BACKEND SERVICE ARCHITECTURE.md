# 08. BACKEND SERVICE ARCHITECTURE

## Amaç

Bu doküman, Antrenova platformunda kullanılacak Backend Service katmanının mimarisini, sorumluluklarını ve geliştirme standartlarını tanımlar.

Backend Service katmanı, kullanıcı arayüzü ile Domain (iş kuralları) katmanı arasında yer alır ve uygulamanın iş akışlarını yönetir. Bu katman; veri doğrulama, işlem sıralaması, transaction yönetimi ve modüller arası koordinasyondan sorumludur.

Bu belge, geliştirilecek tüm servisler için ortak standartları belirler.

---

# Mimari Felsefesi

Backend servisleri;

- modüler,
- yeniden kullanılabilir,
- test edilebilir,
- bağımsız,
- tek sorumluluk ilkesine uygun

olmalıdır.

Her servis yalnızca kendi iş alanından sorumlu olmalıdır.

---

# Katman Konumu

Backend Service katmanı aşağıdaki yapı içerisinde yer alır.

```text
UI

↓

API

↓

Application Service

↓

Domain

↓

Repository

↓

Database
```

Application Service katmanı Domain ile kullanıcı arayüzü arasında koordinasyon sağlar.

---

# Servislerin Görevi

Servisler;

- iş akışını başlatır,
- gerekli doğrulamaları yapar,
- transaction yönetir,
- farklı modülleri koordine eder,
- sonucu API katmanına döndürür.

İş kuralları mümkün olduğunca Domain katmanında tutulmalıdır.

---

# Tek Sorumluluk İlkesi

Her servis yalnızca tek bir amacı gerçekleştirmelidir.

Örneğin;

```
CreateMemberService

MemberSearchService

FreezeMembershipService

CreatePaymentService
```

Bir servis onlarca farklı işlem yapmamalıdır.

---

# Modül Bazlı Yapı

Her modül kendi servis klasörüne sahip olmalıdır.

Örnek:

```text
features/

members/

services/

create-member.service.ts

update-member.service.ts

delete-member.service.ts

search-member.service.ts
```

Servisler modül sınırlarını ihlal etmemelidir.

---

# Transaction Yönetimi

Birden fazla tabloyu etkileyen işlemler transaction içerisinde çalışmalıdır.

Örneğin;

- Üye oluşturma
- Paket satışı
- Tahsilat işlemi
- Üyelik yenileme

İşlemler yarıda kalmamalıdır.

---

# Hata Yönetimi

Servisler beklenen ve beklenmeyen hataları ayırmalıdır.

Beklenen örnekler:

- Üye bulunamadı
- Paket süresi dolmuş
- Yetkisiz işlem

Beklenmeyen teknik hatalar kullanıcıya gösterilmemelidir.

---

# Validation

Servisler yalnızca doğrulanmış veri ile çalışmalıdır.

Validation işlemleri API katmanında başlasa da kritik kurallar servis seviyesinde tekrar kontrol edilmelidir.

---

# Repository Kullanımı

Servisler veritabanına doğrudan erişmemelidir.

Veri erişimi yalnızca Repository katmanı üzerinden yapılmalıdır.

Bu yapı test edilebilirliği artırır.

---

# Domain Servisleri

İş kuralları Domain katmanında bulunmalıdır.

Application Service;

- Domain servislerini çağırır,
- sonucu yönetir.

Kurallar servis katmanına dağılmamalıdır.

---

# Event Tetikleme

Önemli işlemler sonrasında sistem olayları tetiklenebilmelidir.

Örneğin;

- Üye oluşturuldu
- Tahsilat tamamlandı
- Paket yenilendi

Bu olaylar bildirim, log veya raporlama sistemleri tarafından kullanılabilir.

---

# Audit Uyumluluğu

Servis katmanında gerçekleşen kritik işlemler Audit Log sistemine aktarılmalıdır.

Örneğin;

- Kim oluşturdu?
- Ne zaman oluşturdu?
- Hangi kayıt değişti?

Tüm önemli işlemler izlenebilir olmalıdır.

---

# Performans

Servisler aşağıdaki prensiplere uygun geliştirilmelidir.

- Gereksiz sorgulardan kaçınılmalı
- Aynı veri tekrar çekilmemeli
- Büyük işlemler parçalanmalı
- Uzun süren görevler Queue sistemine aktarılmalı

Performans her servis için önceliklidir.

---

# Güvenlik

Servisler aşağıdaki güvenlik kontrollerini desteklemelidir.

- Authentication
- Authorization
- business_id doğrulaması
- branch_id doğrulaması
- Veri doğrulama
- Audit Log

Hiçbir servis bu kontrolleri atlayamaz.

---

# Test Edilebilirlik

Her servis bağımsız olarak test edilebilmelidir.

Servislerin;

- Unit Test
- Integration Test

ile doğrulanması mümkün olmalıdır.

Bağımlılıklar mümkün olduğunca soyutlanmalıdır.

---

# Ölçeklenebilirlik

İlerleyen sürümlerde servisler;

- Queue Worker'lar,
- Event Bus,
- Microservice yapıları,
- Harici servis entegrasyonları

ile uyumlu çalışabilecek şekilde tasarlanmalıdır.

Bugünkü mimari gelecekte yeniden yazılmak zorunda kalmamalıdır.

---

# Değiştirilemez Kurallar

Aşağıdaki kurallar Backend Service katmanı için zorunludur.

- Servisler tek sorumluluk ilkesine uyar.
- Veritabanına doğrudan erişim yapılmaz.
- Repository kullanımı zorunludur.
- Transaction gereken işlemlerde uygulanır.
- Audit Log desteği sağlanır.
- business_id doğrulaması yapılır.
- İş kuralları Domain katmanında tutulur.

---

# Sonuç

Backend Service Architecture, Antrenova'nın uygulama mantığını yöneten merkezi katmandır. Modüler servis yapısı, transaction yönetimi, güvenlik kontrolleri ve Domain odaklı yaklaşımı sayesinde sistem; bakım yapılabilir, test edilebilir ve uzun yıllar boyunca büyümeye uygun bir mimari üzerinde geliştirilebilir.
