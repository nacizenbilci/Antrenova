# 02. İş Akışı Durum Yönetimi Standartları (Workflow State Management)

> **Doküman Kodu:** WF-02  
> **Dosya Adı:** `02_WORKFLOW_STATE_MANAGEMENT.md`  
> **Versiyon:** 1.0  
> **Durum:** Onaylandı  
> **Bağımlı Dokümanlar:** Workflow Design Principles, Business Rules, Database Standards, API Standards, Audit Rules

---

# 1. Amaç

Bu dokümanın amacı, Antrenova platformunda çalışan tüm iş akışlarında kullanılacak durum (State) yönetimi standartlarını belirlemek ve süreçlerin kontrollü, izlenebilir ve tutarlı şekilde ilerlemesini sağlamaktır.

Bir iş akışının mevcut durumunu doğru yönetmek, yalnızca kullanıcı arayüzü açısından değil; iş kurallarının uygulanması, API davranışlarının standartlaştırılması, bildirimlerin doğru zamanda gönderilmesi ve raporlamanın güvenilir olması açısından da kritik öneme sahiptir.

Platform genelindeki tüm süreçler ortak State Management yaklaşımını kullanmalıdır.

---

# 2. Temel İlkeler

Durum yönetimi aşağıdaki prensiplere uygun olmalıdır.

- Her kayıt yalnızca bir aktif duruma sahip olmalıdır.
- Durum değişiklikleri kontrollü olmalıdır.
- Geçişler tanımlı kurallara bağlı olmalıdır.
- Geçmiş durumlar izlenebilmelidir.
- Yetkisiz durum değişiklikleri engellenmelidir.

Her modül aynı yönetim mantığını kullanmalıdır.

---

# 3. State Kavramı

State, bir kaydın o andaki operasyonel durumunu ifade eder.

Örneğin.

Bir rezervasyon.

```text
Draft
Pending
Confirmed
Completed
Cancelled
```

durumlarından yalnızca birinde bulunabilir.

Aynı anda birden fazla aktif durum bulunmamalıdır.

---

# 4. State Transition

Her durumdan her duruma geçiş yapılamamalıdır.

Örneğin.

```text
Draft
 ↓
Pending
 ↓
Confirmed
 ↓
Completed
```

şeklindeki akış desteklenebilir.

Ancak.

```text
Completed → Draft
```

doğrudan mümkün olmamalıdır.

---

# 5. Geçiş Kuralları

Durum değişiklikleri aşağıdaki kontrollerden sonra yapılmalıdır.

- Kullanıcı yetkisi
- Business Rule doğrulaması
- Veri bütünlüğü
- Gerekli alanların tamamlanması

Başarısız doğrulamalarda State değişmemelidir.

---

# 6. Varsayılan Durum

Yeni oluşturulan kayıtların başlangıç durumu açık şekilde tanımlanmalıdır.

Örneğin.

```text
Draft
```

veya

```text
Pending
```

Varsayılan durum dokümante edilmelidir.

---

# 7. Terminal Durumlar

Bazı durumlar süreç sonunu ifade eder.

Örneğin.

```text
Completed
Cancelled
Expired
```

Bu durumlardan sonra yeni işlem yapılamayabilir.

Terminal State kuralları iş süreçlerine göre belirlenmelidir.

---

# 8. Soft Delete ile İlişki

State değişikliği kayıt silme anlamına gelmez.

Örneğin.

```text
Cancelled
```

durumundaki kayıt hâlâ sistemde bulunmalıdır.

Soft Delete yalnızca veri yaşam döngüsü yönetimi için kullanılmalıdır.

---

# 9. Audit Kaydı

Her durum değişikliği Audit sistemine kaydedilmelidir.

Kaydedilecek bilgiler.

- Eski durum
- Yeni durum
- Kullanıcı
- Tarih
- Saat
- İşlem nedeni

Geçmiş durumlar silinmemelidir.

---

# 10. Bildirimler

Belirli durum değişiklikleri bildirim üretmelidir.

Örneğin.

- Ödeme tamamlandı
- Rezervasyon onaylandı
- Paket süresi doldu
- Üyelik iptal edildi

Bildirim kuralları Business Rules ile uyumlu olmalıdır.

---

# 11. API Davranışı

State değişiklikleri API üzerinden gerçekleştirildiğinde.

- Validation
- Authorization
- Audit
- Notification

süreçleri otomatik çalışmalıdır.

API katmanı iş kurallarını atlamamalıdır.

---

# 12. Kullanıcı Arayüzü

Kullanıcı arayüzünde yalnızca geçerli durum geçişleri gösterilmelidir.

Örneğin.

Bir kayıt.

```text
Completed
```

durumundaysa.

```text
Approve
```

butonu görünmemelidir.

Arayüz State kurallarına uygun davranmalıdır.

---

# 13. Performans

Durum alanları sık sorgulandığından uygun şekilde indekslenmelidir.

Özellikle.

- status
- workflow_state
- updated_at

alanları performans açısından optimize edilmelidir.

---

# 14. Dokümantasyon

Her workflow için aşağıdaki bilgiler belgelenmelidir.

- Desteklenen durumlar
- Geçiş diyagramı
- Yetkiler
- Bildirimler
- Terminal durumlar

State Machine diyagramları güncel tutulmalıdır.

---

# 15. Genel Kurallar

Workflow State Management, Antrenova platformundaki tüm operasyonel süreçlerin kontrollü şekilde ilerlemesini sağlayan temel mekanizmadır. Her kayıt belirli durumlar arasında tanımlı kurallara göre geçiş yapmalı, tüm değişiklikler Audit sistemine kaydedilmeli ve kullanıcı arayüzü ile API katmanı aynı State Machine mantığını kullanmalıdır.

Bu nedenle durum yönetimi platform genelinde standartlaştırılmalı, yeni modüller aynı geçiş kurallarını benimsemeli ve iş süreçleri büyüdükçe genişletilebilir bir yapı korunmalıdır.
