# 16. Rapor Oluşturma İş Akışı (Reporting Workflow)

> **Doküman Kodu:** WF-16  
> **Dosya Adı:** `16_REPORTING_WORKFLOW.md`  
> **Versiyon:** 1.0  
> **Durum:** Onaylandı  
> **Bağımlı Dokümanlar:** Background Jobs Workflow, API Performance, Database Standards, Authorization Rules, Audit Rules

---

# 1. Amaç

Bu dokümanın amacı, Antrenova platformunda oluşturulacak tüm raporların hazırlanması, işlenmesi, sunulması ve paylaşılması süreçlerini standartlaştırmaktır.

Raporlama yalnızca verilerin ekranda listelenmesi değildir. Büyük veri kümelerinin filtrelenmesi, performanslı sorguların çalıştırılması, yetki kontrollerinin uygulanması, raporların dosya olarak dışa aktarılması ve gerektiğinde arka plan görevleriyle hazırlanması süreçlerini kapsar.

Platform genelindeki tüm raporlar bu iş akışına uygun hazırlanmalıdır.

---

# 2. Temel İlkeler

Raporlama süreci aşağıdaki prensiplere uygun olmalıdır.

- Doğru veri üretmelidir.
- Yetki kontrollü olmalıdır.
- Performanslı çalışmalıdır.
- Tekrarlanabilir olmalıdır.
- İzlenebilir olmalıdır.

Her rapor aynı veri kaynağından üretildiğinde aynı sonucu vermelidir.

---

# 3. Rapor Talebi

Rapor oluşturma aşağıdaki kaynaklardan başlatılabilir.

- Yönetim paneli
- Eğitmen paneli
- Finans ekranı
- Mobil uygulama
- API

Tüm istemciler ortak raporlama servisini kullanmalıdır.

---

# 4. Yetki Kontrolü

Rapor hazırlanmadan önce aşağıdaki kontroller yapılmalıdır.

- Kullanıcı rolü
- Business ID
- Branch ID
- Görüntüleme yetkisi

Yetkisiz kullanıcı rapor oluşturamamalıdır.

---

# 5. Filtreleme

Raporlar dinamik filtreleme desteklemelidir.

Örnek filtreler.

- Tarih aralığı
- Şube
- Eğitmen
- Üye
- Paket
- Branş
- Ödeme yöntemi

Filtreler standart API parametrelerini kullanmalıdır.

---

# 6. Veri Hazırlama

Rapor oluşturulurken.

- Gereksiz sütunlar alınmamalıdır.
- Performanslı sorgular kullanılmalıdır.
- İndekslerden yararlanılmalıdır.

Veri hazırlama süreci optimize edilmelidir.

---

# 7. Büyük Raporlar

Uzun süren raporlar kullanıcıyı bekletmemelidir.

Standart süreç.

```text
Request
↓
Background Job
↓
Generate
↓
Notify
↓
Download
```

Büyük raporlar arka planda hazırlanmalıdır.

---

# 8. Dosya Formatları

Raporlar aşağıdaki formatlarda dışa aktarılabilir.

- PDF
- Excel
- CSV

Yeni formatlar sisteme eklenebilir olmalıdır.

---

# 9. Hazırlanan Raporlar

Oluşturulan raporlar belirli süre saklanabilir.

Her rapor.

- Oluşturan kullanıcı
- Tarih
- Filtre bilgileri
- Format

ile ilişkilendirilmelidir.

Eski raporlar otomatik temizlenebilir.

---

# 10. Bildirim Süreci

Arka planda hazırlanan rapor tamamlandığında kullanıcı bilgilendirilmelidir.

Örneğin.

- Uygulama içi bildirim
- E-posta
- WhatsApp (işletme tercihlerine göre)

Bildirim rapor bağlantısını içerebilir.

---

# 11. Audit ve Loglama

Her rapor oluşturma işlemi kayıt altına alınmalıdır.

Kaydedilecek bilgiler.

- Kullanıcı
- Rapor tipi
- Filtreler
- Tarih
- Süre
- Dosya formatı

Bu kayıtlar denetim amaçlı saklanmalıdır.

---

# 12. Performans

Raporlama işlemleri canlı sistemi olumsuz etkilememelidir.

Yoğun sorgular.

- Queue
- Cache
- Read Replica (gelecekte)

ile desteklenebilir.

Performans düzenli izlenmelidir.

---

# 13. API Uyumu

Reporting API aşağıdaki süreçleri otomatik uygulamalıdır.

- Authentication
- Authorization
- Filtering
- Background Jobs
- Audit

API ile kullanıcı arayüzü aynı raporlama mantığını kullanmalıdır.

---

# 14. Rapor Türleri

Platform aşağıdaki temel raporları desteklemelidir.

- Üye raporları
- Finans raporları
- Katılım raporları
- Eğitmen raporları
- Rezervasyon raporları
- Satış raporları

Yeni rapor tipleri mevcut altyapıyı bozmadan eklenebilmelidir.

---

# 15. Genel Kurallar

Rapor oluşturma iş akışı, Antrenova platformundaki karar destek mekanizmalarının temelini oluşturur. Tüm raporlar yetki kontrolleriyle hazırlanmalı, performanslı veri sorguları kullanılmalı, büyük raporlar arka plan görevleriyle oluşturulmalı ve tüm işlemler Audit sistemi tarafından kayıt altına alınmalıdır.

Bu sayede işletmeler güvenilir verilere hızlı şekilde ulaşabilir, operasyonlarını doğru analiz edebilir ve büyüyen veri hacmine rağmen yüksek performanslı raporlama deneyimi yaşayabilir.
