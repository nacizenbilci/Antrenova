# 17. Veritabanı Güvenlik Standartları (Database Security)

> **Doküman Kodu:** DB-17  
> **Dosya Adı:** `17_DATABASE_SECURITY.md`  
> **Versiyon:** 1.0  
> **Durum:** Onaylandı  
> **Bağımlı Dokümanlar:** Authentication Rules, Authorization Rules, Multi-Tenant Database, Audit Rules, Backup Rules

---

# 1. Amaç

Bu dokümanın amacı, Antrenova veritabanında saklanan tüm verilerin gizliliğini, bütünlüğünü ve erişilebilirliğini koruyacak güvenlik standartlarını belirlemektir.

Veritabanı güvenliği yalnızca yetkisiz erişimi engellemekten ibaret değildir. Aynı zamanda veri sızıntılarının önlenmesi, tenant izolasyonunun korunması, hassas bilgilerin güvenli şekilde saklanması ve sistemin saldırılara karşı dayanıklı hale getirilmesini kapsayan bütüncül bir yaklaşımdır.

Bu kurallar tüm geliştirme, test ve üretim ortamlarında uygulanmalıdır.

---

# 2. Temel İlkeler

Veritabanı güvenliği aşağıdaki üç temel prensibe dayanmalıdır.

- Gizlilik (Confidentiality)
- Bütünlük (Integrity)
- Erişilebilirlik (Availability)

Her güvenlik kararı bu üç ilkeye uygun değerlendirilmelidir.

---

# 3. Kimlik Doğrulama

Veritabanına erişen tüm servisler güvenli kimlik doğrulama kullanmalıdır.

Aşağıdaki kurallar uygulanmalıdır.

- Güçlü kimlik bilgileri
- Ayrı servis hesapları
- Minimum yetki prensibi
- Gizli anahtar yönetimi

Ortak kullanıcı hesapları kullanılmamalıdır.

---

# 4. Yetkilendirme

Her kullanıcı ve servis yalnızca ihtiyaç duyduğu verilere erişebilmelidir.

Yetkiler.

- rol bazlı,
- servis bazlı,
- tenant bazlı

olarak sınırlandırılmalıdır.

Varsayılan yaklaşım **"önce reddet, sonra izin ver"** olmalıdır.

---

# 5. Row Level Security

Tenant tablolarında PostgreSQL Row Level Security (RLS) kullanılmalıdır.

Her sorgu.

```sql
business_id = current_business_id
```

mantığıyla sınırlandırılmalıdır.

Uygulama katmanı tek başına güvenlik mekanizması olarak görülmemelidir.

---

# 6. Hassas Veriler

Aşağıdaki bilgiler hassas veri olarak değerlendirilmelidir.

- Kimlik numaraları
- Sağlık bilgileri
- API anahtarları
- Erişim tokenları
- Finansal bilgiler

Bu veriler gerektiğinde şifrelenerek saklanmalıdır.

---

# 7. Şifre Güvenliği

Şifreler hiçbir zaman düz metin olarak saklanmamalıdır.

Kullanılması gereken yaklaşım.

- Güçlü Hash algoritmaları
- Salt kullanımı
- Tek yönlü şifreleme

Eski şifrelerin geri okunabilmesi mümkün olmamalıdır.

---

# 8. SQL Injection Koruması

Tüm sorgular güvenli şekilde oluşturulmalıdır.

Aşağıdaki yöntemler kullanılmalıdır.

- Parametreli sorgular
- ORM güvenlik mekanizmaları
- Girdi doğrulama

Dinamik SQL oluşturulurken kullanıcı girdileri doğrudan kullanılmamalıdır.

---

# 9. Bağlantı Güvenliği

Veritabanı bağlantıları güvenli iletişim kanalları üzerinden gerçekleştirilmelidir.

- TLS/SSL kullanılmalıdır.
- Sertifika doğrulaması yapılmalıdır.
- Güvensiz bağlantılar reddedilmelidir.

Şifrelenmemiş bağlantılar desteklenmemelidir.

---

# 10. Gizli Bilgiler

Bağlantı bilgileri.

- kaynak kod içerisinde tutulmamalıdır.
- Git deposuna eklenmemelidir.
- Ortam değişkenleri veya güvenli Secret Manager üzerinden yönetilmelidir.

Gizli bilgiler düzenli aralıklarla yenilenmelidir.

---

# 11. Log Güvenliği

Veritabanı loglarında hassas bilgiler yer almamalıdır.

Örneğin.

- Şifreler
- Token'lar
- Kimlik numaraları
- Kart bilgileri

Log kayıtlarında maskeleme uygulanmalıdır.

---

# 12. Yedek Güvenliği

Yedek dosyaları da aynı güvenlik standartlarına tabi olmalıdır.

- Şifrelenmelidir.
- Yetkilendirilmelidir.
- Ayrı depolama alanında tutulmalıdır.
- Erişim kayıtları izlenmelidir.

Yedekler canlı veritabanı kadar kritik kabul edilmelidir.

---

# 13. Güvenlik Denetimi

Veritabanı güvenliği düzenli olarak test edilmelidir.

Kontrol edilmesi gereken başlıklar.

- Yetkiler
- RLS politikaları
- Güvenlik açıkları
- Kullanılmayan hesaplar
- Eski erişim anahtarları

Denetim sonuçları kayıt altına alınmalıdır.

---

# 14. Audit ve İzlenebilirlik

Aşağıdaki güvenlik olayları Audit sistemine kaydedilmelidir.

- Başarısız bağlantılar
- Yetkisiz erişim girişimleri
- RLS ihlalleri
- Yetki değişiklikleri
- Şifre değişiklikleri
- Güvenlik ayarı güncellemeleri

Bu kayıtlar silinemez olmalıdır.

---

# 15. Genel Kurallar

Veritabanı güvenliği, Antrenova'nın tüm dijital varlıklarını koruyan en kritik altyapı katmanlarından biridir. Her veri yalnızca yetkili kullanıcılar tarafından erişilebilir olmalı, tenant izolasyonu eksiksiz uygulanmalı ve tüm güvenlik mekanizmaları uygulama ile veritabanı seviyesinde birlikte çalışmalıdır.

Bu nedenle Database Security standartları tüm geliştirme süreçlerinde temel referans olarak kullanılmalı, güvenlik sonradan eklenen bir özellik değil, tasarımın ayrılmaz bir parçası olarak değerlendirilmelidir.
