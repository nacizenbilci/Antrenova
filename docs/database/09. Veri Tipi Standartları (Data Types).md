# 09. Veri Tipi Standartları (Data Types)

> **Doküman Kodu:** DB-09  
> **Dosya Adı:** `09_DATA_TYPES.md`  
> **Versiyon:** 1.0  
> **Durum:** Onaylandı  
> **Bağımlı Dokümanlar:** Database Design Principles, Column Standards, Constraint Rules, Table Standards, Naming Conventions

---

# 1. Amaç

Bu dokümanın amacı, Antrenova veritabanında kullanılacak veri tiplerinin (Data Types) standartlarını belirlemek, tüm modüllerde tutarlı veri yapıları oluşturmak ve gereksiz veri kaybı, performans sorunları veya bakım maliyetlerini önlemektir.

Veri tipi seçimi yalnızca teknik bir tercih değildir. Yanlış seçilen veri tipleri depolama alanını artırabilir, sorgu performansını düşürebilir, indeks kullanımını olumsuz etkileyebilir ve veri doğruluğunu bozabilir.

Bu nedenle her sütun, taşıdığı bilginin niteliğine en uygun veri tipiyle tanımlanmalıdır.

---

# 2. Temel İlkeler

Veri tipi seçilirken aşağıdaki prensipler dikkate alınmalıdır.

- Gereğinden büyük veri tipi kullanılmamalıdır.
- Veri kaybına neden olacak küçük veri tipi seçilmemelidir.
- Aynı veri platform genelinde aynı veri tipiyle saklanmalıdır.
- Gelecekteki büyüme dikkate alınmalıdır.

Platform genelinde ortak veri sözlüğü kullanılmalıdır.

---

# 3. UUID Kullanımı

Tüm Primary Key alanlarında aşağıdaki veri tipi kullanılacaktır.

```text
UUID
```

UUID aşağıdaki alanlarda da kullanılmalıdır.

- Foreign Key alanları
- Business ID
- Branch ID
- User ID
- Audit ID

Integer tabanlı kimlikler standart olarak kullanılmayacaktır.

---

# 4. Metin Verileri

Kısa metinler için.

```text
VARCHAR
```

Uzun açıklamalar için.

```text
TEXT
```

kullanılmalıdır.

Örnekler.

```text
first_name
last_name
email
phone_number
```

gereksiz şekilde TEXT olarak tanımlanmamalıdır.

---

# 5. Sayısal Veriler

Tam sayı gerektiren alanlarda.

```text
INTEGER
BIGINT
```

Ondalıklı finansal verilerde.

```text
NUMERIC
```

kullanılmalıdır.

Para hesaplamalarında FLOAT veya DOUBLE kullanılmamalıdır.

---

# 6. Para Alanları

Finansal tüm alanlar aşağıdaki veri tipini kullanmalıdır.

```text
NUMERIC(12,2)
```

Örneğin.

```text
price
discount_amount
remaining_balance
tax_amount
payment_amount
```

Bu yaklaşım hassas hesaplama hatalarını önler.

---

# 7. Boolean Alanlar

Evet/Hayır mantığı taşıyan alanlarda.

```text
BOOLEAN
```

kullanılmalıdır.

Örnekler.

```text
is_active
is_deleted
is_verified
has_discount
can_login
```

Boolean yerine INTEGER kullanılmamalıdır.

---

# 8. Tarih ve Saat

Tarih alanlarında.

```text
DATE
```

Tarih ve saat bilgisi gereken alanlarda.

```text
TIMESTAMP WITH TIME ZONE
```

kullanılmalıdır.

Timezone desteği platform genelinde zorunludur.

---

# 9. JSON Kullanımı

Esnek veri yapıları için.

```text
JSONB
```

kullanılabilir.

Örneğin.

- Ek ayarlar
- Dinamik konfigürasyonlar
- API cevapları

İlişkisel veriler JSON içerisinde saklanmamalıdır.

---

# 10. Enum Kullanımı

Sınırlı seçenekler içeren alanlarda.

- ENUM
- CHECK Constraint

yaklaşımlarından biri kullanılmalıdır.

Örneğin.

```text
status
payment_status
reservation_status
membership_status
```

Serbest metin kullanımı önerilmez.

---

# 11. Dosya Bilgileri

Dosya yolları ve isimleri için.

```text
TEXT
```

kullanılması önerilir.

Dosya içerikleri doğrudan veritabanında saklanmamalıdır.

Dosyalar nesne depolama (Object Storage) altyapısında tutulmalıdır.

---

# 12. Hassas Veriler

Aşağıdaki alanlar özel güvenlik gerektirir.

- Kimlik numarası
- Sağlık bilgileri
- Erişim anahtarları
- API Token'ları

Bu alanlar gerektiğinde şifrelenmiş olarak saklanmalıdır.

Veri tipi seçiminde güvenlik göz önünde bulundurulmalıdır.

---

# 13. Tutarlılık

Platform genelinde aynı bilgi aynı veri tipiyle kullanılmalıdır.

Örneğin.

```text
phone_number
```

tüm tablolarda aynı veri tipine sahip olmalıdır.

Farklı veri tipleri veri dönüşüm maliyetini artıracaktır.

---

# 14. Performans

Veri tipleri sorgu performansını doğrudan etkiler.

Bu nedenle.

- gereksiz büyük alanlar kullanılmamalı,
- indekslerle uyumlu tipler seçilmeli,
- dönüşüm (CAST) gerektiren tasarımlardan kaçınılmalıdır.

Performans tasarım aşamasında planlanmalıdır.

---

# 15. Genel Kurallar

Veri tipi seçimi, Antrenova veritabanının doğruluğunu, performansını ve sürdürülebilirliğini belirleyen temel tasarım kararlarından biridir. Her sütun taşıdığı veriye en uygun veri tipiyle tanımlanmalı, platform genelinde ortak standartlar kullanılmalı ve gereksiz veri dönüşümlerinden kaçınılmalıdır.

Bu nedenle UUID, NUMERIC, BOOLEAN, TIMESTAMP WITH TIME ZONE ve uygun metin veri tipleri platform genelinde standart olarak kullanılmalı; tüm modüller aynı veri sözlüğünü paylaşarak tutarlı ve yüksek performanslı bir veritabanı mimarisi oluşturmalıdır.
