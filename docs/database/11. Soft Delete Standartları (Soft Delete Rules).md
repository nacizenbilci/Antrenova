# 11. Soft Delete Standartları (Soft Delete Rules)

> **Doküman Kodu:** DB-11  
> **Dosya Adı:** `11_SOFT_DELETE_RULES.md`  
> **Versiyon:** 1.0  
> **Durum:** Onaylandı  
> **Bağımlı Dokümanlar:** Audit Columns, Data Retention Rules, Table Standards, Relationship Rules, Constraint Rules

---

# 1. Amaç

Bu dokümanın amacı, Antrenova veritabanında kayıtların fiziksel olarak silinmesi yerine güvenli şekilde pasif duruma alınmasını sağlayan Soft Delete mimarisinin standartlarını tanımlamaktır.

Soft Delete yaklaşımı yalnızca yanlışlıkla silinen kayıtları geri getirmek için kullanılmaz. Aynı zamanda finansal geçmişin korunması, rapor tutarlılığının sağlanması, denetim süreçlerinin desteklenmesi ve veri ilişkilerinin bozulmaması açısından temel veritabanı politikalarından biridir.

Platform genelindeki kritik tablolar Soft Delete yapısını desteklemelidir.

---

# 2. Temel İlkeler

Varsayılan yaklaşım fiziksel silme (Hard Delete) değildir.

Bir kayıt silindiğinde.

- veritabanından kaldırılmaz,
- pasif duruma alınır,
- geçmiş ilişkileri korunur,
- rapor geçmişi bozulmaz.

Hard Delete yalnızca istisnai durumlarda uygulanabilir.

---

# 3. Standart Alanlar

Soft Delete kullanılan tablolarda aşağıdaki alanlar bulunmalıdır.

```text
deleted_at
deleted_by
```

İsteğe bağlı olarak.

```text
delete_reason
```

alanı da eklenebilir.

Bu alan isimleri platform genelinde standarttır.

---

# 4. deleted_at

Silme işlemi gerçekleştirildiğinde.

```text
deleted_at
```

alanı sistem zamanı ile doldurulmalıdır.

Kurallar.

- UTC formatı kullanılmalıdır.
- NULL ise kayıt aktiftir.
- Dolu ise kayıt silinmiş kabul edilir.

Kullanıcı bu alanı manuel değiştiremez.

---

# 5. deleted_by

Silme işlemini gerçekleştiren kullanıcı aşağıdaki alanda tutulmalıdır.

```text
deleted_by
```

Kurallar.

- User ID saklanmalıdır.
- NULL ise kayıt silinmemiştir.
- Sistem işlemleri için özel sistem kullanıcısı kullanılabilir.

Audit kayıtlarıyla uyumlu çalışmalıdır.

---

# 6. Varsayılan Sorgular

Platform genelindeki sorgular varsayılan olarak yalnızca aktif kayıtları getirmelidir.

Örneğin.

```sql
WHERE deleted_at IS NULL
```

şartı standart filtre olarak uygulanmalıdır.

Silinmiş kayıtlar yalnızca yetkili kullanıcılar tarafından görüntülenebilir.

---

# 7. Geri Yükleme

Soft Delete ile silinen kayıtlar geri yüklenebilir olmalıdır.

Geri yükleme sırasında.

```text
deleted_at = NULL
deleted_by = NULL
```

olarak güncellenmelidir.

İlişkili kayıtlar kontrol edilmeden geri yükleme yapılmamalıdır.

---

# 8. İlişki Yönetimi

Soft Delete kullanılan kayıtların ilişkileri korunmalıdır.

Örneğin.

Silinen bir üyenin.

- ödeme geçmişi,
- rezervasyonları,
- faturaları

ilişkisini kaybetmemelidir.

Referans bütünlüğü korunmalıdır.

---

# 9. Finansal Kayıtlar

Finans modülündeki kayıtlar varsayılan olarak Soft Delete kullanmalıdır.

Örneğin.

- Ödemeler
- Giderler
- Faturalar
- İadeler

Bu kayıtlar fiziksel olarak silinmemelidir.

Yanlış işlemler düzeltme kayıtlarıyla yönetilmelidir.

---

# 10. Raporlama

Varsayılan raporlar silinmiş kayıtları içermemelidir.

İşletme isterse.

- silinen kayıtlar,
- geri yüklenen kayıtlar,
- silme istatistikleri

ayrı raporlanabilir.

Rapor hesaplamaları tutarlı olmalıdır.

---

# 11. Performans

Soft Delete kullanılan büyük tablolarda.

```text
deleted_at
```

alanı uygun şekilde indekslenmelidir.

Bu yaklaşım aktif kayıt sorgularının performansını koruyacaktır.

Gereksiz tam tablo taramalarından kaçınılmalıdır.

---

# 12. Hard Delete Politikası

Aşağıdaki kayıtlar belirli koşullarda fiziksel olarak silinebilir.

- Geçici dosyalar
- Önbellek kayıtları
- Test verileri
- Süresi dolmuş geçici oturumlar

İşletme verileri varsayılan olarak Hard Delete kullanmamalıdır.

---

# 13. Yetkilendirme

Soft Delete işlemleri yalnızca yetkili kullanıcılar tarafından gerçekleştirilebilir.

Silme yetkisi.

- rol bazlı,
- modül bazlı,
- işletme bazlı

olarak kontrol edilmelidir.

Yetkisiz kullanıcılar kayıt silemez.

---

# 14. Audit ve İzlenebilirlik

Aşağıdaki işlemler Audit Log sistemine kaydedilmelidir.

- Soft Delete
- Geri yükleme
- Hard Delete
- Silme nedeni değişikliği

Her kayıt aşağıdaki bilgileri içermelidir.

- Record ID
- Business ID
- Kullanıcı
- Tarih
- Saat
- İşlem türü

---

# 15. Genel Kurallar

Soft Delete, Antrenova'nın veri güvenliği ve geçmiş kayıt bütünlüğünü koruyan temel veritabanı politikalarından biridir. Kritik kayıtlar fiziksel olarak silinmemeli, yalnızca pasif duruma alınmalı ve gerektiğinde güvenli şekilde geri yüklenebilmelidir.

Bu nedenle tüm iş tabloları standart Soft Delete yapısını kullanmalı, silme işlemleri Audit sistemiyle entegre çalışmalı, ilişkiler korunmalı ve veri yaşam döngüsü Data Retention kurallarına uygun olarak yönetilmelidir.
