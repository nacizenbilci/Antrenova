# 10. Gizli Bilgi ve Secret Yönetimi Standartları (Secrets Management)

> **Doküman Kodu:** DEVOPS-10  
> **Dosya Adı:** `10_SECRETS_MANAGEMENT.md`  
> **Versiyon:** 1.0  
> **Durum:** Onaylandı  
> **Bağımlı Dokümanlar:** Security Standards, Configuration Management, Environment Management, CI/CD Standards, Deployment Principles

---

# 1. Amaç

Bu dokümanın amacı, Antrenova platformunda kullanılan tüm gizli bilgilerin (Secrets) güvenli şekilde oluşturulması, saklanması, kullanılması, yenilenmesi ve erişimlerinin yönetilmesine ilişkin standartları belirlemektir.

Secret yönetimi yalnızca API anahtarlarını saklamak değildir. Veritabanı bağlantıları, erişim anahtarları, OAuth bilgileri, üçüncü parti servis kimlikleri, şifreleme anahtarları, imzalama anahtarları ve servis hesapları da bu kapsamda değerlendirilmelidir.

Platformdaki tüm gizli bilgiler ortak güvenlik politikalarına göre yönetilmelidir.

---

# 2. Temel İlkeler

Secret yönetimi aşağıdaki prensiplere uygun olmalıdır.

- Gizli tutulmalıdır.
- Merkezi yönetilmelidir.
- Yetkilendirilmelidir.
- Düzenli yenilenmelidir.
- Denetlenebilir olmalıdır.

Hiçbir Secret kaynak kod içerisinde yer almamalıdır.

---

# 3. Secret Türleri

Platform aşağıdaki Secret türlerini desteklemelidir.

- Database Password
- API Key
- JWT Secret
- OAuth Client Secret
- SMTP Password
- Storage Credentials
- Encryption Keys
- Service Tokens

Her kategori farklı güvenlik seviyesine sahip olabilir.

---

# 4. Saklama Kuralları

Secret bilgileri yalnızca güvenli ortamlarda saklanmalıdır.

Desteklenen yöntemler.

- Environment Variables
- Secret Manager
- CI/CD Secret Store

Düz metin dosyalarda saklanmamalıdır.

---

# 5. Kaynak Kod Kuralları

Aşağıdaki bilgiler Git deposuna eklenmemelidir.

- API anahtarları
- Şifreler
- Token'lar
- Sertifikalar
- Private Key dosyaları

Secret içeren Commit'ler derhal iptal edilmelidir.

---

# 6. Erişim Yetkilendirmesi

Secret'lara erişim en düşük yetki prensibine göre verilmelidir.

Kurallar.

- Geliştirici yalnızca gerekli Secret'lara erişebilir.
- Production Secret'ları sınırlı kişiler görebilir.
- Otomasyon servisleri ayrı kimlik kullanmalıdır.

Paylaşılan hesap kullanılmamalıdır.

---

# 7. Secret Yenileme

Tüm kritik Secret'lar düzenli aralıklarla yenilenmelidir.

Örneğin.

- API anahtarları
- JWT Secret
- OAuth bilgileri
- Servis Token'ları

Yenileme işlemleri planlı yürütülmelidir.

---

# 8. Secret Kullanımı

Uygulama Secret bilgilerini çalışma zamanında yüklemelidir.

Kurallar.

- Bellekte minimum süre tutulmalıdır.
- Log dosyalarına yazılmamalıdır.
- Hata mesajlarında gösterilmemelidir.

Secret'lar kullanıcıya hiçbir zaman döndürülmemelidir.

---

# 9. Güvenlik Olayları

Secret sızıntısı şüphesi oluştuğunda.

- Secret iptal edilmelidir.
- Yeni Secret oluşturulmalıdır.
- İlgili servisler güncellenmelidir.
- Güvenlik analizi başlatılmalıdır.

Olay kayıt altına alınmalıdır.

---

# 10. CI/CD Entegrasyonu

Pipeline içerisinde kullanılan Secret'lar güvenli şekilde sağlanmalıdır.

Kurallar.

- Build loglarında görünmemelidir.
- Manuel girilmemelidir.
- Pipeline sonunda temizlenmelidir.

Geçici erişimler tercih edilmelidir.

---

# 11. Audit ve Loglama

Secret yönetimine ilişkin işlemler kayıt altına alınmalıdır.

Kaydedilecek bilgiler.

- Erişim zamanı
- Kullanıcı
- Secret türü
- Yenileme işlemi
- Başarısız erişim denemeleri

Secret değerleri loglanmamalıdır.

---

# 12. Dokümantasyon

Secret yönetimi aşağıdaki bilgileri içermelidir.

- Secret adı
- Kullanıldığı servis
- Yenileme politikası
- Erişim yetkileri
- Sorumlu ekip

Gerçek Secret değerleri dokümantasyonda yer almamalıdır.

---

# 13. Performans

Secret erişimi uygulama performansını olumsuz etkilememelidir.

Sık kullanılan bilgiler güvenli şekilde önbelleğe alınabilir.

Gereksiz tekrar yüklemeler önlenmelidir.

---

# 14. Sürekli İyileştirme

Secret yönetimi düzenli olarak gözden geçirilmelidir.

İyileştirilebilecek alanlar.

- Yetkilendirme
- Otomatik yenileme
- Merkezi yönetim
- Güvenlik taramaları
- İzleme

Yeni güvenlik ihtiyaçlarına göre süreç güncellenmelidir.

---

# 15. Genel Kurallar

Secrets Management standartları, Antrenova platformundaki tüm gizli bilgilerin güvenli şekilde korunmasını sağlayan temel DevOps ve güvenlik süreçlerinden biridir. Secret'lar merkezi olarak yönetilmeli, kaynak koddan tamamen ayrılmalı, erişimleri sınırlandırılmalı, düzenli olarak yenilenmeli ve tüm işlemler Audit sistemiyle kayıt altına alınmalıdır.

Bu sayede güvenlik riskleri önemli ölçüde azaltılır, üçüncü taraf servislerle güvenli entegrasyon sağlanır ve platform büyüdükçe sürdürülebilir bir güvenlik altyapısı korunur.
