# 02. Ortam Yönetimi Standartları (Environment Management)

> **Doküman Kodu:** DEVOPS-02  
> **Dosya Adı:** `02_ENVIRONMENT_MANAGEMENT.md`  
> **Versiyon:** 1.0  
> **Durum:** Onaylandı  
> **Bağımlı Dokümanlar:** Deployment Principles, Security Standards, Database Standards, CI/CD Standards, Monitoring Standards

---

# 1. Amaç

Bu dokümanın amacı, Antrenova platformunda kullanılacak geliştirme, test ve canlı çalışma ortamlarının (Environment) standartlarını belirlemek ve tüm ekip üyelerinin aynı ortam yönetim kurallarını kullanmasını sağlamaktır.

Ortam yönetimi yalnızca farklı veritabanları kullanmak anlamına gelmez. Yapılandırmalar, gizli anahtarlar, servis bağlantıları, dağıtım süreçleri ve erişim yetkileri de ortam yönetiminin önemli parçalarıdır.

Platform genelindeki tüm servisler bu standartlara uygun çalışmalıdır.

---

# 2. Temel İlkeler

Ortam yönetimi aşağıdaki prensiplere uygun olmalıdır.

- İzole olmalıdır.
- Güvenli olmalıdır.
- Tekrarlanabilir olmalıdır.
- Dokümante edilmelidir.
- Tutarlı olmalıdır.

Hiçbir ortam diğerini etkilememelidir.

---

# 3. Ortam Türleri

Platform aşağıdaki standart ortamları kullanmalıdır.

```text
Development
Staging
Production
```

Gerekirse.

```text
Local
Testing
Preview
```

ortamları da eklenebilir.

---

# 4. Development Ortamı

Development ortamı geliştiricilerin günlük çalışmalarında kullanılmalıdır.

Özellikleri.

- Test verileri
- Geliştirme ayarları
- Debug açık olabilir
- Sık güncelleme

Canlı kullanıcı verisi bulunmamalıdır.

---

# 5. Staging Ortamı

Staging ortamı Production'ın birebir benzeri olmalıdır.

Amaçları.

- Son testler
- Kullanıcı kabul testleri
- Performans kontrolleri
- Yayın doğrulaması

Yeni sürümler önce burada doğrulanmalıdır.

---

# 6. Production Ortamı

Production yalnızca gerçek kullanıcılar için kullanılmalıdır.

Kurallar.

- Debug kapalı
- Maksimum güvenlik
- Sürekli izleme
- Otomatik yedekleme

Canlı ortamda geliştirme yapılmamalıdır.

---

# 7. Environment Variables

Tüm ortam ayarları Environment Variables üzerinden yönetilmelidir.

Örneğin.

- API URL
- Database URL
- JWT Secret
- Storage Key
- SMTP Bilgileri

Kod içerisine sabit değer yazılmamalıdır.

---

# 8. Gizli Bilgiler

Aşağıdaki bilgiler ortam değişkenlerinde saklanmalıdır.

- API Key
- Access Token
- Secret
- Database Password
- OAuth Credentials

Git deposuna eklenmemelidir.

---

# 9. Yapılandırma Yönetimi

Her ortam kendi yapılandırmasına sahip olmalıdır.

Örneğin.

- Log seviyesi
- Cache ayarları
- Bildirim sağlayıcıları
- Harici servis URL'leri

Ortamlar arasında yapılandırma karışmamalıdır.

---

# 10. Veritabanı Ayrımı

Her ortam kendi veritabanını kullanmalıdır.

Örneğin.

```text
Development DB
Staging DB
Production DB
```

Ortamlar aynı veritabanını paylaşmamalıdır.

---

# 11. Erişim Yetkileri

Her ortam için farklı erişim politikaları uygulanmalıdır.

Örneğin.

- Developer
- QA
- DevOps
- System Admin

Production erişimi sınırlandırılmalıdır.

---

# 12. İzleme

Her ortam bağımsız olarak izlenmelidir.

Takip edilmesi gerekenler.

- Performans
- Hata oranı
- Bellek
- CPU
- API yanıt süresi

Sorunlar ortam bazında değerlendirilmelidir.

---

# 13. Dokümantasyon

Her ortam için aşağıdaki bilgiler belgelenmelidir.

- URL
- Kullanılan servisler
- Environment Variables
- Erişim kuralları
- Deployment yöntemi

Dokümantasyon güncel tutulmalıdır.

---

# 14. Değişiklik Yönetimi

Environment ayarları değiştirilmeden önce.

- Etki analizi yapılmalıdır.
- Onay alınmalıdır.
- Test edilmelidir.

Kritik değişiklikler Audit sistemine kaydedilmelidir.

---

# 15. Genel Kurallar

Environment Management standartları, Antrenova platformunda geliştirme, test ve canlı çalışma ortamlarının güvenli ve tutarlı şekilde yönetilmesini sağlar. Her ortam bağımsız yapılandırılmalı, gizli bilgiler güvenli biçimde saklanmalı, erişim yetkileri sınırlandırılmalı ve tüm değişiklikler kontrollü süreçlerle uygulanmalıdır.

Bu sayede geliştirme süreçleri hızlanır, canlı ortam riskleri azalır ve platformun tüm yaşam döngüsü boyunca güvenilir bir operasyon altyapısı korunur.
