# 06. Release Management Standartları (Release Management)

> **Doküman Kodu:** DEVOPS-06  
> **Dosya Adı:** `06_RELEASE_MANAGEMENT.md`  
> **Versiyon:** 1.0  
> **Durum:** Onaylandı  
> **Bağımlı Dokümanlar:** Version Management, CI/CD Standards, Git & Branch Strategy, Environment Management, Deployment Principles

---

# 1. Amaç

Bu dokümanın amacı, Antrenova platformunda yeni sürümlerin planlanması, hazırlanması, test edilmesi, yayınlanması ve yayın sonrası doğrulanmasına ilişkin standart Release Management sürecini tanımlamaktır.

Release Management yalnızca kodun Production ortamına aktarılması değildir. Yayın kapsamının belirlenmesi, risk analizinin yapılması, kalite kontrollerinin tamamlanması, kullanıcı etkisinin değerlendirilmesi, geri dönüş planının hazırlanması ve yayın sonrası sistem doğrulamalarının gerçekleştirilmesini kapsayan uçtan uca operasyonel bir süreçtir.

Platform genelindeki tüm yayınlar bu standartlara uygun yürütülmelidir.

---

# 2. Temel İlkeler

Release süreçleri aşağıdaki prensiplere uygun olmalıdır.

- Planlı olmalıdır.
- Tekrarlanabilir olmalıdır.
- Geri alınabilir olmalıdır.
- İzlenebilir olmalıdır.
- Minimum kesinti hedeflemelidir.

Plansız yayınlar yalnızca kritik güvenlik veya sistem hatalarında uygulanmalıdır.

---

# 3. Release Türleri

Platform aşağıdaki yayın türlerini desteklemelidir.

```text
Major Release
Minor Release
Patch Release
Hotfix Release
```

Her yayın türü farklı onay ve doğrulama süreçlerine tabi olabilir.

---

# 4. Release Planlama

Her yayın öncesinde aşağıdaki bilgiler hazırlanmalıdır.

- Yayın kapsamı
- Etkilenen modüller
- Risk değerlendirmesi
- Beklenen kesinti süresi
- Rollback planı
- Sorumlu ekip

Planlama tamamlanmadan yayın başlatılmamalıdır.

---

# 5. Yayın Öncesi Kontroller

Release başlamadan önce aşağıdaki doğrulamalar yapılmalıdır.

- Kod incelemeleri tamamlandı mı?
- CI/CD başarılı mı?
- Migration test edildi mi?
- Güvenlik kontrolleri tamamlandı mı?
- Release Notes hazır mı?

Eksik kontrol bulunan sürümler yayınlanmamalıdır.

---

# 6. Release Pipeline

Standart yayın süreci aşağıdaki sırayı izlemelidir.

```text
Planning
↓
Code Freeze
↓
Testing
↓
Approval
↓
Deployment
↓
Verification
↓
Monitoring
```

Her aşama başarıyla tamamlanmadan sonraki adıma geçilmemelidir.

---

# 7. Code Freeze

Release öncesinde belirlenen süre boyunca yeni özellik geliştirmesi durdurulmalıdır.

Bu süreçte yalnızca.

- Kritik hata düzeltmeleri
- Güvenlik güncellemeleri
- Yayını engelleyen sorunlar

kabul edilmelidir.

---

# 8. Release Notes

Her yayın için Release Notes hazırlanmalıdır.

İçerik.

- Yeni özellikler
- Düzeltilen hatalar
- Performans iyileştirmeleri
- Güvenlik güncellemeleri
- Bilinen kısıtlamalar

Release Notes teknik ekip ve işletme yöneticileri tarafından anlaşılabilir olmalıdır.

---

# 9. Production Yayını

Production dağıtımı sırasında aşağıdaki adımlar uygulanmalıdır.

- Son yedek doğrulanır.
- Deployment başlatılır.
- Migration uygulanır.
- Servisler kontrol edilir.
- Sağlık kontrolleri tamamlanır.

Her adım operasyon kayıtlarına eklenmelidir.

---

# 10. Yayın Sonrası Doğrulama

Deployment tamamlandıktan sonra aşağıdaki kontroller yapılmalıdır.

- Uygulama açılıyor mu?
- API servisleri çalışıyor mu?
- Veritabanı bağlantıları sağlıklı mı?
- Kimlik doğrulama çalışıyor mu?
- Bildirim sistemi aktif mi?

Sorun bulunursa Rollback değerlendirilmelidir.

---

# 11. Rollback Süreci

Kritik hata oluştuğunda.

- Önceki sürüme dönülmelidir.
- Veritabanı durumu doğrulanmalıdır.
- Kullanıcılar bilgilendirilmelidir.
- Sorun analizi başlatılmalıdır.

Rollback prosedürü önceden test edilmiş olmalıdır.

---

# 12. İzleme

Yayın sonrası sistem yakından izlenmelidir.

Takip edilmesi gereken metrikler.

- Hata oranı
- API yanıt süresi
- CPU kullanımı
- Bellek kullanımı
- Background Job durumu

İlk saatlerde yoğun izleme uygulanmalıdır.

---

# 13. Audit ve Dokümantasyon

Her Release aşağıdaki bilgilerle kayıt altına alınmalıdır.

- Versiyon numarası
- Commit bilgisi
- Yayın tarihi
- Yayınlayan kullanıcı
- Rollback durumu
- Sonuç

Tüm yayın geçmişi saklanmalıdır.

---

# 14. Sürekli İyileştirme

Release süreci düzenli olarak analiz edilmelidir.

İyileştirilebilecek alanlar.

- Yayın süresi
- Başarısız Release oranı
- Rollback sıklığı
- Otomasyon seviyesi
- Test kapsamı

Her yeni yayın önceki deneyimlerden öğrenmelidir.

---

# 15. Genel Kurallar

Release Management standartları, Antrenova platformunda yeni sürümlerin güvenli, kontrollü ve sürdürülebilir şekilde yayınlanmasını sağlayan temel DevOps süreçlerinden biridir. Her yayın önceden planlanmalı, kalite kontrollerinden geçirilerek Production ortamına aktarılmalı, yayın sonrası sistem doğrulanmalı ve gerektiğinde hızlı şekilde geri alınabilmelidir.

Bu yaklaşım sayesinde yayın kalitesi yükselir, operasyonel riskler azalır, sistem kararlılığı korunur ve Antrenova büyüdükçe profesyonel bir Release Management sürecine sahip olur.
