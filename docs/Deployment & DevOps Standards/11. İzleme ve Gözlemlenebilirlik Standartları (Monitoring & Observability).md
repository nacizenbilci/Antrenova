# 11. İzleme ve Gözlemlenebilirlik Standartları (Monitoring & Observability)

> **Doküman Kodu:** DEVOPS-11  
> **Dosya Adı:** `11_MONITORING_OBSERVABILITY.md`  
> **Versiyon:** 1.0  
> **Durum:** Onaylandı  
> **Bağımlı Dokümanlar:** Logging Standards, Alerting Standards, Background Jobs Workflow, API Standards, System Maintenance Workflow

---

# 1. Amaç

Bu dokümanın amacı, Antrenova platformunda çalışan tüm servislerin, uygulamaların ve altyapı bileşenlerinin sürekli izlenmesini sağlayacak Monitoring ve Observability standartlarını belirlemektir.

İzleme sistemi yalnızca sunucunun çalışıp çalışmadığını kontrol etmek için kullanılmaz. Uygulama performansını ölçmek, kullanıcı deneyimini değerlendirmek, sistem darboğazlarını tespit etmek, hata nedenlerini analiz etmek ve gelecekteki kapasite planlamalarını desteklemek için temel veri kaynağıdır.

Platform genelindeki tüm servisler bu standartlara uygun izlenmelidir.

---

# 2. Temel İlkeler

Monitoring sistemi aşağıdaki prensiplere uygun olmalıdır.

- Sürekli çalışmalıdır.
- Gerçek zamanlı olmalıdır.
- Ölçülebilir olmalıdır.
- Alarm üretebilmelidir.
- Geçmiş verileri saklayabilmelidir.

İzleme yalnızca hata oluştuğunda değil, sürekli yapılmalıdır.

---

# 3. İzlenecek Sistemler

Aşağıdaki bileşenler sürekli izlenmelidir.

- Web uygulaması
- API servisleri
- Veritabanı
- Background Worker
- Bildirim sistemi
- Dosya depolama
- Kimlik doğrulama servisleri

Yeni servisler otomatik izleme kapsamına alınmalıdır.

---

# 4. Uygulama Sağlığı

Her servis Health Check endpoint'i sağlamalıdır.

Kontroller.

- Servis çalışıyor mu?
- Veritabanı erişilebilir mi?
- Cache erişilebilir mi?
- Queue çalışıyor mu?

Health Check sonuçları düzenli izlenmelidir.

---

# 5. Performans Metrikleri

Aşağıdaki performans değerleri izlenmelidir.

- API yanıt süresi
- Ortalama istek süresi
- CPU kullanımı
- Bellek kullanımı
- Disk kullanımı
- Ağ trafiği

Metrikler düzenli olarak kaydedilmelidir.

---

# 6. İş Süreci Metrikleri

Teknik metriklerin yanında iş metrikleri de izlenmelidir.

Örneğin.

- Günlük rezervasyon sayısı
- Paket satışları
- Ödeme işlemleri
- Katılım oranı
- Gönderilen bildirim sayısı

Bu veriler işletme analizlerinde kullanılmalıdır.

---

# 7. Hata İzleme

Tüm uygulama hataları merkezi olarak toplanmalıdır.

Takip edilmesi gereken bilgiler.

- Exception türü
- Hata mesajı
- Stack Trace
- Kullanıcı
- Endpoint
- Tarih

Tekrarlayan hatalar önceliklendirilmelidir.

---

# 8. Dağıtık İzleme

Bir isteğin tüm sistem boyunca izlenebilmesi sağlanmalıdır.

Örneğin.

```text
API
↓
Service
↓
Database
↓
Notification
```

Her işlem ortak bir Trace ID ile takip edilmelidir.

---

# 9. Dashboard

Operasyon ekipleri için merkezi izleme panelleri oluşturulmalıdır.

Gösterilebilecek bilgiler.

- Aktif kullanıcı sayısı
- API durumu
- Worker durumu
- Bildirim kuyruğu
- Hata oranı

Paneller gerçek zamanlı güncellenmelidir.

---

# 10. Alarm Mekanizması

Belirlenen eşikler aşıldığında otomatik alarm oluşturulmalıdır.

Örneğin.

- API yanıt süresi arttı.
- CPU %90 üzerine çıktı.
- Worker durdu.
- Queue doldu.

Alarm seviyeleri tanımlanmalıdır.

---

# 11. Audit ve Loglama

Monitoring sistemi aşağıdaki bilgileri kayıt altına almalıdır.

- Alarm zamanı
- Servis
- Etkilenen bileşen
- Çözüm süresi
- Sonuç

İzleme geçmişi saklanmalıdır.

---

# 12. Performans Analizi

Toplanan metrikler düzenli analiz edilmelidir.

İyileştirilebilecek alanlar.

- Yavaş sorgular
- Darboğazlar
- Bellek tüketimi
- Ağ kullanımı

Performans çalışmaları veriye dayalı yapılmalıdır.

---

# 13. Dokümantasyon

Monitoring sistemi belgelenmelidir.

İçerik.

- İzlenen servisler
- Alarm kuralları
- Dashboard açıklamaları
- Metrik tanımları

Yeni ekip üyeleri sistemi kolayca anlayabilmelidir.

---

# 14. Sürekli İyileştirme

Monitoring altyapısı düzenli olarak geliştirilmelidir.

İyileştirilebilecek alanlar.

- Yeni metrikler
- Yeni dashboard'lar
- Alarm doğruluğu
- İzleme kapsamı

Platform büyüdükçe izleme kapasitesi artırılmalıdır.

---

# 15. Genel Kurallar

Monitoring & Observability standartları, Antrenova platformunun sağlıklı ve sürdürülebilir şekilde çalışmasını sağlayan temel operasyon süreçlerinden biridir. Tüm servisler gerçek zamanlı izlenmeli, teknik ve operasyonel metrikler birlikte değerlendirilmeli, alarm mekanizmaları etkin kullanılmalı ve elde edilen veriler sürekli iyileştirme çalışmalarına yön vermelidir.

Bu sayede sistem sorunları erken tespit edilir, kullanıcı deneyimi korunur, operasyon ekipleri hızlı müdahale edebilir ve platform büyüdükçe güvenilir bir gözlemlenebilirlik altyapısı sürdürülebilir.
