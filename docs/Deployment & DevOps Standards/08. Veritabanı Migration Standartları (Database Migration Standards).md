# 08. Veritabanı Migration Standartları (Database Migration Standards)

> **Doküman Kodu:** DEVOPS-08  
> **Dosya Adı:** `08_DATABASE_MIGRATION_STANDARDS.md`  
> **Versiyon:** 1.0  
> **Durum:** Onaylandı  
> **Bağımlı Dokümanlar:** Database Standards, Deployment Pipeline, Release Management, Environment Management, Backup Standards

---

# 1. Amaç

Bu dokümanın amacı, Antrenova platformunda veritabanı şema değişikliklerinin güvenli, izlenebilir ve kontrollü şekilde yönetilmesini sağlayacak Migration standartlarını belirlemektir.

Migration süreci yalnızca yeni tablo oluşturmak değildir. Mevcut tabloların güncellenmesi, indeks eklenmesi, veri dönüşümleri, geriye uyumluluk, Rollback senaryoları ve farklı ortamların senkronizasyonu gibi kritik işlemleri kapsar.

Platformdaki tüm veritabanı değişiklikleri bu standartlara göre uygulanmalıdır.

---

# 2. Temel İlkeler

Migration süreçleri aşağıdaki prensiplere uygun olmalıdır.

- Sürümlenebilir olmalıdır.
- Tekrarlanabilir olmalıdır.
- Geri alınabilir olmalıdır.
- Test edilebilir olmalıdır.
- İzlenebilir olmalıdır.

Hiçbir şema değişikliği manuel olarak Production ortamında uygulanmamalıdır.

---

# 3. Migration Kaynağı

Migration dosyaları yalnızca sürüm kontrol sistemi içerisinde tutulmalıdır.

Kurallar.

- Git ile versiyonlanmalıdır.
- Kod incelemesinden geçmelidir.
- CI/CD sürecine dahil edilmelidir.

Veritabanı değişiklikleri koddan bağımsız olmamalıdır.

---

# 4. Dosya Adlandırma

Migration dosyaları benzersiz isimlendirme kullanmalıdır.

Örnek.

```text
20260804_create_members_table.sql

20260805_add_branch_id.sql

20260806_create_indexes.sql
```

Dosya sıralaması kronolojik olmalıdır.

---

# 5. Migration İçeriği

Her Migration yalnızca tek mantıksal değişiklik içermelidir.

Örneğin.

- Yeni tablo
- Yeni kolon
- Yeni indeks
- Constraint ekleme

Birden fazla büyük değişiklik tek dosyada yapılmamalıdır.

---

# 6. Forward Only Yaklaşımı

Migration'lar varsayılan olarak ileri yönlü çalışmalıdır.

Kurallar.

- Eski Migration değiştirilmez.
- Yeni değişiklik yeni Migration ile eklenir.
- Geçmiş dosyalar korunur.

Yayınlanmış Migration yeniden düzenlenmemelidir.

---

# 7. Rollback Desteği

Her kritik Migration için geri dönüş planı hazırlanmalıdır.

Rollback sırasında.

- Veri kaybı değerlendirilmelidir.
- Constraint değişiklikleri incelenmelidir.
- Bağımlılıklar doğrulanmalıdır.

Rollback prosedürü test edilmelidir.

---

# 8. Veri Dönüşümü

Şema değişikliğiyle birlikte veri taşınması gerekiyorsa.

- Küçük veri setlerinde Migration içerisinde,
- Büyük veri setlerinde Background Job ile

işlem yapılmalıdır.

Uzun süren veri dönüşümleri Deployment süresini uzatmamalıdır.

---

# 9. Ortam Sıralaması

Migration aşağıdaki sırayla uygulanmalıdır.

```text
Development
↓
Staging
↓
Production
```

Bir ortam doğrulanmadan sonraki ortama geçilmemelidir.

---

# 10. Performans

Büyük tablolar üzerinde yapılan değişiklikler dikkatle planlanmalıdır.

Örneğin.

- İndeks oluşturma
- Constraint ekleme
- Büyük UPDATE işlemleri

Yoğun saatlerde uygulanmamalıdır.

---

# 11. Audit ve Loglama

Her Migration aşağıdaki bilgilerle kayıt altına alınmalıdır.

- Migration adı
- Uygulama zamanı
- Ortam
- Süre
- Sonuç
- Uygulayan Pipeline

Migration geçmişi silinmemelidir.

---

# 12. Doğrulama

Migration tamamlandıktan sonra aşağıdaki kontroller yapılmalıdır.

- Şema doğruluğu
- Constraint kontrolü
- İndeks doğrulaması
- Uygulama çalışırlığı

Doğrulama başarısızsa Rollback değerlendirilmelidir.

---

# 13. Dokümantasyon

Her Migration belgelenmelidir.

İçerik.

- Amaç
- Etkilenen tablolar
- Geri dönüş planı
- Beklenen etkiler

Dokümantasyon geliştiriciler tarafından erişilebilir olmalıdır.

---

# 14. Sürekli İyileştirme

Migration süreçleri düzenli analiz edilmelidir.

İyileştirilebilecek alanlar.

- Uygulama süresi
- Rollback başarısı
- Hata oranı
- Deployment etkisi

Yeni standartlar geçmiş deneyimlerden oluşturulmalıdır.

---

# 15. Genel Kurallar

Database Migration standartları, Antrenova platformunda veritabanı değişikliklerinin güvenli ve kontrollü şekilde yönetilmesini sağlayan temel DevOps süreçlerinden biridir. Tüm şema değişiklikleri sürümlenebilir Migration dosyalarıyla uygulanmalı, Production öncesinde test edilmeli, Rollback planları hazırlanmalı ve tüm işlemler ayrıntılı olarak kayıt altına alınmalıdır.

Bu yaklaşım sayesinde veri bütünlüğü korunur, yayın süreçleri güvenli hale gelir ve büyüyen platformun veritabanı altyapısı sürdürülebilir şekilde yönetilebilir.
