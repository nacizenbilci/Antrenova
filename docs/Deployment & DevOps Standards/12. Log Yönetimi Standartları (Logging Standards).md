# 12. Log Yönetimi Standartları (Logging Standards)

> **Doküman Kodu:** DEVOPS-12  
> **Dosya Adı:** `12_LOGGING_STANDARDS.md`  
> **Versiyon:** 1.0  
> **Durum:** Onaylandı  
> **Bağımlı Dokümanlar:** Monitoring & Observability, Audit Rules, Security Standards, API Standards, Background Jobs Workflow

---

# 1. Amaç

Bu dokümanın amacı, Antrenova platformunda oluşan tüm sistem kayıtlarının (Logs) standart şekilde üretilmesini, saklanmasını, analiz edilmesini ve gerektiğinde denetim amacıyla kullanılmasını sağlayacak kuralları belirlemektir.

Log sistemi yalnızca hata kayıtlarından oluşmaz. API istekleri, servis çağrıları, arka plan görevleri, güvenlik olayları, entegrasyonlar ve performans bilgileri de log altyapısının bir parçasıdır.

Platform genelindeki tüm servisler ortak log standartlarını kullanmalıdır.

---

# 2. Temel İlkeler

Log yönetimi aşağıdaki prensiplere uygun olmalıdır.

- Tutarlı olmalıdır.
- Yapısal olmalıdır.
- Aranabilir olmalıdır.
- Performansı etkilememelidir.
- Güvenli olmalıdır.

Her log anlamlı bilgi içermelidir.

---

# 3. Log Seviyeleri

Standart log seviyeleri aşağıdaki şekilde kullanılmalıdır.

```text
TRACE
DEBUG
INFO
WARN
ERROR
FATAL
```

Her olay doğru seviyede kaydedilmelidir.

---

# 4. Log Formatı

Log kayıtları yapılandırılmış formatta oluşturulmalıdır.

Örnek alanlar.

- Timestamp
- Level
- Service
- Request ID
- User ID
- Business ID
- Message

Makine tarafından okunabilir format tercih edilmelidir.

---

# 5. API Logları

Her API isteği için aşağıdaki bilgiler kaydedilmelidir.

- Endpoint
- HTTP Method
- Yanıt kodu
- Süre
- Kullanıcı
- IP adresi
- Request ID

Kişisel veriler loglanmamalıdır.

---

# 6. Servis Logları

Her servis kendi operasyon kayıtlarını üretmelidir.

Örneğin.

- Notification Service
- Payment Service
- Reservation Service
- Reporting Service

Loglar merkezi sisteme aktarılmalıdır.

---

# 7. Hata Logları

Hata oluştuğunda aşağıdaki bilgiler kaydedilmelidir.

- Exception türü
- Mesaj
- Stack Trace
- Request ID
- Kullanıcı
- Servis

Gizli bilgiler hata kayıtlarına yazılmamalıdır.

---

# 8. Güvenlik Logları

Güvenlik olayları ayrı kategoride tutulmalıdır.

Örneğin.

- Başarısız giriş
- Yetki ihlali
- Token hatası
- Şüpheli istekler

Bu kayıtlar uzun süre saklanmalıdır.

---

# 9. Background Job Logları

Her Worker aşağıdaki bilgileri üretmelidir.

- Job ID
- Süre
- Durum
- Retry sayısı
- Hata nedeni

Arka plan görevleri izlenebilir olmalıdır.

---

# 10. Log Saklama

Loglar belirlenen süre boyunca saklanmalıdır.

Kurallar.

- Aktif loglar
- Arşiv logları
- Silme politikası

Saklama süreleri yasal gerekliliklere uygun olmalıdır.

---

# 11. Log Analizi

Loglar merkezi analiz sisteminde değerlendirilebilmelidir.

Desteklenmesi gereken işlemler.

- Filtreleme
- Arama
- Gruplama
- Korelasyon

Tekrarlayan hatalar kolayca bulunabilmelidir.

---

# 12. Audit ve Log İlişkisi

Audit kayıtları ile sistem logları birbirini tamamlamalıdır.

Audit.

- İş kararlarını,

Log ise.

- Teknik olayları

kayıt altına almalıdır.

Bu iki sistem karıştırılmamalıdır.

---

# 13. Performans

Yoğun log üretimi sistem performansını düşürmemelidir.

Gerektiğinde.

- Asenkron loglama
- Batch yazma
- Log seviyesine göre filtreleme

kullanılmalıdır.

---

# 14. Dokümantasyon

Log standartları aşağıdaki bilgileri içermelidir.

- Log seviyeleri
- Alan açıklamaları
- Saklama politikaları
- Güvenlik kuralları

Tüm geliştiriciler aynı yapıyı kullanmalıdır.

---

# 15. Genel Kurallar

Logging standartları, Antrenova platformunda teknik olayların güvenilir şekilde izlenmesini sağlayan temel operasyon altyapılarından biridir. Tüm servisler yapılandırılmış log üretmeli, güvenlik ve performans bilgileri merkezi olarak toplanmalı, kişisel veriler korunmalı ve log kayıtları analiz edilebilir formatta saklanmalıdır.

Bu sayede sistem sorunları daha hızlı çözülebilir, performans darboğazları kolayca tespit edilir ve operasyon ekipleri platformu güvenle yönetebilir.
